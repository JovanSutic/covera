**Prerequisite:** none for steps 4.1–4.4 (type declarations and pure functions). Step 4.5 is the

## Why this phase is split this way

The classifier's measured boundary (2026-11-25, re-verified 2026-11-26):

- **Allowed:** type declarations — the `AccessParamName` type, the `hasAccessParam` predicate, and
  the `accessParam?` field on `RouteBase` / `GuardMeta`.
- **Refused:** every edit that changes what a route admits — the `makeLoader` rule loop,
  `guardPasses`, and the `requires` lines.

So steps 4.1–4.4 are declarations and pure functions, and 4.5 is the single admission change. If
4.5 is refused, revert 4.1–4.4 and report — phases 5 and 6 are then blocked, and phases 1, 2, 3, 7,
8 and 9 proceed unaffected.

## Step 4.1 — The access-parameter predicate

**Touch.** `src/lib/router/access.ts` (edit)

**Do.** *(logic mode — exact bytes)*

Add below `ACCESS_RULES`. This is a pure predicate over a `URLSearchParams`; it deliberately does
**not** become a member of `ACCESS_RULES`, because those rules read the session alone and are
precomputed into a synchronous results map — a URL parameter is not session state.

```ts
/**
 * D1: the query parameters that may stand in for a session on a route that names one.
 *
 * This is NOT a member of `ACCESS_RULES`. Those rules read the session alone and are
 * precomputed into a results map by `createAccess`, which is what keeps `isAllowed()`
 * synchronous and request-free. A URL parameter is not session state, so it is evaluated
 * where the URL already exists — in the loader, the preload check and the preloader.
 *
 * Presence only. The guard cannot judge validity: only the API can, and it answers
 * `403 SPECIAL_ACCESS_INVALID` per request. A guard that tried to validate would have to
 * make a request from a loader, which the preload path cannot afford.
 */
export type AccessParamName = "accessId";

export const ACCESS_PARAM_NAMES: readonly AccessParamName[] = ["accessId"];

export function hasAccessParam(
  name: AccessParamName,
  searchParams: URLSearchParams,
): boolean {
  const value = searchParams.get(name);

  return value !== null && value !== "";
}
```

- `grep -n "export type AccessParamName\|export function hasAccessParam\|ACCESS_PARAM_NAMES" src/lib/router/access.ts` → three matches
- `grep -c "AccessParamName" src/lib/router/access.ts` → at least `3`

## Step 4.3 — The pure admission predicate, and its test

**Touch.** `src/lib/router/access.ts` (edit), `src/lib/router/access.test.ts` (edit)

**Do.** *(logic mode — exact bytes)*

Add the predicate the loader will call. Keeping it a pure exported function is what makes step 4.5
a one-line change and lets it be tested without a router.

```ts
/**
 * D1: does this route admit the visitor on the strength of a URL parameter alone?
 *
 * `rules` is the route's whole inherited chain. A route with no `accessParam` never admits
 * this way, so declaring nothing changes nothing.
 */
export function accessParamAdmits(
  accessParam: AccessParamName | undefined,
  searchParams: URLSearchParams,
): boolean {
  return accessParam !== undefined && hasAccessParam(accessParam, searchParams);
}
```

Then append to `src/lib/router/access.test.ts`:

```ts
describe("the access-parameter predicate", () => {
  it("admits when the named parameter is present and non-empty", () => {
    expect(
      accessParamAdmits("accessId", new URLSearchParams("accessId=abc123")),
    ).toBe(true);
  });

  it("refuses when the parameter is absent", () => {
    expect(accessParamAdmits("accessId", new URLSearchParams("foo=bar"))).toBe(false);
  });

  it("refuses an empty value — `?accessId=` is not a credential", () => {
    expect(accessParamAdmits("accessId", new URLSearchParams("accessId="))).toBe(false);
  });

  it("refuses on a route that declares no access parameter", () => {
    expect(accessParamAdmits(undefined, new URLSearchParams("accessId=abc123"))).toBe(false);
  });

  it("is not a member of ACCESS_RULES — the rule set is unchanged", () => {
    expect(Object.keys(ACCESS_RULES)).toEqual([
      "public",
      "isAnonymous",
      "canUseApp",
      "canOpenAdmin",
      "canOpenHost",
    ]);
  });
});
```

Add `accessParamAdmits` to that file's existing import from `./access`.

## Step 4.5 — Admit the visitor in the loader and the preloader

**Touch.** `src/lib/router/defineRoutes.tsx` (edit), `src/lib/router/createAppRouter.tsx` (edit)

> **This is the step the classifier may refuse.** If either edit is denied with `[Security Weaken]`,
> follow `00-index.md` §"The permission-classifier hazard": revert steps 4.1–4.4, report, and stop.
> Do not reword the edit.

**Do.** *(logic mode — exact bytes)*

**In `makeLoader`**, replace the rule loop's opening so a declared access parameter short-circuits
it. The `searchParams` line must move above the loop, because the loop now reads it:

```ts
  return async ({ params, request }) => {
    const searchParams = new URL(request.url).searchParams;
    const accessGranted = accessParamAdmits(guard.accessParam, searchParams);

    for (const rule of guard.rules) {
      if (deps.isAllowed(rule)) continue;

      // D1: a URL parameter may stand in for the session on a route that declares one.
      // Presence only — the API judges validity per request.
      if (accessGranted) continue;

      // A denied route may name where the visitor belongs instead (login-redirect
      // D10). `null` — the result for every route that declares nothing — keeps the
      // 403-in-place behaviour (router-maximization D1).
      const target = ((node as any).denyRedirect as DenyRedirect | undefined)?.(deps.getSources());

      if (target === null || target === undefined) throw data(null, { status: 403 });

      throw redirect(target);
    }

    if (!areParamsValid(params, guard.params)) throw data(null, { status: 404 });

    const parsed = parseParams(params, guard.params);
```

(The old `const searchParams = new URL(request.url).searchParams;` line further down is deleted —
it is now declared once, at the top.)

**In `guardPasses`**, add the same short-circuit so preload cannot start work for a URL the user
cannot open. It needs the search params, so its signature gains one argument:

```ts
function guardPasses(
  node: RouteNode,
  deps: DefineRoutesDeps,
  params: ParsedParams,
  searchParams: URLSearchParams,
): boolean {
  // The preloader (phase 6) already ran the rule and param checks for the whole
  // matched chain; this is the per-route re-check so preload can never start
  // work for a URL the user cannot open.
  if (
    node.requires &&
    !deps.isAllowed(node.requires) &&
    !accessParamAdmits(node.accessParam, searchParams)
  ) {
    return false;
  }
  const declared = node.params ?? {};
  return areParamsValid(
    Object.fromEntries(
      Object.keys(declared).map((key) => [key, params[key] === undefined ? undefined : String(params[key])]),
    ),
    declared,
  );
}
```

and its one call site inside `buildPreload`:

```ts
    if (!guardPasses(node, deps, params, searchParams)) return;
```

Add `accessParamAdmits` to the value import from `./access` (there is currently only a type import
from that module — add a separate value import line):

```ts
import { accessParamAdmits } from "./access";
```

**In `createAppRouter.tsx`**, the preloader's pass-1 loop gains the same short-circuit. Replace:

```ts
      for (const rule of guard.rules) {
        if (!access.isAllowed(rule)) return;
```

with:

```ts

      const accessGranted = accessParamAdmits(guard.accessParam, url.searchParams);

      for (const rule of guard.rules) {
        if (access.isAllowed(rule)) continue;
        if (accessGranted) continue;
```

## Step 4.6 — Prove the guard admits and refuses correctly

Required: the admission rule is the phase's whole point, and it is the one thing a green gate
cannot show on its own.

**Touch.** `src/lib/router/__checks__/router.behaviour.test.ts` (edit)

**Do.** *(logic mode — the test is the acceptance criterion)*

Append to the existing behaviour test file. It already has `buildRouter(role, initialEntry)`
returning `{ router }`, and the established way to read a rejection is
`Object.values(router.state.errors ?? {})[0]?.status`. Use both; do not invent a new helper.

```ts
describe("the access-parameter guard (D1)", () => {
  const GUIDE =
    "/inspection-guide/11111111-1111-1111-1111-111111111111/22222222-2222-2222-2222-222222222222";

  async function statusAt(path: string, role: UserRole | null = null) {
    const { router } = await buildRouter(role, path);
    const error = Object.values(router.state.errors ?? {})[0] as {
      status?: number;
    };

    return error?.status;
  }

  it("refuses an anonymous visitor with no parameter, in place", async () => {
    expect(await statusAt(GUIDE)).toBe(403);
  });

  it("admits an anonymous visitor holding the parameter", async () => {
    expect(await statusAt(`${GUIDE}?accessId=abc123`)).not.toBe(403);
  });

  it("refuses an empty parameter — `?accessId=` is not a credential", async () => {
    expect(await statusAt(`${GUIDE}?accessId=`)).toBe(403);
  });

  it("still refuses an unrelated parameter", async () => {
    expect(await statusAt(`${GUIDE}?foo=bar`)).toBe(403);
  });

  it("still 404s a malformed id even with the parameter present", async () => {
    expect(
      await statusAt(
        `${GUIDE.replace("11111111-1111-1111-1111-111111111111", "not-a-uuid")}?accessId=abc123`,
      ),
    ).toBe(404);
  });

  it("leaves an unrelated host-only route refused", async () => {
    expect(await statusAt("/host/dashboard?accessId=abc123")).toBe(403);
  });

  it("does not admit a signed-in guest-role user to a host route", async () => {
    expect(await statusAt("/host/dashboard", "guest")).toBe(403);
  });
});
```
