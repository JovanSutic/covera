## Step 5.1 — The guest submit chain

**Touch.** `src/lib/api/submitPhotoProofs.ts` (edit)

**Do.** *(logic mode — the auth choice and the body are the decision)*

The three calls in this module are host-only today. They gain an optional `accessId`, and when it is
present the module uses `publicApi()` instead of `withAuth()` and sends the credential as a query
parameter. **Trial-compiled 2026-11-26: this shape gives `tsc -b` exit 0.**

Change the parameter interface and the config resolution:

```ts
interface UploadParams {
  apartmentId: string;
  reservationId: string;
  shots: CapturedApartmentShot[];
  type?: "checkin_state" | "damage";
  /**
   * D11: when present, every call authenticates with the LINK, not the session. A guest must
   * never reach `withAuth()` — it sends `Bearer undefined` for a caller with no account and
   * turns a working anonymous write into a 401 (invariant 11).
   */
  accessId?: string;
}
```

and replace the single `const config = await withAuth();` with:

```ts
  // D11: the token path and the session path are mutually exclusive, and the presence of an
  // accessId decides which. The backend never falls back to a session when the parameter is
  // supplied, so sending a bearer token alongside it would be a second, ignored credential.
  const config = accessId
    ? publicApi()
    : await withAuth();
```

Then add `query: accessId ? { accessId } : undefined` to each of the three calls —
`postApartmentsByIdPhotosUploadTokens`, `postApartmentsByIdPhotosConfirm`, and
`patchReservationsById`. The `PATCH` body stays exactly as it is (D12):

```ts
    body: {
      hasPhotoProof: true,
      status: "COVERED",
    },
```

Add `publicApi` to the existing `import { withAuth } from "./api";` line:

```ts
import { publicApi, withAuth } from "./api";
```

**Accept.**
- `grep -c "accessId" src/lib/api/submitPhotoProofs.ts` → at least `5`
- `grep -n "query: accessId ? { accessId } : undefined" src/lib/api/submitPhotoProofs.ts` → three matches
- `grep -c "hasPhotoProof: true" src/lib/api/submitPhotoProofs.ts` → `1` (the body is unchanged)
- `npx tsc -b` → exit 0

**Verify.** `npm run gate`

## Step 5.2 — The guest branch submits, and an invalid link says so

**Touch.** `src/pages/InspectionGuidePage.tsx` (edit)

**Do.** *(surface mode — specify, do not transcribe)*

- **Exports.** `export default function InspectionGuidePage()` — signature unchanged.
- **Consumes.** `submitInspectionPhotos` from `@/lib/api/submitPhotoProofs` (now takes `accessId`);
  `useReservationWithAccess`, `useShotsWithAccess`, `useReservationPhotosWithAccess` from
  `@/lib/api/specialAccess`; `appPaths.inspectionGuide`; `QUERY_ACTIONS`.
- **The guest branch's three states**, replacing the current `isGuest` early return:
  - **loading** → unchanged (the existing spinner block).
  - **invalid link** → the `guestReservation.isError` branch. **D5:** the copy becomes
    link-specific. Replace the `inspectionGuidePage.notFound.*` keys with
    `inspectionGuidePage.invalidLink.title` / `.subtitle`, and delete the comment claiming the
    backend answers `500` — it answers `403 SPECIAL_ACCESS_INVALID` now.
  - **ready** → the existing read-only render, with two changes:
    1. The `inspectionGuidePage.guest.readOnly` banner is **replaced** by
       `inspectionGuidePage.guest.canSubmit` (the guest may now submit).
    2. The capture/submit flow is rendered, driven by the guest's own reads
       (`guestShotsList`, `guestPhotoList`, `guestReservation.data`) rather than the host hooks.
- **The submit mutation** gains the credential. Change its `mutationFn` to pass
  `accessId: accessId ?? undefined` into `submitInspectionPhotos`, and make its `onSuccess`
  navigate to the reservation path **only for a host** — a guest has no session and would hit a
  403 at that route. For a guest, invalidate the guest query keys and stay on the page:
  - `[...QUERY_ACTIONS.RESERVATIONS_GET_ID, reservationId]`
  - `[...QUERY_ACTIONS.RESERVATIONS_GET_BY_APARTMENT, apartmentId]`
  - the three guest keys the page's own hooks use (they include `accessId ?? ""` — reuse the same
    key builders the hooks use, do not retype the arrays).
- **States the flow must keep.** The capture flow's own loading/empty/ready states come from the
  existing guide components (`InspectionGuideFlow`); this step only decides which data feeds them.
- **Callbacks.** The flow's submit callback calls `submitMutation.mutate(completedShots)` — the
  same call the host path makes.
- **Pattern to follow.** The host path in the same file, and `FieldIncidentPage.tsx` for the
  anonymous-write shape (it is the existing precedent for a tokenless surface making writes).
- **Invariant.** A page holding a link never calls `withAuth()` — including through
  `submitInspectionPhotos`, which is why step 4.1 exists.

**Accept.**
- `grep -c "await withAuth(" src/pages/InspectionGuidePage.tsx` → `0` (the bare `withAuth` string survives in a doc comment; the **call** must not exist)
- `grep -n "guest.canSubmit\|invalidLink" src/pages/InspectionGuidePage.tsx` → at least two matches
- `grep -c "inspectionGuidePage.guest.readOnly" src/pages/InspectionGuidePage.tsx` → `0`

**Verify.** `npm run gate`
