## Step 6.1 — Access-aware query hooks for the four reads

**Touch.** `src/lib/api/queries/incident.ts` (edit), `assets.ts` (edit), `reservation.ts` (edit),
`reservationPhotos.ts` (edit)

**Do.** *(logic mode — the auth choice and the key shape are the decisions)*

Each of the four modules gains an access-aware variant beside its existing hook. The **key includes
the `accessId`**, so two different links cannot read each other's cache — the same rule
`InspectionGuidePage`'s local hooks already follow.

For each module, add a hook with this shape (shown for `incident.ts`; the other three differ only in
the resource, the path parameter name, and the request function):

```ts
/**
 * D3: the guest's read of the same resource, through an access link. It uses `publicApi()`
 * and NEVER `withAuth()` (invariant 11), and the `accessId` is IN the key so two links cannot
 * read each other's cache.
 *
 * `enabled` requires BOTH ids: without an accessId there is nothing to authenticate with, and
 * without the resource id there is nothing to read.
 */
export function useIncidentWithAccess(
  id: string | undefined,
  accessId: string | null,
  enabled = true,
) {
  return useQuery({
    queryKey: [...QUERY_ACTIONS.INCIDENTS_GET_ID, id ?? "", accessId ?? ""] as const,
    queryFn: ({ signal }) => {
      if (!id || !accessId) throw new Error("incidentIdRequired");
      return fetchIncidentWithAccess(id, accessId, signal);
    },
    enabled: Boolean(id) && Boolean(accessId) && enabled,
    staleTime: PREFETCH_STALE_TIME_MS,
  });
}
```

The four variants, with their exact names and parameters:

| Module | Hook | Params | Request fn (from `@/lib/api/specialAccess`) | Key prefix |
| --- | --- | --- | --- | --- |
| `incident.ts` | `useIncidentWithAccess` | `(id, accessId, enabled?)` | `fetchIncidentWithAccess` | `QUERY_ACTIONS.INCIDENTS_GET_ID` |
| `assets.ts` | `useAssetsWithAccess` | `(apartmentId, accessId, enabled?)` | `fetchAssetsWithAccess` | `QUERY_ACTIONS.ASSETS_GET_BY_APARTMENT` |
| `reservation.ts` | `useReservationWithAccess` | `(id, accessId, enabled?)` | `fetchReservationWithAccess` | `QUERY_ACTIONS.RESERVATIONS_GET_ID` |
| `reservationPhotos.ts` | `useReservationPhotosWithAccess` | `(id, accessId, enabled?)` | `fetchReservationPhotosWithAccess` | `QUERY_ACTIONS.RESERVATIONS_GET_PHOTOS` |

> **Name collision to resolve.** `InspectionGuidePage.tsx` already defines local hooks called
> `useReservationWithAccess`, `useShotsWithAccess` and `useReservationPhotosWithAccess`. Phase 4
> leaves those local definitions alone (they are the guide's own three reads, keyed the same way).
> This phase adds module-level hooks of the same names for the proofs page. **The proofs page must
> import from the query modules; the guide page keeps its local ones.** If the executor finds a
> duplicate-export error, the guide page's locals are the ones to rename — but only if the gate
> demands it, and the rename is `useGuideReservationWithAccess` etc. Do not rename the module-level
> hooks.

**Accept.**
- `grep -c "WithAccess" src/lib/api/queries/incident.ts src/lib/api/queries/assets.ts src/lib/api/queries/reservation.ts src/lib/api/queries/reservationPhotos.ts` → at least `2` in each
- `grep -c "await withAuth(" src/lib/api/queries/incident.ts` → `1` (the host hook only)
- `npx tsc -b` → exit 0

**Verify.** `npm run gate`

## Step 6.2 — The proofs page's guest mode

**Touch.** `src/pages/host/IncidentProofsPage.tsx` (edit)

**Do.** *(surface mode — specify, do not transcribe)*

- **Exports.** `export default function IncidentProofsPage()` — signature unchanged.
- **Consumes.** `useIncidentWithAccess` from `@/lib/api/queries/incident`; `useReservationWithAccess`
  from `@/lib/api/queries/reservation`; `useAssetsWithAccess` from `@/lib/api/queries/assets`;
  `useReservationPhotosWithAccess` from `@/lib/api/queries/reservationPhotos`;
  `IncidentItemEvidence` (unchanged); `assetBeforePhotos`.
- **The `if (accessId)` refusal branch is deleted.** It is replaced by the same
  `isGuest = accessId !== null` split the guide page uses: the host path keeps its four existing
  hooks, the guest path uses the four access-aware ones. Delete the comment claiming no
  `/incidents` endpoint accepts `?accessId=` — it does now (probed 2026-11-26).
- **The read order is preserved.** `Incident` carries `reservationId` but not `apartmentId`, so the
  chain stays: claim → reservation → (assets, photos). For a guest the same chain runs through the
  access-aware hooks, each enabled only once its id is known.
- **States.** loading → the existing spinner; **invalid link** → when the guest's claim read errors,
  render `incidentProofsPage.invalidLink.title` / `.subtitle` (new keys); not-found → the existing
  `notFound` branch (host path); empty → the existing "no items" card; ready → the existing
  per-item `SectionCard` list.
- **Capture stays live for a guest.** `IncidentItemEvidence` is rendered **without** `readOnly`, as
  it is today. Its upload/delete mutations call `uploadIncidentEvidence` / `removeIncidentEvidence`,
  which use `withAuth()` — **so they will fail for a guest.** This step therefore also passes the
  credential down: add an optional `accessId?: string` prop to `IncidentItemEvidence` and thread it
  into those two calls. That prop is the one change to a shared component in this phase.
- **Invariant.** A page holding a link never calls `withAuth()`.

**Accept.**
- `grep -c "guestUnavailable" src/pages/host/IncidentProofsPage.tsx` → `0`
- `grep -n "WithAccess" src/pages/host/IncidentProofsPage.tsx` → four matches
- `grep -n "accessId" src/components/host/incident/IncidentItemEvidence.tsx` → at least two matches

**Verify.** `npm run gate`
