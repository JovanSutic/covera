## Step 9.3 — The incident page gates button 1

**Touch.** `src/pages/host/IncidentPage.tsx` (edit)

**Do.** *(surface mode — specify, do not transcribe)*

- **Consumes.** `useReservations` from `@/lib/api/queries/reservations`; `getActionWindows`,
  `SIBLING_LIMIT` from `@/lib/helpers/actionWindows`.
- **Adds one read:** `const { data: siblingPage } = useReservations({ apartmentId: id, limit: SIBLING_LIMIT });`
  — the same hook the route now prefetches (step 8.1).
- **Computes the windows once**, after `claim` is resolved:

  ```ts
  const windows = getActionWindows({
    reservation: {
      ...reservation,
      id: reservationId,
      hasInspection: Boolean(reservation.inspection?.id),
      claimFiled: claim !== null && claim.guestResponseDeadlineAt !== null,
    },
    siblings: siblingPage?.data ?? [],
    now,
  });
  ```

  (D16: "filed" is `guestResponseDeadlineAt !== null`, the same test `ReservationIncidentSection`
  uses — the deadline existing IS the fact.)
- **The "Manage claim photos" button** (`incidentPage.managePhotos`) gains
  `disabled={!windows.manageClaimPhotos.enabled}`, `tooltip={t(windows.manageClaimPhotos.tooltipKey)}`
  and `tooltipLabel={t("incidentPage.managePhotos")}`.
- **The create button in the empty state** switches from the page's own `canOpenClaim` to
  `windows.startClaim.enabled`, and its hint copy becomes `t(windows.startClaim.tooltipKey)`.
  Delete the now-unused `canOpenClaimAt` import if nothing else uses it.
- **States.** unchanged. Only the two buttons' enable rules change.
- **Invariant.** One clock per page — reuse the existing `now` from `useClaimClock()`; do not add a
  second capture.
