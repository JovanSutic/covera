# p2 — Language fixes and the guide page (prep 1, 2, 6)

**Prerequisite:** p1 (gate green)
**Gate:** `npm run gate`

## Why this phase exists

Three defects, all verified by reading the code:

- **Prep 1.** `Header.tsx`'s `handleLanguageChange` **deletes** `?lang` when the host picks
  `en` (correct — a clean URL is the default), but `currentLang`'s fallback is
  `i18n.language`, which is still the *previous* language at that moment. So choosing `en`
  sets no param and falls back to, say, `de` — English is unreachable.
- **Prep 6.** `guide.sections.*.points` is a JSON **array** in `en` and a numeric-keyed
  **object** in `de`, `tr` and `sr-Latn`. `DamageClaimGuidePage` calls `.map()` on it, so
  the page throws in every non-English locale.
- **Prep 2.** The guide page has no back affordance.

---

## Step 2.1 — Fix the language round-trip

**Touch:** `src/components/Header.tsx` (edit)

**Do:**
`handleLanguageChange` must change the language **before** it touches the URL, so that
`en` — which removes the param — falls back to the *new* `i18n.language` rather than the
stale one (D5). Replace the whole handler:

```ts
  // Update query param on select change
  const handleLanguageChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
    const selectedLang = e.target.value;

    // Change the language FIRST. `currentLang`'s fallback is `i18n.language`, and for
    // `en` the branch below REMOVES the param — so switching to `en` while `i18n` still
    // held the old language made `currentLang` resolve back to it and the selection
    // appeared to do nothing (prep 1). The effect above then sees no change to make.
    void i18n.changeLanguage(selectedLang);

    const newParams = new URLSearchParams(searchParams);

    if (selectedLang === "en") {
      newParams.delete("lang"); // Keep URL clean for default language
    } else {
      newParams.set("lang", selectedLang);
    }

    setSearchParams(newParams, { replace: true });
  };
```

Do **not** change the `en`-deletes-the-param rule (D6): `withLang` documents it, and every
link the app builds depends on it.

**Accept:**
- `grep -n "changeLanguage(selectedLang)" src/components/Header.tsx` → one hit inside `handleLanguageChange` ✓
- `grep -n "newParams.delete(\"lang\")" src/components/Header.tsx` → still exactly one hit ✓
- `grep -c "i18n.changeLanguage" src/components/Header.tsx` → `2` (the effect, plus this call) ✓
- `npx tsc -b` clean ✓

## Step 2.3 — Add the defensive `guidePoints` helper

**Touch:** `src/lib/helpers/guidePoints.ts` (create), `src/lib/helpers/guidePoints.test.ts` (create)

**Do:**
A repaired locale file is one `npm run i18n:translate` away from regressing (D8), and the
crash is a blank page rather than a visible error. Add the helper that makes a wrong shape
render an empty list instead of throwing.

Create `src/lib/helpers/guidePoints.ts`:

```ts
/**
 * D8: the guide's bullet list, read defensively.
 *
 * `guide.sections.*.points` is an ARRAY in `en` and was a numeric-keyed OBJECT in `de`,
 * `tr` and `sr-Latn` — `npm run i18n:translate`'s `unflattenObject` writes arrays back that
 * way, and `DamageClaimGuidePage` called `.map()` on the result, so the page threw in every
 * non-English locale (prep 6). The locale files are repaired, but the script that broke them
 * still does this, so the page must not depend on the shape being right.
 *
 * A non-array renders as an empty list. That is the honest degradation: the section still
 * shows its title and body, and a wrong `points` shape costs three bullets rather than the
 * whole page.
 */
export function guidePoints(value: unknown): string[] {
  if (Array.isArray(value)) {
    return value.filter((entry): entry is string => typeof entry === "string");
  }

  // The numeric-keyed object the translate script produces. Keyed order is the authoring
  // order, so sorting numerically preserves it.
  if (value !== null && typeof value === "object") {
    return Object.keys(value as Record<string, unknown>)
      .filter((key) => /^\d+$/.test(key))
      .sort((a, b) => Number(a) - Number(b))
      .map((key) => (value as Record<string, unknown>)[key])
      .filter((entry): entry is string => typeof entry === "string");
  }

  return [];
}
```

Create `src/lib/helpers/guidePoints.test.ts`:

```ts
import { describe, expect, it } from "vitest";

import { guidePoints } from "./guidePoints";

describe("guidePoints", () => {
  it("returns a real array unchanged", () => {
    expect(guidePoints(["one", "two"])).toEqual(["one", "two"]);
  });

  it("recovers the numeric-keyed object the translate script writes", () => {
    // The exact shape `de`/`tr`/`sr-Latn` carried before step 2.2 — the regression this
    // helper exists to survive.
    expect(guidePoints({ "0": "one", "1": "two", "2": "three" })).toEqual([
      "one",
      "two",
      "three",
    ]);
  });

  it("orders numeric keys numerically, not lexically", () => {
    expect(guidePoints({ "2": "c", "10": "d", "0": "a" })).toEqual(["a", "c", "d"]);
  });

  it("drops non-string entries rather than rendering them", () => {
    expect(guidePoints(["one", 42, null, "two"])).toEqual(["one", "two"]);
  });

  it("returns an empty list for anything unusable", () => {
    expect(guidePoints(undefined)).toEqual([]);
    expect(guidePoints(null)).toEqual([]);
    expect(guidePoints("one")).toEqual([]);
    expect(guidePoints(7)).toEqual([]);
  });
});
```

**Accept:**
- `npx vitest run src/lib/helpers/guidePoints.test.ts` → 5 tests pass ✓
- `grep -c "export function guidePoints" src/lib/helpers/guidePoints.ts` → `1` ✓

**Verify:** `npx vitest run src/lib/helpers/guidePoints.test.ts`
