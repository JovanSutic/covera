# p5 — The proofs page (prep 3)

**Prerequisite:** p1, p4
**Gate:** `npm run gate`

## Why this phase exists

Prep 3: the claim page must stop being where photos are captured. This phase builds the page
that owns that work — `/incident/:incidentId/proofs` — showing each claimed asset's before
photos, its captured photos, and its remaining photo slots.

**Why the route is top-level and `public` (D25):** it must be reachable by a guest holding an
access link, so it cannot inherit the `host` section's `canOpenHost`. `routes/public.ts`
already documents this exact shape for the future capability guard.

**What is blocked, and why this page is host-only in practice:** no `/incidents*` endpoint
accepts `?accessId=` (probed 2026-11-23), so a guest genuinely cannot load this page's data.
The route accepts the parameter so the URL shape is stable, and the guest branch renders an
explicit refusal (D31) rather than a spinner or a crash.

## Step 5.1 — Register the path

**Touch:** `src/lib/router/paths.ts` (edit)

**Do:**
Add one entry to `appPaths`, after `damageClaimGuide`. Both `paths.ts`'s `ParamKeysMatch`
guard and the route declaration must agree, or the guard fails the build.

```ts
  // D25 (feature/54): the claim's proof page. TOP LEVEL and `public`, not under `host` —
  // a guest holding an access link must be able to open it, and a `host`-section route
  // could only ever be host-only (routes/public.ts carries the same reasoning for
  // `inspectionGuide`). The page itself enforces "host session OR accessId" (D26), because
  // `ACCESS_RULES` are session-derived and cannot see a query parameter.
  //
  // The param is the INCIDENT id, not the reservation: every read and write the page makes
  // is keyed by the claim, and passing the reservation would force the list-then-match dance
  // the incident page already performs.
  incidentProofs: {
    pattern: "/incident/:incidentId/proofs",
    requires: ["public"],
    params: { incidentId: "uuid" },
  },
```

**Accept:**
- `grep -n "incidentProofs" src/lib/router/paths.ts` → one hit ✓
- `npx tsc -b` clean — `ParamKeysMatch` would error if the param were undeclared ✓

**Verify:** `npm run gate`

## Step 5.2 — Add the route declaration

**Touch:** `src/lib/router/routes/public.ts` (edit)

**Do:**
Add to `appRoutes`, after the `inspection-guide/:apartmentId/:reservationId` entry and before
the `*` catch-all. Every resource the page reads must be declared here or
`prefetchCoverage.test.ts` fails (it compares a page's imported hooks against its route
chain):

```ts
  {
    // D25 (feature/54): the claim's proof page. `public` because a guest access link must
    // be able to open it — the same reason `inspectionGuide` above is top-level. The page
    // enforces "host session OR accessId" itself (D26); a rule name cannot express a query
    // parameter.
    //
    // All four reads are declared even though the page gates them behind a claim existing:
    // `prefetchCoverage.test.ts` requires a page's route chain to declare every hook the
    // page reads. Three resolve to null (their ids come from the claim, not the URL), which
    // is how this registry says "declared for coverage, not prefetched".
    path: "incident/:incidentId/proofs",
    requires: "public",
    params: { incidentId: "uuid" },
    page: () => import("@/pages/host/IncidentProofsPage"),
    data: [
      { resource: "incident", params: (params) => ({ id: String(params.incidentId) }) },
      { resource: "reservation", params: () => null },
      { resource: "assets", params: () => null },
      { resource: "reservationPhotos", params: () => null },
    ],
    handle: { crumb: "incidentProofsPage.title" },
  },
```

`incident` resolves from the URL (the id is the param). `reservation`, `assets` and
`reservationPhotos` need ids that are only knowable once the claim resolves — so they declare
`null`, the registry's documented "not on this navigation".

**Accept:**
- `grep -n "incident/:incidentId/proofs" src/lib/router/routes/public.ts` → one hit ✓
- `npx vitest run src/lib/router/__checks__/tree.test.ts` → passes (the `appPaths` entry from step 5.1 now has a route whose rules are `["public"]`) ✓
- `npx tsc -b` clean ✓

**Verify:** `npx vitest run src/lib/router/__checks__/tree.test.ts`

## Step 5.3 — The proofs page

**Touch:** `src/pages/host/IncidentProofsPage.tsx` (create)

**Do (contract — the executor writes the JSX):**

Create the page. Follow `IncidentPage.tsx` for the read order, the loading/notFound branches
and the `BackLink`, and `IncidentItemEvidence.tsx` for the per-item photo strip.

**Exports:**
```ts
export default function IncidentProofsPage(): JSX.Element
```

**Reads, by exported name:**
- `useIncident(incidentId)` from `@/lib/api/queries/incident`
- `useReservation(reservationId)` from `@/lib/api/queries/reservation`
- `useAssets(apartmentId)` from `@/lib/api/queries/assets`
- `useReservationPhotos(reservationId)` from `@/lib/api/queries/reservationPhotos`
- `useRouteParams(appPaths.incidentProofs)` from `@/lib/router`
- `useSearchParams` from `react-router` — for the `accessId` guest check
- `IncidentItemEvidence` from `@/components/host/incident/IncidentItemEvidence` (D30 — reuse,
  do not reimplement)
- `assetBeforePhotos` from `@/lib/helpers/assetBeforePhotos`
- `PageLayout`, `PageTitle`, `SectionCard`, `BackLink`

**Derivation order — this is forced by the API and must be followed exactly:**
1. `useIncident(incidentId)` gives the claim and its items. **`Incident` carries
   `reservationId` but NOT `apartmentId`** (verified in `types.gen.ts`).
2. `reservationId` comes from the claim (`claim.reservationId`).
3. `useReservation(reservationId)` — enabled only once step 2 has an id — is where
   `apartmentId` comes from (`reservation.apartmentId`). There is no shorter path: the claim
   does not carry it, and the URL does not either.
4. `useAssets(apartmentId)` and `useReservationPhotos(reservationId)` are enabled only once
   step 3 has resolved.

Do **not** read the apartment's incident list: the claim id is the URL param, so the
list-then-match dance `IncidentPage` performs is unnecessary here.

**State branches it must handle:**
1. **guest** — an `accessId` search param is present: render the refusal state (D31) using
   `incidentProofsPage.guestUnavailable.title` / `.body`, plus a `BackLink` to nothing (no
   guest destination exists) — render the title and body only. This branch is checked
   **before** the claim read so a guest never sees a spinner that never resolves.
2. **loading** — the claim read is loading: the `incidentProofsPage.loading` line.
3. **notFound** — the claim read errored or resolved empty: `incidentProofsPage.notFound.title`
   / `.subtitle`, with the back link.
4. **empty** — the claim exists but has no items: `incidentProofsPage.empty`.
5. **success** — one `SectionCard` per item, titled with the asset's name, containing the
   before photos and the item's photo slots.
6. **no before photos** — when `assetBeforePhotos(...)` returns none for an item, render
   `incidentProofsPage.before.none` rather than an empty strip.

**Render `IncidentItemEvidence` WITHOUT `readOnly`.** This is the page where capture and
delete are live (prep 3: "you can delete the current ones just the same as we have it now").
The claim page passes `readOnly` (p6); this page must not, or the new page would be
display-only too and prep 3 would be unimplemented.

**t() keys it renders — all under `incidentProofsPage.*`:**
`title`, `subtitle`, `loading`, `notFound.title`, `notFound.subtitle`, `empty`,
`backToClaim`, `before.title`, `before.none`, `guestUnavailable.title`,
`guestUnavailable.body`, `slots.title`.

The per-slot and per-photo labels are **not** new keys — `IncidentItemEvidence` already
renders `incidentPage.evidence.*` and `evidenceLabelKey(type)`. Reuse it (D30).

**Invariant it must not break:** invariant 2 — every string through `t("host")`. And
invariant 8: this page makes **no** anonymous read in this phase. The guest branch renders
before any fetch, so no `withAuth()` call can occur on a guest's behalf.

**Accept:**
- `grep -c "export default function IncidentProofsPage" src/pages/host/IncidentProofsPage.tsx` → `1` ✓
- `grep -n "IncidentItemEvidence" src/pages/host/IncidentProofsPage.tsx` → at least one hit ✓
- `grep -n "appPaths.incidentProofs" src/pages/host/IncidentProofsPage.tsx` → one hit ✓
- `grep -n "accessId" src/pages/host/IncidentProofsPage.tsx` → at least one hit ✓
- `grep -n "withAuth\|publicApi" src/pages/host/IncidentProofsPage.tsx` → no hits ✓
- `npx tsc -b` clean ✓

**Verify:** `npm run gate`
