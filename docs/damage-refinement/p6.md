# p6 — Incident page goes view-mode (prep 3, host side)

**Prerequisite:** p5
**Gate:** `npm run gate`

## Why this phase exists

Prep 3: "the old page stays the same, but the photos are in the view mode, there should be a
button with something manage claim photos, when you click it you will go to another page."

So the claim page keeps *showing* each item's photos and before photos, but stops being where
they are captured. One button leads to the page p5 built.

---

## Step 6.1 — Remove the capture controls, keep the display

**Touch:** `src/components/host/incident/IncidentItemEvidence.tsx` (edit)

**Do:**
Add a `readOnly` prop. When it is `true`, the component renders the before photos and the
captured photos exactly as now, and renders **no** capture buttons and **no** delete buttons
(D32). The upload/delete mutations stay in the file: the proofs page (p5) still uses them
(D34).

Add to the props interface:

```ts
  /**
   * D32 (feature/54): display-only. The claim page shows what an item has and offers no
   * capture or delete control — that work moved to `/incident/:incidentId/proofs`. The
   * mutations stay in this file because that page renders this same component.
   */
  readOnly?: boolean;
```

Destructure it with a default of `false`, so every existing caller and test is unaffected:

```ts
export function IncidentItemEvidence({
  incidentId,
  item,
  beforePhotos = [],
  renderCapture,
  readOnly = false,
}: IncidentItemEvidenceProps) {
```

Then guard the two interactive regions:

- The capture region — the whole `{renderCapture ? (…) : (…)}` block **and** its sibling
  `<input type="file">` — renders only when `!readOnly`.
- The delete button on each captured photo renders only when `!readOnly`.

The photo `<ul>` and the before-photo `<ul>` render in both modes, unchanged.

**Accept:**
- `grep -n "readOnly" src/components/host/incident/IncidentItemEvidence.tsx` → at least three hits (the prop, the destructure, the guards) ✓
- `grep -c "readOnly = false" src/components/host/incident/IncidentItemEvidence.tsx` → `1` ✓
- `npx vitest run src/components/host/incident/IncidentItemEvidence.test.tsx` → **passes unchanged** (the default keeps every existing assertion valid) ✓
- `npx tsc -b` clean ✓

**Verify:** `npx vitest run src/components/host/incident/IncidentItemEvidence.test.tsx`

## Step 6.2 — Point the claim page at the proofs page

**Touch:** `src/pages/host/IncidentPage.tsx` (edit)

**Do:**
Two changes.

**(a)** Pass `readOnly` to the evidence component, so the claim page is display-only:

```tsx

                      incidentId={claim.id}
                      item={item}
                      beforePhotos={assetBeforePhotos(reservationPhotos, item.assetId)}
                      readOnly
                    />
```

**(b)** Add the manage-photos button (D33) inside the items `SectionCard`, after
`<IncidentItemList>`, so it sits with the list it manages. It is rendered only when a claim
exists (D35) — it is already inside the `{claim && (…)}` block:

```tsx
              <div className="mt-4">
                <ActionButton
                  variant="neutral"
                  size="md"
                  icon={<Camera className="h-4 w-4 shrink-0" />}
                  label={t("incidentPage.managePhotos")}
                  onClick={() =>
                    navigate(
                      withLang(
                        buildPath(appPaths.incidentProofs, {
                          incidentId: claim.id,
                        }),
                        i18n.language,
                      ),
                    )
                  }
                />
              </div>
```

Imports to add:

```ts
import { Camera } from "lucide-react";           // extend the existing lucide import
import { useNavigate } from "react-router";

```

`appPaths` is already imported. `useNavigate` and `withLang` are **not** — add them. `withLang`
keeps the active language on the hop, the same as every other in-app navigation on this page's
sibling (`ReservationPage`).
