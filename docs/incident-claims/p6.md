# Phase 6 — Open a claim and list its items

**Prerequisite:** phase 5 (the reservation section is what links here, and its status-chip pattern is
what this phase's item rows follow)
**Gate:** `npm run gate`

The phase where the claim page stops being a stub. It creates the write module, the feature's **only
form**, the item list, and the page that composes them — and it is the first phase that consumes
phase 1's evidence vocabulary on screen.

Five things to know before starting:

1. **This is the only form in the feature, and invariant 8 applies to it.** react-hook-form + a zod
   schema through `@hookform/resolvers`, exactly as `CreateAssetForm.tsx` does it. A controlled
   `<select>` or a hand-rolled `useState` validation is a red gate in review even though `tsc` passes.
2. **D48: the form adds ONE asset per submission.** One asset, one type, one optional value. Adding
   three assets is three submissions, each behind the same pending state. It is **not** a
   `MultiSelect` — D48 rejects that explicitly, on the grounds that the type is a per-submission
   question and a multi-select would have to ask it once for the whole selection.
3. **The item list renders phase 1's vocabulary, it does not re-derive it.** `itemStatusCopy`,
   `requiredPhotoTypes`, `missingPhotoTypes`, `activePhotoCount` and `evidenceLabelKey` all exist. A
   `Record` of label keys written a second time in the component is drift (invariant 9).
4. **`StatusChip` is new in this phase (D47).** The tone→classes map would be its third copy here, so
   it moves into `src/components/shared/StatusChip.tsx`. Phases 7 and 8 reuse it. The two legacy copies
   in `ReservationProofSection` and `ReservationIncidentSection` are **not** migrated — that is a
   separate change to two components that each have a passing test, and it is out of scope.
5. **`mode: "onChange"` on the form is deliberate (D49).** The submit is disabled while `!isValid`,
   the `CreateAssetForm` pattern — but under react-hook-form's default `onSubmit` mode `isValid` does
   not update until a submit, which the disabled button prevents. See D49.

### Step 6.1 — Create the write module

**Touch.** `src/lib/api/incidentClaims.ts` (create)

**Do.** D13/D12: these are plain functions called from mutations, never resources and never declared
in a route's `data:`. This step writes the two phase 6 needs; phases 7 and 8 append to the same file.

```ts
import {
  postIncidents,
  postIncidentsByIdItems,
} from "@/api/generated/requests/sdk.gen";
import type { CreateIncidentItem } from "@/api/generated/requests/types.gen";
import { withAuth } from "@/lib/api/api";

/**
 * The claim write path (D13).
 *
 * These are plain async functions, NOT `ResourceDefinition`s and NOT registered in
 * `registry.ts`. A prefetch is speculative and there is nothing speculative about a
 * write; `ResourceDefinition` has no shape for one either. `submitPhotoProofs.ts`
 * is the existing precedent for a write module living flat in `src/lib/api/`, beside
 * `api.ts` and outside `queries/`.
 *
 * Every call here authenticates with `withAuth()` — the host is signed in. The field
 * portal's three calls are the anonymous exception and they live in
 * `src/lib/api/fieldIncident.ts` (phase 9), not here (D12).
 *
 * Errors are NOT caught and re-worded here. The generated client is configured with
 * `throwOnError: true` (see `withAuth`), so a failure rejects with the backend's own
 * payload and the caller's `onError` reads `error?.error?.message` — the backend's
 * own sentence (D33). There is no `error.code` switch anywhere in this feature.
 */

export async function createIncident(
  reservationId: string,
  signal?: AbortSignal,
) {
  const config = await withAuth(signal ? { signal } : {});
  const response = await postIncidents({
    ...config,
    body: { reservationId },
  });

  return response.data;
}

/**
 * D48: the form adds exactly ONE item per submission, so there is no loop here and
 * none at the call site. Adding three assets is three calls, each with its own
 * pending state.
 *
 * It takes the already-shaped `CreateIncidentItem` rather than an asset id, because
 * the item's `type` is the caller's decision and `estimatedPlaceholderValueCents` is
 * optional — `AddIncidentItemForm` decides both, and omits the value entirely when
 * the host has not priced the item (phase 2's `parseCentsFromInput` returns `null`
 * for "not said yet", which is not the same answer as zero).
 */
export async function addIncidentItem(
  incidentId: string,
  item: CreateIncidentItem,
  signal?: AbortSignal,
) {
  const config = await withAuth(signal ? { signal } : {});
  const response = await postIncidentsByIdItems({
    ...config,
    path: { id: incidentId },
    body: item,
  });

  return response.data;
}
```

```tsx
import { useTranslation } from "react-i18next";
import { Package, TriangleAlert } from "lucide-react";

import { StatusChip } from "@/components/shared/StatusChip";
import { formatCents } from "@/lib/helpers/claimMoney";
import { itemStatusCopy } from "@/lib/helpers/claimStatus";
import {
  activePhotoCount,
  evidenceLabelKey,
  missingPhotoTypes,
  requiredPhotoTypes,
} from "@/lib/helpers/incidentEvidence";
import type { IncidentItem } from "@/api/generated/requests/types.gen";

interface IncidentItemListProps {
  items: readonly IncidentItem[];
}

/**
 * The claim's items, one row each.
 *
 * It reads phase 1's vocabulary and renders it — it does NOT decide what a status
 * means (invariant 9). `itemStatusCopy` returns the tone and the label key;
 * `requiredPhotoTypes` / `missingPhotoTypes` / `activePhotoCount` answer "what is
 * still needed". A second `Record` of label keys here, or an `=== "complete"`, is
 * drift.
 *
 * The room comes from `assets:roomLocations.*`: `roomLocations` is an `assets.json`
 * key and this component's `t` is bound to `host`, so the namespace prefix is
 * load-bearing — without it the row shows the raw key string. `ReservationPhotoGallery`
 * carries the same prefix for the same reason.
 */
export function IncidentItemList({ items }: IncidentItemListProps) {
  const { t } = useTranslation("host");

  if (items.length === 0) {
    return (
      <div className="flex items-start gap-3">
        <Package className="mt-0.5 h-5 w-5 shrink-0 text-gray-400" />
        <p className="text-sm text-gray-500 dark:text-gray-400">
          {t("incidentPage.items.empty")}
        </p>
      </div>
    );
  }

  return (
    <ul className="space-y-3">
      {items.map((item) => {
        const copy = itemStatusCopy(item.status);
        const required = requiredPhotoTypes(item.type);
        const missing = missingPhotoTypes(item);

        return (
          <li
            key={item.id}
            className="rounded-lg border border-gray-200 p-3 dark:border-gray-800"
          >
            <div className="flex items-start justify-between gap-3">
              <div className="min-w-0">
                <p className="truncate text-sm font-medium text-gray-900 dark:text-gray-100">
                  {item.asset.name}
                </p>
                <p className="mt-0.5 text-xs text-gray-500 dark:text-gray-400">
                  {t(`assets:roomLocations.${item.asset.roomLocation}`, {
                    defaultValue: item.asset.roomLocation,
                  })}
                  {" · "}
                  {t(`incidentPage.itemType.${item.type}`)}
                  {" · "}
                  {formatCents(item.estimatedPlaceholderValueCents)}
                </p>
              </div>

              <StatusChip tone={copy.tone} label={t(copy.labelKey)} />
            </div>

            {/* What the evidence must contain for THIS item's type (D21). The list is
                phase 1's answer, not a second copy of the backend's rule. */}
            <div className="mt-2.5">
              <p className="text-xs font-medium uppercase tracking-wide text-gray-500 dark:text-gray-400">
                {t("incidentPage.items.views")}
              </p>

              <ul className="mt-1 space-y-0.5">
                {required.map((type) => {
                  const collected = activePhotoCount(item, type) > 0;

                  return (
                    <li
                      key={type}
                      className="flex items-center gap-1.5 text-xs text-gray-600 dark:text-gray-300"
                    >
                      {!collected && (
                        <TriangleAlert className="h-3 w-3 shrink-0 text-amber-500" />
                      )}
                      <span
                        className={
                          collected ? "" : "text-gray-500 dark:text-gray-400"
                        }
                      >
                        {t(evidenceLabelKey(type))}
                      </span>
                    </li>
                  );
                })}
              </ul>

              <p className="mt-1 text-xs text-gray-500 dark:text-gray-400">
                {missing.length === 0
                  ? t("incidentPage.items.viewsComplete")
                  : t("incidentPage.items.viewsMissing", { count: missing.length })}
              </p>
            </div>
          </li>
        );
      })}
    </ul>
  );
}
```

### Step 6.4 — Create the add-item form

**Touch.** `src/components/host/incident/AddIncidentItemForm.tsx` (create)

**Do.** D48: **one asset, one type, one optional value** per submission. The feature's only form, so
invariant 8 applies — zod through `@hookform/resolvers`, exactly as `CreateAssetForm.tsx` does it,
including the `eslint-disable` header both files need for the `onError: any` payload (D33).

```tsx
/* eslint-disable @typescript-eslint/no-explicit-any */
import { useMemo } from "react";
import { useForm, Controller } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import { useTranslation } from "react-i18next";
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { toast } from "sonner";

import Button from "@/components/formItems/Button";
import Input from "@/components/formItems/Input";
import Select from "@/components/formItems/Select";
import type { RichOption } from "@/components/formItems/Select";
import { addIncidentItem } from "@/lib/api/incidentClaims";
import { useAssets } from "@/lib/api/queries/assets";
import { incidentsQueryKey } from "@/lib/api/queries/incidents";
import { incidentQueryKey } from "@/lib/api/queries/incident";
import { parseCentsFromInput } from "@/lib/helpers/claimMoney";
import type { IncidentItemWithToken } from "@/api/generated/requests/types.gen";

/**
 * Validation messages are i18n KEYS, not sentences — the convention
 * `CreateAssetForm`'s schema already uses. The key is resolved by `t()` at the point
 * it is rendered, which is the only way a validation error can be translated.
 */
const addItemSchema = z.object({
  assetId: z.string().min(1, "incidentPage.addItem.validation.assetRequired"),
  type: z.enum(["damage", "theft"], {
    message: "incidentPage.addItem.validation.typeRequired",
  }),
  value: z.string().optional(),
});

type AddItemFormValues = z.infer<typeof addItemSchema>;

interface AddIncidentItemFormProps {
  apartmentId: string;
  incidentId: string;
  /** D27: the assets already on the claim. The picker offers everything BUT these. */
  claimedAssetIds: readonly string[];
  /**
   * D50: the created item, carrying its `cleanerToken` — which ONLY this response
   * and the reissue response have. Phase 7's page keeps the token in session state;
   * without this callback the freshly minted link would be unreachable until a
   * reissue, because `GET /incidents/{id}` does not return tokens.
   *
   * Optional, so phase 6's own tests render the form without wiring a parent.
   */
  onItemAdded?: (item: IncidentItemWithToken) => void;
}

const DEFAULT_FORM_VALUES: AddItemFormValues = {
  assetId: "",
  // Most claims are damage, and the host switching it is one click. The alternative —
  // an empty default — would leave the form permanently invalid, because a `Select`
  // with no matching option renders blank and the enum would reject "".
  type: "damage",
  value: "",
};

/**
 * The feature's only form (invariant 8).
 *
 * D27: the picker lists the apartment's assets MINUS those already on the claim. The
 * backend refuses a duplicate with `INCIDENT_ITEM_EXISTS`, and offering an action the
 * API will reject is the failure this filter prevents — the same principle as
 * `getReservationActionAvailability`.
 *
 * D48: ONE asset per submission. Adding five assets is five submissions, each with its
 * own type — which matters, because the same asset cannot be both damaged and stolen,
 * but two assets on one claim routinely differ.
 *
 * D49: `mode: "onChange"`. The submit is disabled while `!isValid` (the
 * `CreateAssetForm` pattern), and under react-hook-form's default `onSubmit` mode
 * `isValid` is not recomputed until a submit — which the disabled button makes
 * impossible. `onChange` is what makes `isValid` track the selection.
 */
export function AddIncidentItemForm({
  apartmentId,
  incidentId,
  claimedAssetIds,
  onItemAdded,
}: AddIncidentItemFormProps) {
  const { t } = useTranslation("host");
  const queryClient = useQueryClient();

  // The route already declared this read (phase 4), so on a normal navigation it is a
  // cache hit and starts no request.
  const { data: assets = [], isLoading: areAssetsLoading } = useAssets(apartmentId);

  const claimed = useMemo(() => new Set(claimedAssetIds), [claimedAssetIds]);

  const availableOptions: RichOption[] = useMemo(
    () =>
      assets
        .filter((asset) => asset.isActive && !claimed.has(asset.id))
        .map((asset) => ({
          value: asset.id,
          label: asset.name,
          subLabel: t(`assets:roomLocations.${asset.roomLocation}`, {
            defaultValue: asset.roomLocation,
          }),
        })),
    [assets, claimed, t],
  );

  const typeOptions: RichOption[] = useMemo(
    () => [
      { value: "damage", label: t("incidentPage.itemType.damage") },
      { value: "theft", label: t("incidentPage.itemType.theft") },
    ],
    [t],
  );

  const {
    control,
    register,
    handleSubmit,
    reset,
    formState: { errors, isSubmitting, isValid },
  } = useForm<AddItemFormValues>({
    resolver: zodResolver(addItemSchema),
    mode: "onChange",
    defaultValues: DEFAULT_FORM_VALUES,
  });

  const { mutate, isPending } = useMutation({
    mutationFn: (values: AddItemFormValues) => {
      const cents = parseCentsFromInput(values.value ?? "");

      return addIncidentItem(incidentId, {
        assetId: values.assetId,
        type: values.type,
        // Omitted rather than sent as 0 — "not priced yet" and "worth nothing" are
        // different answers (phase 2's `parseCentsFromInput`).
        ...(cents === null ? {} : { estimatedPlaceholderValueCents: cents }),
      });
    },
    onSuccess: (created) => {
      // Both keys the write changed (invariant 7): the detail the item rows read, and
      // the apartment's list the reservation section reads — its item count and total
      // are stale the moment this returns.
      queryClient.invalidateQueries({ queryKey: incidentQueryKey(incidentId) });
      queryClient.invalidateQueries({
        queryKey: incidentsQueryKey({ apartmentId }),
      });

      // D50: the only moment this item's field token is knowable until a reissue.
      if (created) onItemAdded?.(created);

      toast.success(t("incidentPage.toasts.itemAdded"));
      // The added asset is now in `claimedAssetIds`, so the picker no longer offers it.
      // Clearing the selection here is what stops the next submit from resending a
      // value the list no longer shows.
      reset(DEFAULT_FORM_VALUES);
    },
    onError: (error: any) => {
      toast.error(error?.error?.message || t("incidentPage.toasts.itemAddError"));
    },
  });

  const noOptionsLeft = !areAssetsLoading && availableOptions.length === 0;

  return (
    <form
      onSubmit={handleSubmit((values) => mutate(values))}
      className="flex w-full flex-col gap-4"
    >
      {noOptionsLeft ? (
        <p className="text-sm text-gray-500 dark:text-gray-400">
          {t("incidentPage.addItem.allClaimed")}
        </p>
      ) : (
        <Controller
          name="assetId"
          control={control}
          render={({ field }) => (
            <Select
              label={t("incidentPage.addItem.asset")}
              options={availableOptions}
              disabled={areAssetsLoading}
              value={field.value}
              onChange={field.onChange}
              error={
                errors.assetId?.message ? t(errors.assetId.message) : undefined
              }
              ref={field.ref}
            />
          )}
        />
      )}

      <Controller
        name="type"
        control={control}
        render={({ field }) => (
          <Select
            label={t("incidentPage.addItem.type")}
            options={typeOptions}
            value={field.value}
            onChange={field.onChange}
            error={errors.type?.message ? t(errors.type.message) : undefined}
            ref={field.ref}
          />
        )}
      />

      <Input
        label={t("incidentPage.addItem.value")}
        type="text"
        inputMode="decimal"
        placeholder={t("incidentPage.addItem.valueHint")}
        error={errors.value?.message ? t(errors.value.message) : undefined}
        {...register("value")}
      />

      <Button
        type="submit"
        className="w-full py-3 disabled:opacity-50 disabled:cursor-not-allowed"
        disabled={isSubmitting || isPending || !isValid || noOptionsLeft}
        isLoading={isPending}
      >
        {isSubmitting || isPending
          ? t("incidentPage.addItem.submitting")
          : t("incidentPage.addItem.submit")}
      </Button>
    </form>
  );
}
```

### Step 6.5 — Create the item-list test

**Touch.** `src/components/host/incident/IncidentItemList.test.tsx` (create)

**Do.** No query mocks: the component takes its items as props, so this is a pure render. `t()` is
global-mocked by `test-setup.ts` to return the key, so every assertion is on a **key**, never on
English.

Note the matcher discipline: where a key shares a `<p>` with the type and the value, the assertion is
a **regex**. `getByText` with an exact string compares an element's own text, and no single element
owns that key alone.

```tsx
import { describe, expect, it } from "vitest";
import { render, screen } from "@testing-library/react";

import { IncidentItemList } from "./IncidentItemList";
import type {
  IncidentEvidence,
  IncidentItem,
} from "@/api/generated/requests/types.gen";

function evidence(
  evidenceType: IncidentEvidence["evidenceType"],
  overrides: Partial<IncidentEvidence> = {},
): IncidentEvidence {
  return {
    id: `e-${evidenceType}`,
    incidentItemId: "item-1",
    evidenceType,
    storageKey: "key-1",
    exifCapturedAt: null,
    exifLatitude: null,
    exifLongitude: null,
    status: "active",
    deletedAt: null,
    createdAt: "2026-11-08T12:00:00.000Z",
    kind: evidenceType.includes("photo") ? "photo" : "document",
    ...overrides,
  };
}

function item(overrides: Partial<IncidentItem> = {}): IncidentItem {
  return {
    id: "item-1",
    incidentId: "incident-1",
    assetId: "asset-1",
    type: "damage",
    status: "link_generated",
    tokenExpiresAt: "2026-11-08T20:00:00.000Z",
    estimatedPlaceholderValueCents: 5000,
    descriptionByCleaner: null,
    createdAt: "2026-11-08T10:00:00.000Z",

      name: "Bedroom Curtains",
      roomLocation: "BEDROOM_PRIMARY",
    } as IncidentItem["asset"],

    ...overrides,

}

describe("IncidentItemList", () => {

    render(<IncidentItemList items={[]} />);

    expect(screen.getByText("incidentPage.items.empty")).toBeInTheDocument();

    render(<IncidentItemList items={[item()]} />);
```

### Step 6.7 — Compose the page

**Touch.** `src/pages/host/IncidentPage.tsx` (replace the phase-4 stub)

**Do.** The stub becomes the real page. Every hook is called before the first early return (rules of
hooks), and the page reads **both** the list and the detail — the list is how it finds its claim
(D11), the detail is what carries the items.

```tsx
/* eslint-disable @typescript-eslint/no-explicit-any */
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { useTranslation } from "react-i18next";
import { FileWarning, Plus } from "lucide-react";
import { toast } from "sonner";

import PageLayout from "@/components/layout/PageLayout";
import PageTitle from "@/components/PageTitle";
import { ActionButton } from "@/components/shared/ActionButton";
import { BackLink } from "@/components/shared/BackLink";
import { SectionCard } from "@/components/shared/SectionCard";
import { StatusChip } from "@/components/shared/StatusChip";
import { AddIncidentItemForm } from "@/components/host/incident/AddIncidentItemForm";
import { IncidentItemList } from "@/components/host/incident/IncidentItemList";
import { createIncident } from "@/lib/api/incidentClaims";
import { useIncident, incidentQueryKey } from "@/lib/api/queries/incident";
import { useIncidents, incidentsQueryKey } from "@/lib/api/queries/incidents";
import { useReservation } from "@/lib/api/queries/reservation";
import {
  claimStatusCopy,
  findIncidentForReservation,
  isIncidentEditable,
} from "@/lib/helpers/claimStatus";
import { appPaths, useRouteParams } from "@/lib/router";
import type { IncidentWithItems } from "@/api/generated/requests/types.gen";

/**
 * The claim page. The spec's rows 2 and 3 are this page; phase 8 adds the filing panel
 * that is row 4.
 *
 * The read order is forced by the API:
 *
 *   1. `useIncidents({ apartmentId })` — the apartment's claim list. There is NO
 *      incident-by-reservation endpoint (D11), so this is the only way to learn whether
 *      this reservation has a claim.
 *   2. `findIncidentForReservation` — phase 1's helper picks it out. Both host surfaces
 *      call it, so they cannot match differently.
 *   3. `useIncident(listed?.id)` — the detail, which is what carries `items`. It stays
 *      disabled until step 1 resolves, because the id is not in the URL.
 *
 * `claim = detail ?? listed`: the list's `IncidentWithItems` already has items, so the
 * page paints from the list immediately and refines once the detail lands. The detail is
 * still worth reading — it is the key the item writes invalidate (invariant 7).
 */
export default function IncidentPage() {
  const { t } = useTranslation("host");
  const queryClient = useQueryClient();

  const { id, reservationId } = useRouteParams(appPaths.incidentClaim) as {
    id: string;
    reservationId: string;
  };

  const {
    data: reservation,
    isLoading: isReservationLoading,
    isError: isReservationError,
  } = useReservation(reservationId);

  // D14: page 1, limit 100, `createdAt desc`. An apartment with more than 100 claims
  // could hide an older one — recorded as a PR deviation.
  const {
    data: incidentsPage,
    isLoading: isListLoading,
    isError: isListError,
  } = useIncidents({ apartmentId: id });

  const listed = findIncidentForReservation<IncidentWithItems>(
    incidentsPage?.data ?? [],
    reservationId,
  );

  const { data: detail } = useIncident(listed?.id);

  const claim = detail ?? listed ?? null;

  const createMutation = useMutation({
    mutationFn: () => createIncident(reservationId),
    onSuccess: (created) => {
      if (created) {
        // Seed the detail key so the page does not flash its "no claim" state on the
        // way back from the create call.
        queryClient.setQueryData(incidentQueryKey(created.id), created);
      }

      queryClient.invalidateQueries({
        queryKey: incidentsQueryKey({ apartmentId: id }),
      });

      toast.success(t("incidentPage.toasts.created"));
    },
    // D33: the backend's own sentence, not a `code` switch.
    onError: (error: any) => {
      toast.error(error?.error?.message || t("incidentPage.toasts.createError"));
    },
  });

  if (isReservationLoading || isListLoading) {
    return (
      <PageLayout size="lg">
        <PageTitle title={t("incidentPage.title")} />
        <div className="flex items-center gap-2 text-sm text-gray-500 dark:text-gray-400">
          <div className="h-5 w-5 animate-spin rounded-full border-2 border-gray-900 border-t-transparent dark:border-gray-100" />
          {t("incidentPage.loading")}
        </div>
      </PageLayout>
    );
  }

  // One branch for "no reservation": an unknown id and one this host cannot read are the
  // same thing to a host — a link that does not work.
  if (isReservationError || !reservation) {
    return (
      <PageLayout size="lg">
        <PageTitle
          title={t("incidentPage.notFound.title")}
          subtitle={t("incidentPage.notFound.subtitle")}
        />
      </PageLayout>
    );
  }

  const editable = claim !== null && isIncidentEditable(claim);
  const claimedAssetIds = claim?.items.map((item) => item.assetId) ?? [];

  return (
    <PageLayout size="lg">
      <div className="space-y-6">
        <BackLink
          to={appPaths.hostReservation}
          params={{ id, reservationId }}
          label={t("incidentPage.backToReservation")}
        />

        <PageTitle
          title={t("incidentPage.title")}
          subtitle={reservation.guestName}
        />

        {isListError && !claim && (
          <SectionCard title={t("incidentPage.title")}>
            <p className="text-sm text-rose-500 dark:text-rose-400">
              {t("incidentPage.listError")}
            </p>
          </SectionCard>
        )}

        {!isListError && !claim && (
          <SectionCard title={t("incidentPage.empty.title")}>
            <div className="flex items-start gap-3">
              <FileWarning className="mt-0.5 h-5 w-5 shrink-0 text-gray-400" />
              <p className="text-sm text-gray-500 dark:text-gray-400">
                {t("incidentPage.empty.body")}
              </p>
            </div>

            {/* The backend enforces one incident per reservation, so this state means
                CREATE, not choose. A second attempt is refused with
                INCIDENT_ALREADY_EXISTS, and the toast carries that sentence. */}
            <div className="mt-4">
              <ActionButton
                variant="primary"
                size="md"
                icon={<Plus className="h-4 w-4 shrink-0" />}
                label={t("incidentPage.empty.create")}
                loading={createMutation.isPending}
                onClick={() => createMutation.mutate()}
              />
            </div>
          </SectionCard>
        )}

        {claim && (
          <>
            <SectionCard
              title={t("incidentPage.items.title")}
              action={
                <StatusChip
                  tone={claimStatusCopy(claim.status).tone}
                  label={t(claimStatusCopy(claim.status).labelKey)}
                />
              }
            >
              <IncidentItemList items={claim.items} />
            </SectionCard>

            {/* The add form is offered only while the claim is editable (phase 1's
                `isIncidentEditable`) — past filing the backend refuses an item write, so
                showing the form would be showing an action that cannot succeed. */}
            {editable && (
              <SectionCard title={t("incidentPage.addItem.title")}>
                <AddIncidentItemForm
                  apartmentId={id}
                  incidentId={claim.id}
                  claimedAssetIds={claimedAssetIds}
                />
              </SectionCard>
            )}
          </>
        )}
      </div>
    </PageLayout>
  );
}
```
