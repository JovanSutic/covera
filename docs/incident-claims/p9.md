# Phase 9 — The cleaner's portal

**Prerequisite:** phase 4 (the route, the `hex32` param and the page stub) and phase 7 (the host can
mint the link this portal is the far end of)
**Gate:** `npm run gate`

A cleaner opens a link with no account, sees what to photograph, shoots each required view, and gets a
screen that tells them it is safe to lock up and leave. Nothing in this phase authenticates.

Six things to know before starting:

1. **Invariant 10 is the phase.** Nothing here calls `withAuth()` or `publicApi()` — the 32-hex token
   in the URL **is** the credential (D4/D12). `queries/fieldIngest.ts` (phase 3) already carries that
   exception for the read; this phase adds it for the two writes. An `Authorization: Bearer undefined`
   header would fail the request in a way nothing on this screen could explain.
2. **The required views come from the server, not from phase 1's helper.** `FieldIngest.
   requiredEvidenceTypes` is the backend's own answer (D21). Phase 1's `requiredPhotoTypes` is keyed
   off `IncidentItem["type"]` and exists for the *host* surface, which has no such field. Do not
   import it here — it would be a second copy of the rule on the one page that already has the rule
   from the source.
3. **`requiredEvidenceTypes` is `Array<string>`, but `FieldSubmitPhoto.evidenceType` is a
   three-value union.** `FieldIngest.requiredEvidenceTypes` is `Array<string>` and this portal can
   produce exactly the three photo types — documents have no capture path here. The narrowing is
   load-bearing in one direction: a string this portal cannot shoot must not be *counted as
   required*, or the submit would be disabled forever (the same soft-lock D49 records for the
   add-item form).

   It has to be a **type predicate**, not a cast. `EvidenceType` (phase 1's union) is seven values
   including the four document types, and `isPhotoEvidence` returns a plain `boolean` — it narrows
   nothing, so it cannot be reused here. A cast would assert the shape and silently skip the
   filtering; the predicate is the filter. Step 9.1 derives it from `FieldSubmitPhoto["evidenceType"]`
   so a backend type added to that union breaks the compile rather than going uncapturable.

   And it deliberately does **not** import phase 1's `requiredPhotoTypes`. That helper is keyed off
   `IncidentItem["type"]` and exists for the host surface, which has no server-supplied list; this
   page already has the authoritative list, and a second copy of the rule on the one page that does
   not need it is how the two drift.
4. **`FieldBaselinePhoto.downloadUrl` is already a signed URL.** It is used **as-is**. The host
   panel's `${R2_IMAGE_URL}/${storageKey}` pattern is the *other* surface — applying it here would
   prefix a signed URL with an image origin and produce a 404 that looks like a missing photo.
5. **The field upload body is `{ photos: [...] }`, not `{ files: [...] }`** — the host's
   `EvidenceUploadTokensBody` uses `files` and this one does not. Verified in `types.gen.ts`.
6. **`MAX_EVIDENCE_PER_ITEM` (20) stays server-owned.** D55: the client shows the counts the server
   sent and does not re-implement the ceiling. A client-side cap would be a second copy of a backend
   constant with no test to keep them equal, and the failure it prevents — a `400` with the backend's
   own sentence on screen (D33) — is already handled.

### Step 9.1 — Create the anonymous field writer

**Touch.** `src/lib/api/fieldIncident.ts` (create)

**Do.** D13: a flat write module in `src/lib/api/`, beside `submitPhotoProofs.ts`. Two generated
calls and one unauthenticated `PUT`, in the same order and for the same reason as the host's
`uploadIncidentEvidence` (phase 7).

```ts
import {
  postFieldIngestByTokenSubmit,
  postFieldIngestByTokenUploadTokens,
} from "@/api/generated/requests/sdk.gen";
import type {
  FieldSubmitPhoto,
  FieldSubmitResponse,
} from "@/api/generated/requests/types.gen";

/**
 * Invariant 10 / D12: this module NEVER imports `withAuth` or `publicApi`. The 32-hex
 * token in the path is the credential, and the caller it serves has no session at all —
 * `withAuth()` would read `undefined` from Supabase and send
 * `Authorization: Bearer undefined`, turning a working request into a 401 that nothing
 * on the field screen could explain. `queries/fieldIngest.ts` carries the same exception
 * for the read, and `queries/inspection.ts` set the precedent.
 *
 * `throwOnError: true` IS passed, and it is a deliberate difference from the read. The
 * read's failure is an expected answer — a rejected token is one of the three cases the
 * "link unusable" screen exists for (D23), so it must not throw. A WRITE's failure is
 * never expected, and `throwOnError` is what puts the backend's own sentence into
 * `error.error.message` where the page's toast reads it (D33), instead of leaving the
 * caller to unpack a `{ data, error }` union it would then have to guess about.
 */
export type FieldPhotoType = FieldSubmitPhoto["evidenceType"];

/**
 * Every evidence type this portal can produce — which is to say, every evidence type
 * there is, as far as a photo upload is concerned: the three photo views, because a
 * cleaner on a phone is not sending a police report or a retail quote.
 *
 * It is spelled out rather than derived from `isPhotoEvidence` (phase 1) for a reason that
 * costs a compile error to ignore: `FieldIngest.requiredEvidenceTypes` is `Array<string>`,
 * an ordinary runtime array with no union to narrow, so a list is needed somewhere. This is
 * the smallest place to put it, and it is the generated union — a backend type added to
 * `FieldSubmitPhoto` breaks the compile right here instead of going uncapturable.
 */
const SUBMITTABLE_PHOTO_TYPES: readonly FieldPhotoType[] = [
  "damage_photo_wide",
  "damage_photo_closeup",
  "theft_empty_space_photo",
];

/**
 * `FieldIngest.requiredEvidenceTypes` is `Array<string>` — the backend's own list, which
 * it validates submissions against. This narrows it to the three this portal can
 * actually produce.
 *
 * It is a predicate rather than a cast (D54): a cast would assert the shape and skip the
 * filtering entirely. The server's array may hold a document type, and an unrecognised
 * value must never be treated as REQUIRED. The submit gate below requires a capture for
 * every required type, so a type that can never be captured would disable the button for
 * good — a soft-lock the gate cannot see, which is exactly the failure D49 records for
 * the add-item form.
 */
export function isFieldPhotoType(type: string): type is FieldPhotoType {
  return (SUBMITTABLE_PHOTO_TYPES as readonly string[]).includes(type);
}

/** The server's list, filtered to what this portal can shoot, in the order it sent them. */
export function requiredFieldViews(
  requiredEvidenceTypes: readonly string[],
): FieldPhotoType[] {
  return requiredEvidenceTypes.filter(isFieldPhotoType);
}

export interface FieldUpload {
  evidenceType: FieldPhotoType;
  file: File;
}
/**
 * The device's own timestamp for the file, not `Date.now()` at upload time: the phone
 * knows when the photo was taken, and an upload-time stamp would silently claim a photo
 * shot yesterday was shot now. `0` means the platform did not supply one, and the field
 * is then omitted rather than sent as the epoch.
 *
 * Latitude and longitude are deliberately NOT sent (D56). The body accepts them, but
 * reading them needs a `navigator.geolocation` permission prompt on a page a cleaner
 * opens from a link — and a denied prompt is a dead end they cannot recover from, on a
 * page with no settings, no account and nobody to ask. The backend reads EXIF from the
 * uploaded bytes itself, which is where the host panel's `exifLatitude`/`exifLongitude`
 * come from, so the coordinates are not lost by omitting them.
 */
function capturedAtOf(file: File): string | undefined {
  return file.lastModified > 0 ? new Date(file.lastModified).toISOString() : undefined;
}

/**
 * Mint presigned URLs, `PUT` the bytes, submit the keys.
 *
 * The `PUT` carries no headers beyond the content type: the URL is presigned, so its
 * query string is the credential. Adding an `Authorization` header to a third-party
 * origin would be both useless and a leak of a session token this caller does not have.
 */
export async function submitFieldPhotos(
  token: string,
  uploads: readonly FieldUpload[],
): Promise<FieldSubmitResponse> {
  if (uploads.length === 0) throw new Error("No photos to submit.");

  const tokensResponse = await postFieldIngestByTokenUploadTokens({
    path: { token },
    // `photos`, NOT `files` — the host's `EvidenceUploadTokensBody` uses the other
    // word, and this body is verified in `types.gen.ts`.
    body: {
      photos: uploads.map((upload) => ({
        fileType: upload.file.type || "image/jpeg",
      })),
    },
    throwOnError: true,
  });

  const targets = tokensResponse.data?.tokens ?? [];

  const photos: FieldSubmitPhoto[] = await Promise.all(
    uploads.map(async (upload, index): Promise<FieldSubmitPhoto> => {
      const target = targets[index];

      if (!target?.uploadUrl) {
        throw new Error("Missing presigned URL for the photo upload.");
      }

      const putResponse = await fetch(target.uploadUrl, {
        method: "PUT",
        headers: { "Content-Type": upload.file.type || "image/jpeg" },
        body: upload.file,
      });

      if (!putResponse.ok) {
        throw new Error("Failed to upload the photo.");
      }

      return {
        evidenceType: upload.evidenceType,
        storageKey: target.key,
        capturedAt: capturedAtOf(upload.file),
      };
    }),
  );

  const submitResponse = await postFieldIngestByTokenSubmit({
    path: { token },
    body: { photos },
    throwOnError: true,
  });

  if (!submitResponse.data) {
    throw new Error("The photos were uploaded but the report was not recorded.");
  }

  return submitResponse.data;
}
```

### Step 9.2 — Create the framing reference

**Touch.** `src/components/field/FieldBaselineReference.tsx` (create)

**Do.** D19: the blueprint's "ghost overlay" as a **dimmed still**, not a viewfinder. The image is

```tsx
import { useTranslation } from "react-i18next";
import { Baseline } from "lucide-react";

import type { FieldBaselinePhoto } from "@/api/generated/requests/types.gen";

interface FieldBaselineReferenceProps {
  /** The previous stay's photos of THIS asset. `[]` when there are none. */
  photos: readonly FieldBaselinePhoto[];
}

/**
 * D19: the framing reference — the previous stay's photo of the same asset, dimmed, so a
 * cleaner can line the current state up against it. It is a STILL, not a viewfinder: no
 * `getUserMedia`, no `<canvas>`, no MediaStream. The capture path stays the native camera
 * picker every other photo flow in this app uses.
 *
 * `downloadUrl` is already signed by the backend (`getBaselinePhotos` returns five-minute
 * URLs, asset-scoped). It is used AS-IS. Prefixing it with `VITE_R2_IMAGE_URL` — which is
 * what the host panel does with a bare `storageKey` — would produce a URL that 404s, and
 * the page would look like it had simply lost the photo.
 *
 * No heading of its own: the `SectionCard` above it is already titled, and the copy key is
 * NOT repeated here. Renders nothing when there are none — the spec's row 5 names "framing
 * reference absent" as a state, and it is the normal one for a first stay, since there is
 * nothing to compare to.
 */
export function FieldBaselineReference({ photos }: FieldBaselineReferenceProps) {
  const { t } = useTranslation("guest");

  if (photos.length === 0) return null;

  return (
    <div className="space-y-2">
      <div className="flex gap-2 overflow-x-auto">
        {photos.map((photo) => (
          <img
            key={photo.storageKey}
            // Signed and short-lived — never prefixed, never cached past the session.
            src={photo.downloadUrl}
            alt={t("fieldIncident.baseline.alt")}
            // The blueprint's `opacity: 0.4`, as a Tailwind step.
            className="h-28 w-28 shrink-0 rounded-lg border border-gray-200 object-cover opacity-40 dark:border-gray-800"
          />
        ))}
      </div>

      <p className="flex items-start gap-1.5 text-xs text-gray-500 dark:text-gray-400">
        <Baseline className="mt-0.5 h-3.5 w-3.5 shrink-0" />
        {t("fieldIncident.baseline.caption")}
      </p>
    </div>
  );
}
```

### Step 9.3 — Create the capture list

**Touch.** `src/components/field/FieldCaptureList.tsx` (create)

**Do.** One row per required view, each with its own hidden `<input type="file" accept="image/*"
capture="environment">` — `ShotStepPanel`'s mechanism, including the `input.value = ""` reset that
makes a re-shoot fire `change` again.

The row is a **component of its own** (`FieldCaptureRow`) for one reason: the reset above needs a ref
per input, and a ref map keyed by evidence type is more machinery than the problem deserves.

```tsx
import { useRef } from "react";
import type { ChangeEvent } from "react";
import { useTranslation } from "react-i18next";
import { Camera, Check, Trash2 } from "lucide-react";

import { ActionButton } from "@/components/shared/ActionButton";
import type { FieldPhotoType } from "@/lib/api/fieldIncident";

export interface FieldCapture {
  evidenceType: FieldPhotoType;
  file: File;
  /** Built by `URL.createObjectURL` at capture time — `ShotStepPanel`'s rule, and the same one. */
  previewUrl: string;
}

/**
 * The label for each capturable view, as an i18n key — total over the generated union,
 * so a type the backend adds is a compile error here rather than a raw key on screen.
 *
 * These keys live in the `guest` namespace, NOT `incidentPage.evidence.*`. Phase 1's
 * `evidenceLabelKey` returns host-namespace keys for the HOST item row; this page renders
 * no host copy, and reusing that helper would put `host.json` strings on a public,
 * signed-out page (D28).
 */
const VIEW_LABEL_KEYS: Record<FieldPhotoType, string> = {
  damage_photo_wide: "fieldIncident.views.damagePhotoWide",
  damage_photo_closeup: "fieldIncident.views.damagePhotoCloseup",
  theft_empty_space_photo: "fieldIncident.views.theftEmptySpacePhoto",
};

interface FieldCaptureRowProps {
  evidenceType: FieldPhotoType;
  /** How many of this view the server says are ALREADY attached to the item. */
  attachedCount: number;
  captured?: FieldCapture | undefined;
  disabled: boolean;
  onCapture: (capture: FieldCapture) => void;
  onRemove: (evidenceType: FieldPhotoType) => void;
}

function FieldCaptureRow({
  evidenceType,
  attachedCount,
  captured,
  disabled,
  onCapture,
  onRemove,
}: FieldCaptureRowProps) {
  const { t } = useTranslation("guest");
  const inputRef = useRef<HTMLInputElement>(null);

  const handleFileChange = (event: ChangeEvent<HTMLInputElement>) => {
    const file = event.target.files?.[0];
    if (!file) return;

    onCapture({
      evidenceType,
      file,
      // The object URL is built once, at capture time, and handed up with the file —
      // nothing below re-derives it, so the preview cannot disagree with what will be
      // uploaded.
      previewUrl: URL.createObjectURL(file),
    });

    // Clear the input so choosing the SAME file again still fires `change` — which is
    // what makes "Replace" take a second photo rather than silently doing nothing.
    if (inputRef.current) {
      inputRef.current.value = "";
    }
  };

  return (
    <li className="rounded-xl border border-gray-200 p-3 dark:border-gray-800">
      <div className="flex flex-wrap items-center justify-between gap-2">
        <span className="text-sm font-medium text-gray-900 dark:text-gray-100">
          {t(VIEW_LABEL_KEYS[evidenceType])}
        </span>

        {attachedCount > 0 && (
          <span className="text-xs text-gray-500 dark:text-gray-400">
            {t("fieldIncident.views.alreadyProvided")}
          </span>
        )}
      </div>

      {captured ? (
        <div className="mt-3 flex items-center gap-3">
          <img
            src={captured.previewUrl}
            alt={t(VIEW_LABEL_KEYS[evidenceType])}
            className="h-20 w-20 shrink-0 rounded-lg border border-gray-200 object-cover dark:border-gray-800"
          />

          <span className="inline-flex items-center gap-1.5 text-xs font-medium text-emerald-600 dark:text-emerald-400">
            <Check className="h-3.5 w-3.5 shrink-0" />
            {t("fieldIncident.views.captured")}
          </span>

          <div className="ml-auto flex items-center gap-2">
            <label className="inline-flex cursor-pointer items-center gap-2 rounded-lg border border-gray-300 px-2.5 py-1.5 text-xs font-medium text-gray-700 dark:border-gray-700 dark:text-gray-300">
              <Camera className="h-3.5 w-3.5 shrink-0" />
              {t("fieldIncident.views.retake")}
              <input
                ref={inputRef}
                type="file"
                accept="image/*"
                capture="environment"
                onChange={handleFileChange}
                disabled={disabled}
                className="hidden"
              />
            </label>

            <ActionButton
              variant="danger"
              size="sm"
              icon={<Trash2 className="h-3.5 w-3.5 shrink-0" />}
              label={t("fieldIncident.views.remove")}
              disabled={disabled}
              onClick={() => onRemove(evidenceType)}
            />
          </div>
        </div>
      ) : (
        <label className="mt-3 inline-flex cursor-pointer items-center gap-2 rounded-lg border border-gray-300 px-3 py-2 text-sm font-medium text-gray-700 dark:border-gray-700 dark:text-gray-300">
          <Camera className="h-4 w-4 shrink-0" />
          {t("fieldIncident.views.capture")}
          <input
            ref={inputRef}
            type="file"
            accept="image/*"
            capture="environment"
            onChange={handleFileChange}
            disabled={disabled}
            className="hidden"
          />
        </label>
      )}
    </li>
  );
}

interface FieldCaptureListProps {
  /** The narrowed required views (step 9.1's `requiredFieldViews`), in the server's order. */
  requiredTypes: readonly FieldPhotoType[];
  /** `FieldIngest.attachedEvidenceCounts` — how many of each view are already on the item. */
  attachedCounts: Record<string, number>;
  captures: readonly FieldCapture[];
  disabled?: boolean;
  onCapture: (capture: FieldCapture) => void;
  onRemove: (evidenceType: FieldPhotoType) => void;
}

/**
 * One row per view the server says this item needs. The list renders what it is given and
 * derives nothing: which types are required, and which are already partly covered, are
 * both the server's answers.
 */
export function FieldCaptureList({
  requiredTypes,
  attachedCounts,
  captures,
  disabled = false,
  onCapture,
  onRemove,
}: FieldCaptureListProps) {
  return (
    <ul className="space-y-3">
      {requiredTypes.map((evidenceType) => (
        <FieldCaptureRow
          key={evidenceType}
          evidenceType={evidenceType}
          attachedCount={attachedCounts[evidenceType] ?? 0}
          captured={captures.find((capture) => capture.evidenceType === evidenceType)}
          disabled={disabled}
          onCapture={onCapture}
          onRemove={onRemove}
        />
      ))}
    </ul>
  );
}
```

Invariant 7 says a mutation invalidates what it changed — and the honest answer here is that it
changed nothing this client caches: the route's `fieldIngest` entry is the only cache entry on this
page, and re-fetching it after a submit returns `404 FIELD_TOKEN_INVALID` by design, because the
`PUT`-then-submit sequence burns the token. Invalidating it would flip a successful screen into the
unusable-link screen. D22 is why the post-submit state is local.

```tsx
import { appPaths, useRouteParams } from "@/lib/router";

/**
 * The cleaner's portal — the spec's row 5, rendered OUTSIDE the app shell (D4), with no
 * navigation, no header and no account.
 *
 * The route declares `params: { token: "hex32" }`, so a malformed token never reaches
 * this page: `useRouteParams` throws and the router's own 404 renders instead. That is a
 * DIFFERENT screen from the one below on purpose (D23) — "this URL is not a field link"
 * and "this field link cannot be used" are different things to a cleaner, and the router
 * can only tell the first.
 *
 * D23 again, for the three cases the router cannot distinguish: the backend answers
 * `404 FIELD_TOKEN_INVALID` for an unknown token, an expired one and an already-used one
 * alike, so this page has ONE unusable branch for all three. It does not try to be more
 * informative than the API is.
 */
export default function FieldIncidentPage() {
  const { t } = useTranslation("guest");
  const { token } = useRouteParams(appPaths.fieldIncident) as { token: string };

  const { data: ingest, isLoading, isError } = useFieldIngest(token);

  const [captures, setCaptures] = useState<FieldCapture[]>([]);
  // D22: the post-submit state is LOCAL. The token is spent the moment the submit lands,
  // so navigating or re-reading would show the cleaner a failure screen at the one moment
  // their work is actually safe.
  const [result, setResult] = useState<FieldSubmitResponse | null>(null);

  const submitMutation = useMutation({
    mutationFn: () =>
      submitFieldPhotos(
        token,
        captures.map((capture) => ({
          evidenceType: capture.evidenceType,
          file: capture.file,
        })),
      ),
    // No `invalidateQueries` here, and that is the point — see the note above.
    onSuccess: (response) => setResult(response),
    // D33: the backend's own sentence. No `error.code` switch — `StandardError.error.code`
    // is a plain `string` and there is no union to switch on.
    onError: (error: any) => {
      toast.error(error?.error?.message || t("fieldIncident.submitError"));
    },
  });

  const requiredTypes = ingest ? requiredFieldViews(ingest.requiredEvidenceTypes) : [];
  const isComplete = requiredTypes.every((type) =>
    captures.some((capture) => capture.evidenceType === type),
  );

  const addCapture = (capture: FieldCapture) => {
    // One slot per view: a re-shoot REPLACES the previous shot rather than queueing a
    // second upload of the same type, which is what the cleaner means by "Replace".
    setCaptures((previous) => [
      ...previous.filter((entry) => entry.evidenceType !== capture.evidenceType),
      capture,
    ]);
  };

  const removeCapture = (evidenceType: FieldCapture["evidenceType"]) => {
    setCaptures((previous) =>
      previous.filter((entry) => entry.evidenceType !== evidenceType),
    );
  };

  if (isLoading) {
    return (
      <PageLayout size="sm">
        <PageTitle title={t("fieldIncident.loading")} />
      </PageLayout>
    );
  }

  // One branch for all three causes (D23). `!ingest` covers the case the query resolved
  // with no data, which is what the anonymous read returns for a rejected token.
  if (isError || !ingest) {
    return (
      <PageLayout size="sm">
        <PageTitle
          title={t("fieldIncident.unusable.title")}
          subtitle={t("fieldIncident.unusable.body")}
        />
      </PageLayout>
    );
  }

  // D22 and the blueprint's "Validation Block Screen": the cleaner is told their work is
  // safe, that they may leave, and nothing else. No navigation, no retry, no new link.
  if (result) {
    return (
      <PageLayout size="sm">
        <SectionCard title={t("fieldIncident.done.title")}>
          <div className="flex items-start gap-3">
            <CheckCircle2 className="mt-0.5 h-5 w-5 shrink-0 text-emerald-500" />
            <div className="space-y-1">
              <p className="text-sm text-gray-900 dark:text-gray-100">
                {t("fieldIncident.done.body")}
              </p>
              <p className="text-xs text-gray-500 dark:text-gray-400">
                {t("fieldIncident.done.evidenceCount", {
                  count: result.evidenceCount,
                })}
              </p>
            </div>
          </div>
        </SectionCard>
      </PageLayout>
    );
  }

  return (
    <PageLayout size="sm">
      <div className="space-y-4">
        <header className="space-y-1">
          <p className="text-xs font-semibold uppercase tracking-wider text-gray-400">
            {ingest.apartmentName}
          </p>
          <h1 className="text-xl font-semibold text-gray-900 dark:text-gray-100">
            {ingest.asset.name}
          </h1>
          <p className="text-sm text-gray-500 dark:text-gray-400">
            {/* `roomLocations` lives in the `assets` namespace, not `guest` — this `t` is
                bound to `guest`, so an unqualified key would render the raw key string.
                `defaultValue` keeps a location the catalogue has not translated readable
                rather than blank. */}
            {t(`assets:roomLocations.${ingest.asset.roomLocation}`, {
              defaultValue: ingest.asset.roomLocation,
            })}
          </p>
        </header>

        {ingest.asset.description && (
          <p className="text-sm text-gray-500 dark:text-gray-400">
            {ingest.asset.description}
          </p>
        )}

        <SectionCard title={t("fieldIncident.baseline.title")}>
          {/* D19. Renders nothing at all when the backend sent no baseline — the spec's
              "framing reference absent" state is a real state, not an error. */}
          <FieldBaselineReference photos={ingest.baselinePhotos} />
          {ingest.baselinePhotos.length === 0 && (
            <p className="text-sm text-gray-500 dark:text-gray-400">
              {t("fieldIncident.baseline.none")}
            </p>
          )}
        </SectionCard>

        <SectionCard title={t("fieldIncident.views.title")}>
          <FieldCaptureList
            requiredTypes={requiredTypes}
            attachedCounts={ingest.attachedEvidenceCounts}
            captures={captures}
            disabled={submitMutation.isPending}
            onCapture={addCapture}
            onRemove={removeCapture}
          />

          {requiredTypes.length === 0 && (
            <p className="mt-3 text-sm text-gray-500 dark:text-gray-400">
              {t("fieldIncident.views.noneRequired")}
            </p>
          )}

          {/* The gate is "every view the server asked for has been shot". It is written
              over `requiredTypes` — the NARROWED list — and not over the server's raw
              array: gating on a string this portal can never produce would disable the
              button permanently (step 9.1). */}
          {!isComplete && requiredTypes.length > 0 && (
            <p className="mt-4 flex items-start gap-2 text-xs text-amber-600 dark:text-amber-400">
              <AlertTriangle className="mt-0.5 h-3.5 w-3.5 shrink-0" />
              {t("fieldIncident.views.missing")}
            </p>
          )}

          <div className="mt-4">
            <ActionButton
              variant="primary"
              size="md"
              icon={<Send className="h-4 w-4 shrink-0" />}
              label={
                submitMutation.isPending
                  ? t("fieldIncident.submitting")
                  : t("fieldIncident.submit")
              }
              loading={submitMutation.isPending}
              disabled={!isComplete || captures.length === 0}
              onClick={() => submitMutation.mutate()}
            />
          </div>
        </SectionCard>
      </div>
    </PageLayout>
  );
}
```
