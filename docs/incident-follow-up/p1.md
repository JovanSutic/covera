## Step 1.1 — Extract the overlay

**Touch:** `src/components/shared/ImageZoomOverlay.tsx` (new)

**Do:** create the file with exactly this content:

```tsx
import { X } from "lucide-react";
import { useTranslation } from "react-i18next";

interface ImageZoomOverlayProps {
  src: string;
  alt: string;
  onClose: () => void;
}

/**
 * The fullscreen photo viewer, lifted verbatim out of `ExpandableImage` so the incident
 * thumbnails and the guide images open the same overlay (D5). It owns no open state: the
 * caller decides when it is mounted, because each surface triggers it differently — a
 * boolean there, the photo's own key here.
 */
export function ImageZoomOverlay({ src, alt, onClose }: ImageZoomOverlayProps) {
  const { t } = useTranslation("general");

  return (
    <div
      className="fixed inset-0 z-50 flex items-center justify-center bg-black/90 p-4 backdrop-blur-xs animate-in fade-in duration-200"
      onClick={onClose}
    >
      <button
        type="button"
        aria-label={t("common.closeZoom")}
        className="absolute top-4 right-4 z-10 rounded-full bg-white/10 p-2 text-white hover:bg-white/20 transition-colors cursor-pointer"
        onClick={onClose}
      >
        <X className="h-6 w-6" />
      </button>
      <img
        src={src}
        alt={alt}
        className="max-h-[90vh] max-w-[90vw] rounded-xl object-contain shadow-2xl"
      />
    </div>
  );
}
```

The markup, classes and `common.closeZoom` key are copied from `ExpendableImage.tsx`'s existing modal.
Do not restyle it: the guide pages already look like this.

**Accept:** the file exists; `npx tsc -b --noEmit` reports no error naming `ImageZoomOverlay`.

**Verify:** `npx tsc -b`

## Step 1.4 — Test the trigger

**Touch:** `src/components/host/incident/IncidentItemEvidence.test.tsx`

**Do:** add a `describe("zooming a photo", …)` block with these four cases, using the existing
`renderPanel`/`item`/`photo` helpers. Under the test-setup mock, `t(key) => key`, so every accessible
name is its key string.

1. **opens** — render `item({ evidence: [photo("damage_photo_wide")] })`, click
   `screen.getByRole("button", { name: "incidentPage.evidence.zoom" })`, then assert
   `screen.getAllByRole("img")).toHaveLength(2)` (thumbnail + overlay) and
   `screen.getByRole("button", { name: "common.closeZoom" })` is present.
2. **closes** — from the open state, click `common.closeZoom`; assert `getAllByRole("img")` is length 1
   and `queryByRole("button", { name: "common.closeZoom" })` is null.
3. **the delete control does not open it** — render an active photo, click
   `getByRole("button", { name: "incidentPage.evidence.remove" })`, and assert
   `screen.queryByRole("button", { name: "common.closeZoom" })` is null. The write itself is already
   covered by the existing "removes a photo through the delete write" case.
4. **the overlay is not rendered until asked** — render an item with no photos and assert
   `screen.queryByRole("button", { name: "common.closeZoom" })` is null.

Do not touch the existing cases. The delete-button assertions in them stay valid because the zoom
button has a different accessible name.
