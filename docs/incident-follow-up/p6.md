# Phase 6 — Language follows the link

Prerequisite: phase 5 (the guide route is the one new path this phase has to carry; the claim-section
test this phase extends was wrapped in `AccessProvider` there).
Gate: `npm run gate`.

Issue 7. Every internal navigation carries `lang=<current>`, and the Header stops resetting the UI to
English when the parameter is absent.

**Deliberately NOT wrapped with `withLang`** — these URLs are written for someone else to open, not for
the host to navigate to: `IncidentFieldLink.tsx` (the cleaner's token URL) and `ReservationPage.tsx`'s
`guestInspectionUrl` / `useReservationActions.ts`'s `guestInspectionUrl` (the guest's inspection link,
pasted into a message). Adding `lang` there would change text the host sends to a third party.

## Step 6.1 — `withLang`

**Touch:** `src/lib/router/lang.ts` (new), `src/lib/router/lang.test.ts` (new)

**Do:** create `lang.ts` with exactly this content:

```ts
/**
 * D24: the language travels with the link.
 *
 * The Header keeps the language in `<lang>` on the query string and `i18n` keeps it in
 * localStorage, but neither follows a `<Link>`: a link replaces the whole search string,
 * so the next page starts without it. Every href this app builds for its own navigation
 * goes through here.
 *
 * `en` is omitted, matching the Header's rule for the default language: a clean URL is
 * the default, and `?lang=en` would be a second way of saying nothing. An unsupported
 * code is ignored rather than written into the URL.
 */
export const SUPPORTED_LANGS = ["en", "de", "tr", "sr-Latn"] as const;

export type AppLang = (typeof SUPPORTED_LANGS)[number];

export function withLang(path: string, lang: string): string {
  if (lang === "en" || !SUPPORTED_LANGS.includes(lang as AppLang)) return path;

  const hashIndex = path.indexOf("#");
  const hash = hashIndex === -1 ? "" : path.slice(hashIndex);
  const withoutHash = hashIndex === -1 ? path : path.slice(0, hashIndex);

  const queryIndex = withoutHash.indexOf("?");
  const base = queryIndex === -1 ? withoutHash : withoutHash.slice(0, queryIndex);
  const search = queryIndex === -1 ? "" : withoutHash.slice(queryIndex + 1);

  const params = new URLSearchParams(search);
  params.set("lang", lang);

  return `${base}?${params.toString()}${hash}`;
}
```

Create `lang.test.ts` with six cases:

| call | expected |
| --- | --- |
| `withLang("/host/dashboard", "en")` | `"/host/dashboard"` |
| `withLang("/host/dashboard", "de")` | `"/host/dashboard?lang=de"` |
| `withLang("/host/dashboard", "sr-Latn")` | `"/host/dashboard?lang=sr-Latn"` |
| `withLang("/listing?page=3", "tr")` | `"/listing?page=3&lang=tr"` |
| `withLang("/host/dashboard#claims", "de")` | `"/host/dashboard?lang=de#claims"` |
| `withLang("/host/dashboard", "fr")` | `"/host/dashboard"` |

**Accept:** `npx vitest run src/lib/router/lang.test.ts` → 6 passing.

**Verify:** `npm run gate`

## Step 6.3 — The Header stops forcing English

**Touch:** `src/components/Header.tsx`

**Do:**
1. Add `import { SUPPORTED_LANGS } from "@/lib/router/lang";` beside the router import, and delete the
   `const SUPPORTED_LANG_CODES = LANGUAGES.map((l) => l.code);` line — `LANGUAGES` itself stays, because
   the select needs the labels.
2. Replace the two lines that compute `currentLang` with:

```tsx
  // D25: the parameter wins, and `i18n.language` is the fallback — not "en". The previous
  // fallback meant a reload without `?lang` silently dropped the host back to English,
  // which is the second half of issue 7. `SUPPORTED_LANGS` is the same list `withLang`
  // uses, so the Header and the links cannot disagree about what is a language.
  const fallbackLang = SUPPORTED_LANGS.includes(i18n.language as (typeof SUPPORTED_LANGS)[number])
    ? i18n.language
    : "en";
  const currentLang =
    urlLang && SUPPORTED_LANGS.includes(urlLang as (typeof SUPPORTED_LANGS)[number])
      ? urlLang
      : fallbackLang;
```

3. Wrap both `buildPath(appPaths.login)` calls (the logout handler and the signed-out menu item) with
   `withLang(…, i18n.language)` and add `withLang` to the router import. They are `navigate` targets,
   not links, so `AccessLink` does not cover them.

**Accept:** `grep -n "SUPPORTED_LANG_CODES" src/components/Header.tsx` → no match.
`grep -c "withLang(" src/components/Header.tsx` → `2`.

**Verify:** `npm run gate`
