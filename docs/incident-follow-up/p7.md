# Phase 7 — The claim waits for check-out

Prerequisite: phases 5 and 6 (this phase edits the two components phase 5 added the guide link to, and
extends the test phase 6 last touched).
Gate: `npm run gate`.

Issue 10. The claim section is visible for the whole stay, but a claim must not be openable before the
stay has ended. Both CTAs ("Start a claim" on the reservation page, "Open a claim" on the claim page) are
disabled until the effective check-out passes, with a line saying why.

D20: client-side only. The backend has no lower bound — recorded in `blocked.md`, not fixed here.

## Step 7.1 — `canOpenClaimAt`

**Touch:** `src/lib/helpers/claimDeadline.ts`, `src/lib/helpers/claimDeadline.test.ts`

**Do:** append to `claimDeadline.ts`:

```ts
/**
 * D20/D21: may a claim be opened at `now`?
 *
 * The backend enforces the UPPER bounds — 14 days after the effective check-out, and not
 * after the next guest's check-in — but it has no lower bound, so a claim can be opened
 * mid-stay today. Issue 10 asks for the missing half.
 *
 * The alternative check-out wins when it parses: it is the date the host edited the stay
 * to, and the backend's own `effectiveCheckOut` prefers it
 * (`incidents.service.ts`), so this rule and the server's 14-day window must read the
 * same instant.
 *
 * An unparseable check-out reads as "no gate" rather than "never" — a corrupt date must
 * not lock the host out of a claim they are entitled to file.
 */
export function canOpenClaimAt(
  checkOutDatetime: string | null,
  alternativeCheckOutDatetime: string | null,
  now: number,
): boolean {
  const checkOut = toEpoch(alternativeCheckOutDatetime) ?? toEpoch(checkOutDatetime);

  if (checkOut === null) return true;

  return now >= checkOut;
}
```

Add to `claimDeadline.test.ts` a `describe("canOpenClaimAt", …)` with five cases:
1. `now` before the check-out → `false`;
2. `now` exactly at the check-out instant → `true`;
3. `now` after it → `true`;
4. a real `alternativeCheckOutDatetime` later than `checkOutDatetime`, `now` between the two → `false`
   (the alternative wins);
5. a `null` alternative and a garbage `checkOutDatetime` → `true`.

**Accept:** `npx vitest run src/lib/helpers/claimDeadline.test.ts` → passes, five more tests than before.

**Verify:** `npm run gate`
