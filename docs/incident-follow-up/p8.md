# Phase 8 — The incident copy is actually translated

Prerequisite: phases 1–7 (it translates every key they added).
Gate: `npm run gate`.

Issue 6. The root cause is D23: `incidentPage.*` and `reservationPage.incident.*` hold **identical
English values** in `de`, `tr` and `sr-Latn`, so changing the language genuinely cannot change anything.
`scripts/translate-locales.ts` fills only MISSING keys, so the English values have to be removed first —
deleting is what makes the script produce a translation.

## Step 8.1 — Clear the two blocks in the three target locales

**Touch:** `public/locales/de/host.json`, `public/locales/tr/host.json`, `public/locales/sr-Latn/host.json`

**Do:** in each of the three files, delete the entire top-level `"incidentPage": { … }` key, and delete
the `"incident": { … }` key nested under `"reservationPage"`. Delete only those two keys — every sibling
(`reservationPage.title`, the rest of `reservationPage.*`, and every other top-level block) stays.

`en/host.json` is the source of truth and is **not** edited.

**Accept:** `node -e "const j=require('./public/locales/de/host.json');console.log('incidentPage' in j, 'incident' in j.reservationPage)"`
→ `false false`. Repeat for `tr` and `sr-Latn`.

**Verify:** `npm run gate` — expect it to FAIL, with `localeParity` naming missing `de`, `tr` and
`sr-Latn` keys. That failure is this step working; step 8.2 clears it.

## Step 8.2 — Translate

**Touch:** `public/locales/de/host.json`, `public/locales/tr/host.json`, `public/locales/sr-Latn/host.json`

**Do:** run `npm run i18n:translate`.

The script walks `en` and fills only what a target is missing, through Google's free web endpoint, with
`sr-Latn` transliterated from Cyrillic by `scripts/cyrillicToLatin.ts`. It rewrites the three files in
place, and it may reorder keys to match `en` — a large diff is expected, not a mistake.

If it reports keys added OUTSIDE `incidentPage` and `reservationPage.incident`, that is pre-existing
drift, not this plan's work: keep the additions (parity wants them) and say so in the phase report's
`Noticed, untouched:` line.

If it fails, or writes an empty string for a key, halt — do not hand-write a translation.

**Accept:** run this and read the three lines it prints. `identical` must be `0` and `missing` must be
`0` for each locale:

```bash
node -e "const fs=require('fs');const flat=(o,p='')=>Object.entries(o).flatMap(([k,v])=>{const q=p?p+'.'+k:k;return typeof v==='object'&&v!==null?flat(v,q):[[q,v]];});const read=l=>new Map(flat(JSON.parse(fs.readFileSync('public/locales/'+l+'/host.json','utf8')).incidentPage));const en=read('en');for(const l of ['de','tr','sr-Latn']){const m=read(l);const same=[...en].filter(([k,v])=>m.get(k)===v).map(([k])=>k);const missing=[...en.keys()].filter(k=>!m.has(k));console.log(l,'identical:',same.length,'missing:',missing.length);}"
```

**Verify:** `npm run gate`

## Step 8.3 — Confirm the switch works, by reading the files

**Touch:** none.

**Do:** no edit. This step exists because "the page changes language" is a rendered outcome, and the
rendered outcome cannot be a gate command here. The file-level check in 8.2 is the executable proof that
the values differ; this step proves they differ in the places the page actually renders.

Run:

```bash
node -e "const a=require('./public/locales/en/host.json').incidentPage;for(const l of ['de','tr','sr-Latn']){const j=require('./public/locales/'+l+'/host.json');console.log(l, j.incidentPage.title!==a.title, j.incidentPage.message.ask!==a.message.ask, j.reservationPage.incident.title!==a.reservationPage.incident.title);}"
```

**Accept:** all three booleans are `true` on all three lines.

**Verify:** `npm run gate`
