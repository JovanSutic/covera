# Goal and background
During a reservation guest can make some damage or theft, so there needs to be a way host can document this theft or damage. So the goal is to help the host document this and provide the guidance how he can make the request in the Airbnb resolution center. So the whole flow needs to be aligned with the rules of the Airbnb.

# Pages
So this is the first decision that we need to make. What we know for sure is that we need to have a place from the reservation page where host can create the incident. And also we need to have a page similar like inspection page that will be similar to inspection-guide, the point is that this page should be only dedicated to the collecting of the photos of the stolen or damaged assets. So then the decision will be will there be an incident page as well, or everything around the incident will be done through the reservation page. I am leaning more to the separate page for the incident because there is a lot of customer education aspects about the whole process, meaning we need to provide the guidance, where to do what in the Airbnb system.

# The flow
So let's say that guest is checked out, then the cleaner is coming to the apartment it starts to clean and it gets to the assets that is damaged. She calls the host. Host will then create a incident for this reservation and then the collection of proofs for the damage will start. Once incident can have multiple items assign to it, because each incident item is basically an asset that is damaged or stolen. So host needs to create these items, depending on what is damaged or stolen, it needs to label them and then provide the photos that will depict the current damaged state of the asset. Remember this collection of the damage photo proofs can be done by host or a cleaner, so it needs to be on a different page, so we can later grant some cleaner access to that page. But for now we just need to know that this part needs to be on the different page. When the incident is created, incident items also, and photo proofs per items are added, we I think only need to give some invormation about what is the valuation of the damage. That is the first reaction to the damage.
Then we need to provide the guidance to the host how he can use these data and docs to create a real airbnb resolution center request. But this is all explained in the covera\docs\incident_management_frontend_blueprint.md.

# Purpose
The main purpose is to abstract the process of damage and theft claim from the host and give him the process that will make him more confident that everything will be fine, and to close all the gaps where he can drift off the defined Airbnb procedure for these situations.
