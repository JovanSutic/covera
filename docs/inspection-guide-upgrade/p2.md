**Prerequisite:** phase 1 (`DescriptionTooltip` is rebuilt on `TooltipPanel`, which phase 1 creates;
building it first would mean writing the panel twice).
**Gate:** `npm run gate`

### Step 2.1 — extract and generalise `DescriptionTooltip`

**Touch.** `src/components/shared/DescriptionTooltip.tsx` (create)

**Do.** The component is moved out of `AssetItemCard.tsx` and generalised in the same step: the
trigger's `aria-label` was a hardcoded `t("assetCard.tooltips.viewDescription")` call inside the
component, which is what stopped it serving a second call site.

It is built on `TooltipPanel` (D30), so it inherits prep §4's clamping — leaving one of the app's two
tooltip components unclamped would reproduce prep §4's bug on the very page prep §2 is about.

```tsx
import { useRef } from "react";
import { FileText } from "lucide-react";

import { TooltipPanel } from "./TooltipPanel";

interface DescriptionTooltipProps {
  /** The text to show, already translated or already user data. */
  content: string;
  /** The trigger's `aria-label`; it is an icon-only button, so it needs one. */
  label: string;
  className?: string;
}

/**
 * A description behind a text-icon trigger. Extracted from `AssetItemCard` (prep §2) so the
 * inspection guide can use the same affordance for a shot's instructions.
 *
 * D12: it keeps `group-hover` + `group-focus-within` and has no click handler of its own.
 * `group-focus-within` is what makes it work on a touch device — a tap focuses the button once —
 * and a click toggle would need a dismiss affordance, which is `Popover`'s job and collides with
 * the `Modal` layer (see `InfoTooltip`'s own comment).
 *
 * The panel is measured and clamped by `TooltipPanel` (prep §4). Before this phase it was an
 * absolutely-positioned box inside an inline wrapper, which is why it could escape its row.
 */
export function DescriptionTooltip({
  content,
  label,
  className,
}: DescriptionTooltipProps) {
  const triggerRef = useRef<HTMLButtonElement>(null);

  return (
    <div className={`group/tooltip inline-flex shrink-0 ${className ?? ""}`}>
      <button
        ref={triggerRef}
        type="button"
        aria-label={label}
        className="cursor-pointer rounded-lg p-1 text-gray-400 transition-colors hover:bg-gray-100/80 hover:text-gray-700 focus-visible:outline-2 focus-visible:outline-offset-1 focus-visible:outline-gray-900 dark:hover:bg-gray-800 dark:hover:text-gray-200 dark:focus-visible:outline-gray-100"
      >
        <FileText className="h-4 w-4" />
      </button>

      <TooltipPanel triggerRef={triggerRef}>{content}</TooltipPanel>
    </div>
  );
}
```

- `grep -n "w-64\|max-w-xs" src/components/shared/DescriptionTooltip.tsx` → **nothing** (D32)
- `npm run gate` → exit 0

### Step 2.3 — the shot instruction becomes a tooltip

**Touch.** `src/components/host/guide/ShotStepPanel.tsx` (edit), `public/locales/{en,de,tr,sr-Latn}/assets.json` (edit)

**Do.**

**1.** In all four locale files, add a new `instructions` object under the existing `shotGuide`
object — it is a new key, so it does not collide with any existing flat key (fact 5):

```json
"instructions": {
  "trigger": "View shot instructions",
  "empty": "No specific instructions for this shot."
}
```

Both strings are the English text in all four files (D41).

**2.** In `ShotStepPanel.tsx`, add the import:

```tsx
import { DescriptionTooltip } from "@/components/shared/DescriptionTooltip";
```

**3.** In the title row, place the trigger beside the title — the same row the shot-type chip is on,
which is the row `AssetItemCard` puts its own trigger on (D8). Wrap the existing `Typography` in a
flex container so the trigger can sit beside the title:

```tsx
          <div className="flex min-w-0 items-center gap-1">
            <Typography
              type="h4"
              className="truncate text-base font-semibold text-gray-900 sm:text-lg dark:text-gray-100"
            >
              {shot.title}
            </Typography>

            {shot.instructions ? (
              <DescriptionTooltip
                content={shot.instructions}
                label={t("shotGuide.instructions.trigger")}
              />
            ) : (
              <span className="text-xs text-gray-500 dark:text-gray-400">
                {t("shotGuide.instructions.empty")}
              </span>
            )}
          </div>
```

**4.** Delete the instruction paragraph that follows the title row — the `<p className="mt-1
whitespace-pre-line …">{shot.instructions}</p>`. The tooltip is now its only rendering (D5).

Adding `truncate` to the title is required, not cosmetic: the title is now inside a flex row with a
shrink-0 sibling, so without it a long title pushes the trigger off the row instead of ellipsing.
`min-w-0` on the wrapper is the other half of that.

**Accept.**
- `grep -n "shot.instructions" src/components/host/guide/ShotStepPanel.tsx` → in the tooltip's `content`, in the ternary's condition, and **nowhere in a `<p>`**
- `grep -n "whitespace-pre-line" src/components/host/guide/ShotStepPanel.tsx` → **nothing** (the paragraph is gone)
- `node -e "for(const l of ['en','de','tr','sr-Latn']){const j=require('./public/locales/'+l+'/assets.json');console.log(l, Object.keys(j.shotGuide.instructions).join(','))}"` → `trigger,empty` for each of the four files
- `npm run gate` → exit 0

**Verify.** `npm run gate`

### Step 2.4 — the panel's tests follow

**Touch.** `src/components/host/guide/ShotStepPanel.test.tsx` (edit)

**Do.** One existing assertion is on markup the operator asked to remove (D42 records this as the
feature's only deleted assertion). Add the replacement plus the trigger's own test.

The harness's camera stub replaces the panel's camera control, so the instruction trigger is the
panel's only remaining `t()`-labelled control that is not a `stub-` button. `test-setup.ts` global-mocks
`react-i18next` so `t()` returns the key — assert on keys.

```tsx
describe("the shot instruction (prep §2)", () => {
  it("shows the instruction behind a trigger, not as a paragraph", async () => {
    const user = userEvent.setup();
    render(<Harness initial={threePending()} />);

    // The trigger is a real button with the label key as its accessible name.
    const trigger = screen.getByRole("button", {
      name: "shotGuide.instructions.trigger",
    });

    expect(trigger).toBeInTheDocument();

    // And the instruction text is NOT loose in the panel. `threePending` gives shot 0 the
    // instructions "Instructions 0", which the tooltip renders — so it is in the document
    // exactly once, inside the trigger's panel, and never as a sibling paragraph.
    trigger.focus();

    expect(screen.getAllByText("Instructions 0")).toHaveLength(1);
  });

  it("shows the empty-state text, and no trigger, when the shot has no instructions", () => {
    const shots = threePending();
    shots[0] = { ...shots[0], instructions: "" };

    render(<Harness initial={shots} />);

    expect(screen.getByText("shotGuide.instructions.empty")).toBeInTheDocument();
    expect(
      screen.queryByRole("button", {
        name: "shotGuide.instructions.trigger",
      }),
    ).not.toBeInTheDocument();
  });
});
```

**Delete** the assertion that the instruction paragraph renders — it is the one D42 names.
