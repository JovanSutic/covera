# Phase 3 — the strip's two rings

**Prerequisite:** none (independent of phase 1 — different files, no shared symbol).
**Gate:** `npm run gate`

Prep §1. The strip's current step gets an emerald ring, and a captured step the host has tapped into
gets a light orange one.

**The whole phase is one predicate and two class strings.** It is a separate phase from phase 4
because phase 4 replaces `stripItems` outright, and a reviewer reading one diff should be able to
attribute each behaviour change to one prep point.

This phase produces the **emerald** half too: `currentRing` already exists at `HEAD`, but the tile
that renders it is rewritten here so that both rings are emitted from the same two variables and the
ordering rule (D2) is visible in one place.

---

### Step 3.1 — the helper decides `isActive`, and the three locale keys exist

**Touch.** `src/lib/helpers/guideFlow.ts` (edit), `public/locales/{en,de,tr,sr-Latn}/assets.json` (edit)

**Do.** This step is deliberately first: `guideFlow.ts` stops compiling the moment `StripItem` gains
a required field, so the field and its producer land together. The locale keys are here rather than
with the markup because the item cannot be rendered without them, and this phase's Accept checks them
all in one place.

**1.** In `guideFlow.ts`, add to the `StripItem` interface, immediately after `isCurrent`:

```ts
  /**
   * Prep §1: the captured step the host has jumped into, while the cursor is elsewhere.
   * Never true on the current item, and never true on more than one item — `isCurrent`
   * wins, and the item renders one ring.
   */
  isActive: boolean;
```

**2.** In `stripItems` (the existing export — this phase does not rename or re-shape it; that is
phase 4's D17), add the field to the returned object, immediately after `isCurrent`:

```ts
    // Prep §1: "the item that was already done and has the photo, and he will be moved to
    // that step ... the step is not somehow highlighted". Active is only ever the current
    // step — the host has not jumped anywhere in this phase, because `viewedIndex` does not
    // exist yet (phase 4). The predicate is written in its final form here so that phase 4
    // changes one expression, not a shape.
    isActive: false,
```

**3.** In all four of `public/locales/{en,de,tr,sr-Latn}/assets.json`, add one key to the existing
`shotGuide.strip` object:

```json

```

The English string goes into all four files verbatim (D41) — the objective is that every locale
carries every key, and a machine-translated string is neither reviewable nor deterministic.

**Accept.**

### Step 3.2 — the item renders the rings

**Touch.** `src/components/host/guide/PhotoStripItem.tsx` (edit)

**Do.** Add the second ring variable below the existing `currentRing`, and apply both to the two
rendered branches.

**1.** Replace the `currentRing` declaration with:

```tsx
  const currentRing = item.isCurrent
    ? "ring-2 ring-emerald-500 ring-offset-1 dark:ring-offset-gray-900"
    : "";
  const activeRing = item.isActive
    ? "ring-2 ring-orange-400 ring-offset-1 dark:ring-offset-gray-900"
    : "";
```

**2.** Replace the component's docstring with (D2 records the ordering rule):

```tsx
/**
 * One item of the transparency list (prep §1). It renders the states the helper already
 * decided, and makes no decision of its own (D25/invariant 10).
 *
 * Prep §1's rings, in the operator's own words: "current step will be green, but this
 * let's called it active step will have a light orange ring. Then this situation will be
 * active an current = green, only active = orange, only current = green, all else no
 * ring." That is exactly the two class strings below — `currentRing` is applied last, so
 * an item that is somehow both renders green.
 *
 * The captured state is a <button>; the pending state is a <div>. That is the whole of
 * "only the photo components with the photo are clickable", and it is why `isActive` can
 * never be true on the pending branch (the helper guarantees it, D1).
 */
```

**3.** Append `${activeRing} ${currentRing}` to the `className` of the pending `<div>`:

```
        className={`flex h-16 w-16 shrink-0 items-center justify-center rounded-lg border border-dashed border-gray-300 bg-gray-50 text-gray-400 dark:border-gray-700 dark:bg-gray-900 ${activeRing} ${currentRing}`}
```

**4.** Append `${activeRing} ${currentRing}` to the `className` of the captured `<button>`:

```
      className={`relative h-16 w-16 shrink-0 cursor-pointer overflow-hidden rounded-lg border border-gray-300 bg-gray-950 transition-transform hover:scale-105 dark:border-gray-700 ${activeRing} ${currentRing}`}
```

**5.** Inside the captured `<button>`, immediately after the existing `{item.isCurrent && (…)}` badge,
add the active badge:

```tsx
      {item.isActive && (
        <span className="absolute inset-x-0 bottom-0 truncate bg-orange-500/90 px-1 text-[9px] font-semibold leading-4 text-white">
          {t("shotGuide.strip.activeItem")}
        </span>
      )}
```

**Accept.**

- `grep -c "activeRing} \${currentRing}" src/components/host/guide/PhotoStripItem.tsx` → `2` (the pending `<div>` and the captured `<button>`)
- `grep -n "group-hover\|onClick" src/components/host/guide/PhotoStripItem.tsx` → the pending branch still has **no** `onClick` (only the captured `<button>` does)

### Step 3.3 — pin the ring states

**Touch.** `src/components/host/guide/PhotoStripItem.test.tsx` (create)

**Do.** This phase's logic is pure (the helper's predicate) and presentational (the class strings), so
the test has two halves in one file: the predicate through `stripItems`, and the four rendered ring
states. The predicate half is what makes this more than a snapshot of Tailwind classes — it is the
half that would have caught D1's original error.

```tsx
import { describe, expect, it, vi } from "vitest";
import { render } from "@testing-library/react";

import { stripItems } from "@/lib/helpers/guideFlow";
import type { CapturedApartmentShot } from "@/lib/api/submitProofs";
import { PhotoStripItem } from "./PhotoStripItem";

function shots(captured: number[]): CapturedApartmentShot[] {
  return [0, 1].map((index) => ({
    id: `shot-${index}`,
    apartmentId: "apartment-1",
    roomLocation: "KITCHEN",
    shotType: "SWEEP_ONLY",
    title: `Shot ${index}`,
    instructions: `Instructions ${index}`,
    assetIds: [],
    createdAt: "2026-09-01T14:00:00.000Z",
    updatedAt: "2026-09-01T14:00:00.000Z",
    ...(captured.includes(index)
      ? { capturedImageUrl: `blob:preview-${index}` }
      : {}),
  }));
}

function renderItem(cursorIndex: number) {
  const [item] = stripItems(shots([0]), cursorIndex);

  return render(<PhotoStripItem item={item} total={2} onSelect={vi.fn()} />).container;
}

describe("PhotoStripItem's rings (prep §1)", () => {
  it("is current and not active — emerald only — when the cursor is on a captured step", () => {
    const container = renderItem(0);

    expect(container.firstElementChild).toHaveClass("ring-emerald-500");
    expect(container.firstElementChild).not.toHaveClass("ring-orange-400");
  });

  it("is active and not current — orange only — when the cursor has moved past a capture", () => {
    // The whole of prep §1: photo 0 is done, the cursor is on photo 1, photo 0 is the
    // one the host is looking at. In this phase `viewedIndex` does not exist yet, so
    // the helper cannot produce this state — phase 4 makes it reachable. The item's
    // rendering is pinned here so phase 4 changes one helper expression and no markup.
    const items = stripItems(shots([0]), 1);
    const activeItem = { ...items[0], isActive: true, isCurrent: false };

    const container = render(
      <PhotoStripItem item={activeItem} total={2} onSelect={vi.fn()} />,
    ).container;

    expect(container.firstElementChild).toHaveClass("ring-orange-400");
    expect(container.firstElementChild).not.toHaveClass("ring-emerald-500");
  });

  it("renders emerald, not orange, when an item is somehow both (D2's ordering rule)", () => {
    const items = stripItems(shots([0]), 0);
    const both = { ...items[0], isActive: true, isCurrent: true };

    const container = render(
      <PhotoStripItem item={both} total={2} onSelect={vi.fn()} />,
    ).container;

    // `currentRing` is applied last in the template literal, so it is the one that wins.
    const className = container.firstElementChild?.className ?? "";

    expect(className.indexOf("ring-emerald-500")).toBeGreaterThan(-1);
    expect(className.indexOf("ring-orange-400")).toBeGreaterThan(
      className.indexOf("ring-emerald-500"),
    );
  });

  it("has no ring at all when it is neither current nor active", () => {
    const container = renderItem(1);

    expect(container.firstElementChild).not.toHaveClass("ring-emerald-500");
    expect(container.firstElementChild).not.toHaveClass("ring-orange-400");
  });

  it("never marks more than one item active, and never the current one", () => {
    for (const cursorIndex of [0, 1]) {
      const items = stripItems(shots([0, 1]), cursorIndex);

      expect(items.filter((item) => item.isActive)).toEqual([]);
      expect(items.filter((item) => item.isCurrent)).toHaveLength(1);
    }
  });
});
```

**Accept.** `npx vitest run src/components/host/guide/PhotoStripItem.test.tsx` → `Tests 5 passed (5)`, 0 failing
**Verify.** `npm run gate`
