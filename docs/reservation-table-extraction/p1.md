**Prerequisite:** none. This is the first phase.
**Gate:** `npm run gate` (run in `covera`).

### Step 1.1 — Widen the subject and add the two fields

**Touch.** `src/lib/helpers/proofWindow.ts` (edit)

**Do.** Part (a): add `checkOutDatetime` to `ProofWindowSubject`, directly after
`alternativeCheckOutDatetime`, so the two check-outs sit together. It is optional and nullable for
the reason in D2a:

```ts
  alternativeCheckOutDatetime?: string | null;
  /** The plain check-out. Optional so the type stays satisfiable without it (D2a). */
  checkOutDatetime?: string | null;
```

Part (b): add the two fields to the `ProofWindowState` interface, directly after
`hasSubmittedProofs` and before `canTakeShots`:

```ts
  /** True once the effective check-out — the alternative when one is set — has passed (D3). */
  isPast: boolean;
  /** True once the plain check-out has passed. The alternative, if any, is ignored (D3). */
  isPastEnd: boolean;
```

Part (c): compute the two fields inside `getProofWindowState` and add them to the returned object.
The function's second parameter is already named `now`, so the arithmetic reads it directly — the
signature does not change. Insert the two constants directly after the existing `hasSubmittedProofs`
computation, before the `state` resolution:

```ts
  // D3: the same precedence the check-in already uses — the alternative wins when one is set.
  // A missing or unparseable value reads as "not past": a reservation with no usable check-out
  // cannot be a finished stay, and reporting it as one would disable every action on it.
  // `||` and not `??`: an empty-string alternative must fall through to the plain check-out,
  // exactly as `effectiveCheckInDatetime` does with the same operator.
  const effectiveCheckOutDatetime =
    reservation.alternativeCheckOutDatetime || reservation.checkOutDatetime || null;

  const isPast = isAfterNow(effectiveCheckOutDatetime, now);
  const isPastEnd = isAfterNow(reservation.checkOutDatetime, now);
```

Then add them to the returned object literal, after `hasSubmittedProofs`:

```ts
    hasSubmittedProofs,
    isPast,
    isPastEnd,
    canTakeShots: state === "OPEN",
```

Part (d): add the small parse helper at the bottom of the file, below `resolveState`:

```ts
/**
 * D2/D3: "has this instant already passed", for a value that may be missing or corrupt.
 * `Number.isFinite` for the same reason `getProofWindowState` uses it on the check-in: an
 * unparseable date must read as "no such instant", which here means "not past" — never as
 * epoch 0, which would read as "past" and disable everything.
 */
function isAfterNow(value: string | null | undefined, now: number): boolean {
  if (!value) return false;

  const parsed = new Date(value).getTime();

  return Number.isFinite(parsed) && parsed < now;
}
```

### Step 1.2 — Test the new answers

**Touch.** `src/lib/helpers/proofWindow.test.ts` (edit)

**Do.** Append a new `describe` block at the end of the file, as a sibling of the existing blocks.
It uses the file's own idiom — the `subject()` factory and the `at()` offset helper, both anchored
on `CHECK_IN` — so it reads like the cases already there. `checkOutDatetime` is supplied through
`subject()`'s `overrides`, which is why step 1.1 made it optional.

```ts
describe("isPast and isPastEnd — has the stay ended", () => {
  it("reports both as past once the check-out has gone by", () => {
    // Check-out at +2h, the clock at +3h: the stay is over.
    const state = getProofWindowState(subject({ checkOutDatetime: new Date(at(2 * HOUR)).toISOString() }), at(3 * HOUR));

    expect(state.isPast).toBe(true);
    expect(state.isPastEnd).toBe(true);
  });

  it("reports neither as past for a stay that has not ended", () => {
    const state = getProofWindowState(subject({ checkOutDatetime: new Date(at(24 * HOUR)).toISOString() }), at(HOUR));

    expect(state.isPast).toBe(false);
    expect(state.isPastEnd).toBe(false);
  });

  it("lets the alternative check-out win, which is the precedence rule", () => {
    // The plain check-out is 1h gone; the alternative is two days out. The stay is NOT
    // over, because the alternative is the effective one — but the plain end HAS passed,
    // and that is exactly what isPastEnd is for (D3).
    const state = getProofWindowState(
      subject({
        checkOutDatetime: new Date(at(2 * HOUR)).toISOString(),
        alternativeCheckOutDatetime: new Date(at(48 * HOUR)).toISOString(),
      }),
      at(3 * HOUR),
    );

    expect(state.isPast).toBe(false);
    expect(state.isPastEnd).toBe(true);
  });

  it("is never past when the check-out is missing, null, empty or unparseable", () => {
    for (const checkOutDatetime of [undefined, null, "", "not-a-date"]) {
      const state = getProofWindowState(subject({ checkOutDatetime }), at(24 * HOUR));

      expect(state.isPast).toBe(false);
      expect(state.isPastEnd).toBe(false);
    }
  });

  it("stays independent of the window state, in both directions", () => {
    // Both have proofs submitted, so both report ALREADY_SUBMITTED — the window answer must
    // not shadow the past answer, and the past answer must not shadow the window's.
    const past = getProofWindowState(
      subject({ checkOutDatetime: new Date(at(2 * HOUR)).toISOString(), hasPhotoProof: true }),
      at(3 * HOUR),
    );
    const upcoming = getProofWindowState(
      subject({ checkOutDatetime: new Date(at(24 * HOUR)).toISOString(), hasPhotoProof: true }),
      at(HOUR),
    );

    expect(past.state).toBe("ALREADY_SUBMITTED");
    expect(upcoming.state).toBe("ALREADY_SUBMITTED");
    expect(past.isPast).toBe(true);
    expect(upcoming.isPast).toBe(false);
  });

  it("treats the exact check-out instant as not yet past", () => {
    const state = getProofWindowState(subject({ checkOutDatetime: new Date(at(3 * HOUR)).toISOString() }), at(3 * HOUR));

    expect(state.isPast).toBe(false);
  });
});
```
