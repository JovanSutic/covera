# Phase 2 — the past-date rule, on both surfaces

**Prerequisite:** phase 1 must be complete — this phase reads `window.isPast`, the field phase 1 adds.
**Gate:** `npm run gate` (run in `covera`).

This phase is one user-visible thing: a reservation whose stay is over offers no actions, in the
table's menu and on the reservation page's header alike. It touches no typography and no layout.
(The four tooltip keys it references arrive in phase 4; until then `t()` renders the key string,
which is why the gate stays green throughout.)

Part (d): the copy-guest-message item renders only when `hasInspection`. Widening that guard to
`|| isPast` would leave the item **visibly enabled-looking and one click from opening**: in this
repo `PopoverTrigger` is itself a `<div onClick={toggleOpen}>` (`src/components/Popover.tsx:110-113`),
so `disabled` on the `<button>` inside it does nothing — the click lands on the div and the popover
opens regardless. Disabling the button is therefore not enough, and the whole item must be replaced
by a disabled button outside any `Popover` when the stay is past. Replace the entire
`{hasInspection && ( <Popover> … </Popover> )}` block with:

```tsx
            {isPast ? (
              // A past stay has no guest message to copy, and `PopoverTrigger` is the
              // click target, not this button — so a disabled button inside a Popover
              // would still open it. This renders the same item without one.
              <button
                type="button"
                disabled
                title={t("reservationActionsCell.tooltip.copyMessagePast")}
                className={ITEM_CLASSES}
              >
                <LinkIcon className="w-4 h-4 shrink-0" />
                {t("reservationActionsMenu.copyGuestMessage")}
              </button>
            ) : (
              hasInspection && (
                <Popover>
                  <PopoverTrigger>
                    <button type="button" className={ITEM_CLASSES}>
                      <LinkIcon className="w-4 h-4 shrink-0" />
                      {t("reservationActionsMenu.copyGuestMessage")}
                    </button>
                  </PopoverTrigger>
                  <PopoverContent align="left">
                    <GuestInspectionMessage
                      guestName={reservation.guestName}
                      guestInspectionUrl={guestInspectionUrl}
                    />
                  </PopoverContent>
                </Popover>
              )
            )}
```

This keeps the enabled path byte-identical to what is there now (the ternary's else branch is the
existing JSX, unchanged) and gives the past path the same classes and tooltip as the other three
disabled items.

Part (e): the delete item's `disabled` and `title` on its `ConfirmActionButton`:

```tsx
                disabled={isPast || !isDeletable}
                title={
                  isPast
                    ? t("reservationActionsCell.tooltip.cannotDeletePast")
                    : isDeletable
                      ? t("reservationActionsCell.tooltip.delete")
                      : t("reservationActionsCell.tooltip.cannotDelete")
                }
```

## Phase 2 — why 2.1 comes first, and why 2.3 is not optional

Step 2.1 puts `isPast` on the hook; 2.2 and 2.3 consume it. Landing a consumer before 2.1 does not
compile. And both consumers are required: landing 2.2 without 2.3 would leave the table's menu
refusing a past reservation while the page it opens still offers the same actions — the exact
disagreement D5 exists to prevent.

Both 2.2 and 2.3 hit the same obstacle: the copy-guest-message item is a `Popover` whose *trigger
div* is the click target, so `disabled` on the button inside it is inert. That is why both steps
restructure the item into a ternary rather than widening its guard — a guard-only fix would render
four items that look disabled while one of them still opens.
