metric. The document produced here has to make that distinction impossible to miss.

### Step 6.2 — Write the baseline document

**Touch.** `docs/routing-performance-baseline.md` (create — it was deleted in `0fa546c`)

**Do.** Write the file with this structure, filling the metric cells with the real numbers measured
in steps 6.3–6.5 (leave them as `TBD` only until those steps run; the phase is not done while any
`TBD` remains):

```markdown
# Routing performance baseline

Measured on `feature/49_router-improvements`, on this machine, over a local `vite preview` build
with the API reachable. Every number here is a median of 5 runs.

## What each column means — read this before quoting a number

| Column | Measures | What it must NOT be used to claim |
| --- | --- | --- |
| `chunkMs` | Router `loading` → `idle`: guard checks + dynamic import | **Not** how fast data arrives. This was the only column before the router-data-prefetch feature, and it was misread as a data metric. |
| `dataMs` | Navigation start → every query that navigation started settled | Data readiness. `null` when the navigation started no query. |
| `prefetched` | Was the href preloaded before the navigation? | — |
| `waterfalls` | Requests that started only after the page's chunk resolved | The number this feature is meant to drive to 0. |

`window.__routeTimings.getMedians()` returns `{ chunkMs, dataMs }` in dev; `window.__routeTimings.getTimings()`
returns every sample with its `prefetched` flag.

## Tracker

| Row | Change | chunkMs | dataMs | waterfalls | entry chunk (gzip) | gate |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | pre-optimization baseline (2026-10-27, `9bf…`) | 9.2 | n/a (not measured then) | 3/3 | 90566 pre-split | pass |
| … | router-maximization final | 7.2 | n/a (not measured then) | 1 | 90566 | 3/3 |
| 6 | router-data-prefetch (this feature) | TBD | TBD | TBD | TBD | pass |
```

Keep the historical rows verbatim from step 6.1 — do not "correct" the old numbers. The `dataMs`

### Step 6.3 — Measure the entry chunk against the budget

**Touch.** none (measurement)

**Do.**

```

```

`npx vite build`, **not** `npm run build` — the latter's `prebuild` hook calls `api:generate`, which

### Step 6.4 — Measure the timings and the waterfall count

**Touch.** none (measurement)

**Do.** Start the dev server (`npm run dev`), sign in as a host, and for each of these navigations
run 5 times and record the median:

1. `/host/dashboard` reached from the header, **cold** (no hover — click immediately).
2. `/host/dashboard` reached **warm** (hover the link for > 100 ms first).
3. `/host/apartments/:id` reached warm from the list.
4. `/admin/dashboard` reached warm, then the `?tab=apartments` tab.

Read the numbers from the DevTools console:

```js
window.__routeTimings.getMedians()
window.__routeTimings.getTimings()
```

Count waterfalls from the Network tab: a request is a **waterfall** when it starts *after* the
route's JS chunk resolves. Record the count as `startedAfterChunk / total`. The expected result for
warm navigations on `/host/apartments/:id` is `0 / 4` — that is hole 2 closed.

**Accept.** The four medians and the two waterfall counts are recorded in the document from step
6.2, and the `dataMs` column is non-null for every warm row.
**A warm row whose `dataMs` is null**, or whose waterfall count is unchanged from cold, means the
prefetch is not running — report it; do not record the number as a pass.

**Verify.** n/a — the recorded output is the acceptance.

### Step 6.6 — Walk the regression checklist

**Touch.** none (manual verification)

**Do.** Confirm each of these in the browser, because the gate cannot see any of them:

1. `/host` still redirects to `/host/dashboard`.
2. An unknown URL still renders a 404 **inside** the shell.
3. A host visiting `/admin/dashboard` gets a 403 **at that URL** with no admin chunk requested.
4. **A signed-out guest can still open `/inspection/<valid-uuid>`** — the D7 flow. Copy the URL from
   a host's reservation popover, open it in a private window, and confirm the inspection loads
   without a session. This is the single most important manual check in this feature: the prefetch
   touches that query, and getting its auth wrong would break a guest-facing flow.
5. `npm run dev` renders a non-blank page at `/`.

**Accept.** All five confirmed in the browser, each with the observed result recorded in the
document from step 6.2 under a `## Manual verification` heading.

**Verify.** n/a — the recorded observations are the acceptance.
