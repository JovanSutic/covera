# Phase 4 — host and admin sections

**Prerequisite:** phase 3 (`defineRoutes`, `paths.ts`, `redirects.ts`, `createAppRouter`).
**Gate:** `npm run gate` — must be green before step 4.1.

**Why this phase is fourth:** playbook stage 2's second half (R3, R5, F1, F3, F8). It is split from
phase 3 as D19: the public tree and the builder in one reviewable change, the two access-guarded
sections in another.

**Observable gain.** Two of them:

1. **A host opening `/admin/dashboard` sees a 403 at that URL and downloads zero bytes of admin
   code.** Today `requireRoleGuard("admin")` redirects them to `/host/dashboard`, after `lazy` has
   already started fetching the admin chunk.
2. **`/host` lands on `/host/dashboard`** instead of rendering an empty `<Outlet />` (a blank page).

**This phase changes observable behaviour on purpose** (D1). The 403-in-place change affects every
cross-role URL, and it is called out in the PR.

```ts
import type { SectionRoute } from "../defineRoutes";

export const hostRoutes: SectionRoute = {
  path: "host",
  requires: "canOpenHost",
  children: [
    { index: true, loader: { to: "dashboard" } },

      path: "dashboard",
      page: () => import("@/pages/host/Dashboard"),
      handle: { crumb: "hostDashboard.title" },

      page: () => import("@/pages/host/ApartmentList"),
```

Neither section has a `layout` yet — the pages still render their own `<Header />`, which phase 5
removes once the Shell owns it (D24). A section without a layout is a **group** to the builder: it
adds a path segment and a rule, and the builder gives it a loader because it adds a rule (R3) — that
loader is what makes the 403 happen before any child chunk is requested.

`crumb` values are translation keys that already exist (verified in `public/locales/en/general.json`):
`adminDashboard.title`, `hostDashboard.title`, `hostApartments.title`, `apartmentPage.tabs.ariaLabel`.

Part (d): make **no** edit to `src/lib/router/routes/public.ts` in this step. The `*` route is added in
step 5.5, in the same step that creates `NotFoundPage.tsx` — adding it here would reference a module

Part (b): add to `src/lib/router/access.ts`, after `PathRequirement`:

```ts
/** Where a signed-in user of this role belongs after signing in (D9). */
export function dashboardPathForRole(role: UserRole): string {
  if (role === "admin" || role === "host") return `/${role}/dashboard`;
  return "/";
}
```

`dashboardPathForRole` is deliberately the one place a role becomes a path, and it returns a
**string** rather than going through `buildPath`: the two dashboards it names are guarded routes, and
a sign-in redirect is *authentication* navigation (D2), which is exempt from the "no hand-built
paths" rule for the same reason `/login` is. Phase 9's grep for hand-built paths is written to allow
exactly this function — see the phase 9 checklist.


and replace the block

```tsx

```

…together with the two `navigate(...)` calls it feeds, with a navigation driven by the session store.
The exact final shape of that handler, replacing the existing one after `signIn` succeeds:

```tsx
      await sessionRefresh();
```

### Step 4.4 — Static tree test

**Touch.** `src/lib/router/routes.test.ts` (create)

**Do.**

```ts
import { describe, expect, it } from "vitest";
import { defineRoutes } from "./defineRoutes";
import type { RouteNode } from "./defineRoutes";
import { adminRoutes, hostRoutes, publicRoutes } from "./routes";

const TREE: readonly RouteNode[] = [...publicRoutes, adminRoutes, hostRoutes];

function build() {
  return defineRoutes(TREE, { isAllowed: () => true, errorElement: null });
}

interface WalkedRoute {
  id: string;
  path?: string;
  index?: boolean;
  guard?: { pattern: string; rules: readonly string[]; params: Record<string, string> };
  children?: WalkedRoute[];
}

function walk(routes: unknown, visit: (route: WalkedRoute) => void): void {
  for (const route of routes as WalkedRoute[]) {
    visit(route);
    if (route.children) walk(route.children, visit);
  }
}

describe("the route tree", () => {
  it("builds without throwing", () => {
    expect(() => build()).not.toThrow();
  });

  it("gives every top-level section a rule", () => {
    for (const section of [adminRoutes, hostRoutes]) {
      expect(section.requires).toBeTruthy();
    }
  });

  it("types every :param in the tree", () => {
    const seen: string[] = [];

    walk(build(), (route) => {
      const pattern = route.guard?.pattern ?? "";
      for (const segment of pattern.split("/")) {
        if (!segment.startsWith(":")) continue;
        const name = segment.slice(1);
        seen.push(`${pattern} → ${name}`);
        expect(Object.keys(route.guard?.params ?? {})).toContain(name);
      }
    });

    expect(seen.length).toBeGreaterThan(0);
  });

  it("has no duplicate route id", () => {
    const ids: string[] = [];

    walk(build(), (route) => {
      ids.push(route.id);
    });

    expect(new Set(ids).size).toBe(ids.length);
  });

  it("inherits the section rule into every child of a section", () => {
    const patternsWithRules = new Map<string, readonly string[]>();

    walk(build(), (route) => {
      if (route.guard) patternsWithRules.set(route.guard.pattern, route.guard.rules);
    });

    expect(patternsWithRules.get("/admin/dashboard")).toEqual(["canOpenAdmin"]);
    expect(patternsWithRules.get("/host/dashboard")).toEqual(["canOpenHost"]);
    expect(patternsWithRules.get("/host/apartments")).toEqual(["canOpenHost"]);
    expect(patternsWithRules.get("/host/apartments/:id")).toEqual(["canOpenHost"]);
    expect(patternsWithRules.get("/inspection/:id")).toEqual(["public"]);
  });

  it("gives /host and /admin an index redirect to a child they can open", () => {
    const built = build();
    const host = built.find((route) => route.path === "host");
    const index = (host?.children as WalkedRoute[] | undefined)?.find(
      (child) => child.index === true,
    );

    expect(index?.guard?.redirect).toEqual({ to: "dashboard" });
    expect((index?.guard?.rules ?? []).includes("canOpenHost")).toBe(true);
  });

  it("places every guard-carrying route under a boundary that can render an error", () => {
    const built = build();
    const host = built.find((route) => route.path === "host");

    const boundaries = (host?.children as WalkedRoute[] | undefined)?.filter((child) =>
      child.id.endsWith("#boundary"),
    );

    // The group itself is wrapped by its parent level only when it has a page or
    // layout; a group's children are grouped by the callers that own a frame.
    expect(boundaries === undefined || boundaries.length <= 1).toBe(true);
  });
});
```

The last case asserts a weak property on purpose: a **group** route has no frame of its own, so the
builder does not add a boundary under it (the boundary is meaningful under a layout or a page with
children — R7). When phase 5 turns `host` into a layout, this assertion should be tightened to
`expect(boundaries).toHaveLength(1)`. Change that assertion in step 5.x, not here.

**Accept.** `npm run gate` → exit 0 and the test count rises by 7.

**Verify.** `npm run gate`

### Step 4.5 — Walk the phase checklist in a browser

**Touch.** none (verification only)

**Do.** `npm run dev`, then:

1. **Signed out**, open `/admin/dashboard` → 403 page (rendered by `ErrorPage`), **at that URL**. The
   address bar still says `/admin/dashboard`. DevTools → Network shows **no** `Dashboard-*.js` for
   `admin`. This is the phase's headline gain.
2. Signed out, open `/host/apartments` → 403 at that URL, no host chunk.
3. Sign in as a **host**. Open `/host` → lands on `/host/dashboard` with content (was: blank).
4. Sign in as a host. Open `/admin/dashboard` → 403 at `/admin/dashboard` (was: a redirect to
   `/host/dashboard`). **This is the deliberate behaviour change (D1)** — confirm it with the
   operator before committing.
5. As a host, `/host/dashboard`, `/host/apartments`, `/host/apartments/<valid id>` all render as
   before, and `/host/apartments/abc` → 404 with no API request and no chunk.
6. Sign in as an **admin**. `/admin/dashboard` renders; `/host/dashboard` → 403.
7. Sign out from the header. The app lands on `/login` and the session snapshot empties (the header
   shows "Guest").
8. Sign in as a host again from `/login` → lands on `/host/dashboard` (step 4.3's gain: no extra
   `getAuthRole()` read, and the destination comes from the store).

**Accept.** Bullets 1, 3 and 4 observed, with bullet 1's missing admin chunk confirmed in the Network
tab. Bullet 4 confirmed by the operator.

**Verify.** `npm run gate`
