# Phase 7 — URL ownership

**Prerequisite:** phase 6 (`appPaths`, `buildPath`, `AccessLink`, `apartmentQueryKey`).
**Gate:** `npm run gate` — must be green before step 7.1.

**Why this phase is seventh:** playbook stage 7 (R20–R24, R26). It converts the remaining hand-built
URLs to `buildPath`/`AccessLink` and makes page params parsed instead of raw.

**Observable gain.** Two, both about correctness rather than speed — this is the phase that stops the
app *lying* about the URL:

1. **`:id` is read parsed and validated.** `IndividualApartment` currently passes
   `useParams().id` straight into an API call, so a malformed id reaches the backend and the page
   handles the failure itself. After this phase the route rejects it first.
2. **No hand-built app path remains.** `ReservationActionsCell` builds a guest inspection link by
   concatenating `VITE_APP_BASE_PATH` — an env var that is unset in this repo, so the link silently
   becomes `/undefined/inspection/<id>`. It becomes a real path.

**Do.** Part (a): create `src/lib/router/useRouteParams.ts`:

```ts
import { useMemo } from "react";
import { useParams } from "react-router";
import { areParamsValid, parseParams } from "./params";
import type { ParsedParams } from "./params";
import type { PathDefinition } from "./paths";

/**
 * H9/R21: typed params for a route that declares them. A missing or invalid value
 * means the hook is mounted under the wrong route — a programming error, so it
 * throws rather than returning `undefined` and letting an API call fail later.
 */
export function useRouteParams<D extends PathDefinition>(definition: D): ParsedParams {
  const raw = useParams();

  const present = useMemo(() => {
    const result: Record<string, string | undefined> = {};
    for (const key of Object.keys(definition.params)) result[key] = raw[key];
    return result;
  }, [definition.params, raw]);

  if (!areParamsValid(present, definition.params)) {
    throw new Error(
      `[router] useRouteParams(${definition.pattern}) found invalid or missing params: ` +
        `${JSON.stringify(present)}`,
    );
  }

  return parseParams(present, definition.params);
}
```

### Step 7.5 — Query-definition test

**Touch.** `src/lib/api/queries/apartment.test.ts` (create)

**Do.**

```ts
import { describe, expect, it, vi, beforeEach } from "vitest";
import { QueryClient } from "@tanstack/react-query";
import { apartmentQueryKey, fetchApartment } from "./apartment";
import { QUERY_ACTIONS } from "@/lib/api/queryKeys";
import { appPaths } from "@/lib/router/paths";

vi.mock("@/api/generated/requests/sdk.gen", () => ({
  getApartmentsById: vi.fn(async ({ path }: { path: { id: string } }) => ({
    data: { id: path.id, name: "Test Apartment" },
  })),
}));

vi.mock("@/lib/api/api", () => ({
  withAuth: vi.fn(async (extra: Record<string, unknown>) => ({
    baseUrl: "http://localhost/api",
    ...extra,
  })),
}));

const VALID_UUID = "3f2504e0-4f89-41d3-9a0c-0305e82c3301";

describe("apartmentQueryKey", () => {
  it("is composed from the QUERY_ACTIONS registry entry, not a literal", () => {
    expect(apartmentQueryKey(VALID_UUID)).toEqual([
      ...QUERY_ACTIONS.APARTMENTS_GET_ID,
      VALID_UUID,
    ]);
  });

  it("differs per id, so two apartments are two cache entries", () => {
    expect(apartmentQueryKey("a")).not.toEqual(apartmentQueryKey("b"));
  });
});

describe("the prefetch and the page share one cache entry", () => {
  let client: QueryClient;

  beforeEach(() => {
    client = new QueryClient({
      defaultOptions: { queries: { retry: false } },
    });
    vi.clearAllMocks();
  });

  it("a prefetch is reused by a read of the same query, with one request", async () => {
    await client.prefetchQuery({
      queryKey: apartmentQueryKey(VALID_UUID),
      queryFn: ({ signal }) => fetchApartment(VALID_UUID, signal),
      staleTime: 30_000,
    });

    const cached = client.getQueryData(apartmentQueryKey(VALID_UUID));

    expect(cached).toEqual({ id: VALID_UUID, name: "Test Apartment" });

    // A read of the same key within the freshness window uses the cache and
    // starts no second request. This is the assertion that protects §4's
    // "same key = same args" rule from drifting.
    const again = await client.fetchQuery({
      queryKey: apartmentQueryKey(VALID_UUID),
      queryFn: ({ signal }) => fetchApartment(VALID_UUID, signal),
      staleTime: 30_000,
    });

    expect(again).toEqual(cached);

    const { getApartmentsById } = await import(
      "@/api/generated/requests/sdk.gen"
    );
    expect(getApartmentsById).toHaveBeenCalledTimes(1);
  });
});

describe("the path definition matches the route", () => {
  it("declares the full inherited rule chain, root first", () => {
    expect(appPaths.hostApartment.requires).toEqual(["public", "canOpenHost"]);
  });

  it("types the id as a uuid", () => {
    expect(appPaths.hostApartment.params).toEqual({ id: "uuid" });
  });
});
```

The last two cases are the cheap half of H13 (phase 9 does the full cross-check against the built
tree): they pin the definition this phase's `useRouteParams` call depends on.

**Accept.** `npm run gate` → exit 0 and the test count rises by 5.

**Verify.** `npm run gate`
