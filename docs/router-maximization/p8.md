# Phase 8 — startup, bundle and caching

**Prerequisite:** phase 7 (the module graph is final).
**Gate:** `npm run gate` — must be green before step 8.1.

**Why this phase is eighth:** playbook stage 6 (R17–R19, R35, R36). The budget must be set against the
**final** module graph, which is why this phase is after every code change that touches the tree.

**Observable gain.** Three:

1. **The shell paints before the page loaders run** — a cold deep link shows the header and frame while
   the page chunk is still arriving, instead of nothing.
2. **The main bundle is split by vendor** and held under a budget `npm run gate` enforces, so it can
   only get smaller. Stable libraries stop being re-downloaded on every deploy (R35).
3. **The API origin is preconnected**, so the first request does not pay for a fresh TLS handshake.

### Step 8.1 — The bundle budget script

**Touch.** `scripts/check-bundle-budget.ts` (create), `package.json` (edit)

**Do.** Part (a): create `scripts/check-bundle-budget.ts`:

```ts
/* eslint-disable no-console */
import fs from "node:fs";
import path from "node:path";
import zlib from "node:zlib";

/**
 * The main bundle budget, in gzipped bytes. Set from the baseline measured at the
 * end of phase 1 (docs/routing-performance-baseline.md, row 1) and lowered by the
 * phase-8 split. A PR that raises it fails `npm run perf:bundle` (R34/R19).
 */
const BUDGET_BYTES = 200 * 1024;

const DIST_ASSETS = path.join(process.cwd(), "dist", "assets");

function gzipSize(file: string): number {
  return zlib.gzipSync(fs.readFileSync(file)).length;
}

function main(): void {
  if (!fs.existsSync(DIST_ASSETS)) {
    console.error(
      `[perf:bundle] ${DIST_ASSETS} does not exist. Run "npx vite build" first ` +
        `(not "npm run build" — its prebuild hook calls the network).`,
    );
    process.exit(2);
  }

  const entries = fs
    .readdirSync(DIST_ASSETS)
    .filter((name) => name.endsWith(".js"))
    .map((name) => ({
      name,
      gzip: gzipSize(path.join(DIST_ASSETS, name)),
    }))
    .sort((a, b) => b.gzip - a.gzip);

  const main = entries.find((entry) => /^index-.*\.js$/.test(entry.name));

  if (!main) {
    console.error("[perf:bundle] no index-*.js entry chunk found in dist/assets.");
    process.exit(2);
  }

  console.log("[perf:bundle] largest chunks (gzip):");
  for (const entry of entries.slice(0, 5)) {
    console.log(`  ${entry.name}  ${(entry.gzip / 1024).toFixed(1)} KiB`);
  }

  const actualKib = main.gzip / 1024;
  const budgetKib = BUDGET_BYTES / 1024;

  if (main.gzip > BUDGET_BYTES) {
    console.error(
      `[perf:bundle] FAIL ${main.name} is ${actualKib.toFixed(1)} KiB gzip, ` +
        `budget is ${budgetKib.toFixed(1)} KiB. Move a heavy import out of the root, ` +
        `shell or route config (R19), or lower the budget deliberately in this file ` +
        `and say why in the PR.`,
    );
    process.exit(1);
  }

  console.log(
    `[perf:bundle] OK ${main.name} is ${actualKib.toFixed(1)} KiB gzip ` +
      `(budget ${budgetKib.toFixed(1)} KiB).`,
  );
}

main();
```

Part (b): add to `package.json`'s `scripts`, after `"gate"`:

```json
    "perf:bundle": "tsx scripts/check-bundle-budget.ts"
```

Part (c): **set `BUDGET_BYTES` from the real number.** Run `npx vite build`, then
`npm run perf:bundle`, and set the constant to the measured main-chunk gzip size **rounded down to the
nearest 4 KiB**, so the budget is today's size with no headroom to grow into. Do not leave `200 *
1024` unless it is the measured value.

**Accept.** `npx vite build && npm run perf:bundle` → exit 0 and a line reading
`[perf:bundle] OK index-*.js is <n> KiB gzip (budget <n> KiB)`. Plus
`grep -c "perf:bundle" package.json` → `1`.

**Verify.** `npx vite build && npm run perf:bundle`

### Step 8.2 — The budget test, so the gate enforces it

**Touch.** `src/lib/router/__checks__/bundleBudget.test.ts` (create)

**Do.**

```ts
import { describe, expect, it } from "vitest";
import fs from "node:fs";
import path from "node:path";
import zlib from "node:zlib";

const BUDGET_BYTES = 200 * 1024;
const DIST_ASSETS = path.join(process.cwd(), "dist", "assets");

// The gate must stay green on a clean checkout, where dist/ does not exist.
// The budget is enforced by `npm run perf:bundle` (and by this test whenever a
// build happens to be present).
const distExists = fs.existsSync(DIST_ASSETS);

describe("main bundle budget", () => {
  it.skipIf(!distExists)("keeps the entry chunk under the budget", () => {
    const main = fs
      .readdirSync(DIST_ASSETS)
      .filter((name) => /^index-.*\.js$/.test(name))
      .map((name) => ({
        name,
        gzip: zlib.gzipSync(fs.readFileSync(path.join(DIST_ASSETS, name))).length,
      }))
      .sort((a, b) => b.gzip - a.gzip)[0];

    expect(main, "no index-*.js entry chunk in dist/assets").toBeDefined();
    expect(main.gzip).toBeLessThanOrEqual(BUDGET_BYTES);
  });

  it("documents the budget in one place", () => {
    const script = fs.readFileSync(
      path.join(process.cwd(), "scripts", "check-bundle-budget.ts"),
      "utf-8",
    );

    // The two budgets must not drift: the script is the source of truth.
    expect(script).toContain("BUDGET_BYTES");
  });
});
```

Set this file's `BUDGET_BYTES` to the **same** value as the script's in step 8.1(c). Keeping two
copies is a deliberate trade: the script runs as a fast standalone check and the test re-uses the same
number inside the gate. If you prefer one source, import the constant from the script — but the script
calls `process.exit`, so importing it would run it; do not do that.

**Accept.** `npm run gate` → exit 0 and the test count rises by 2 (the first is skipped when `dist/`
is absent, which is the clean-checkout case).

**Verify.** `npm run gate`

```ts
                    'vendor-supabase': ['@supabase/supabase-js'],

        },

```

Also add the API `preconnect` (R36). In the same `defineConfig`, extend the existing plugin's
`transformIndexHtml` to also inject the preconnect tag, by changing its returned array to:

```ts
                return [
                    {
                        tag: 'link',
                        attrs: {
                            rel: 'preconnect',
                            href: (process.env.VITE_BASE_URL ?? '').replace(/\/api\/?$/, ''),
                        },
                        injectTo: 'head',
                    },
                    {
                        tag: 'script',
                        injectTo: 'head',
                        children: [
                            // ...the existing vite:preloadError listener from phase 5, unchanged
                        ].join('\n'),
                    },
                ];
```

Do **not** put the API base URL in a new variable. `VITE_BASE_URL` already exists and is already
public (invariant 3: everything `VITE_`-prefixed ships to the browser, and this is a URL, not a
secret). If `VITE_BASE_URL` is unset, the tag's `href` is an empty string — harmless, but strip it by
filtering empty tags out of the array if you prefer a clean `index.html`.

Part (b): add the shell's hydrate fallback (R18) to `createAppRouter.tsx`. The root route gets a
`HydrateFallback` for the app tree, and the root and shell routes must have **no loader** so the header
can paint immediately:

```ts
  const tree: RouteObject[] = [
    ...outsideTree,
    {
      id: "root",
      path: "/",
      element: shellElement,
      errorElement: backstopElement,
      children: appTree,
    },
  ];
```

becomes

```ts
  const tree: RouteObject[] = [
    ...outsideTree,
    {
      id: "root",
      path: "/",
      element: shellElement,
      errorElement: backstopElement,
      // No loader on root or shell: the header and frame paint at once (R18).
      children: [
        {
          id: "root#hydrate",
          hydrateFallbackElement: hydrateFallbackElement ?? null,
          children: appTree,
        },
      ],
    },
  ];
```

with a new option

```ts
  /** Shown inside the shell while the first page's loader runs (R18, phase 8). */
  hydrateFallbackElement?: React.ReactNode;
```

and in `src/App.tsx` pass `hydrateFallbackElement={<PageSkeleton />}` where `PageSkeleton` is a new
small component. Create `src/components/router/PageSkeleton.tsx`:

```tsx
/** R18: the shell paints immediately; this holds the page area during a cold load. */
export function PageSkeleton() {
  return (
    <div className="mx-auto w-full max-w-[1266px] px-4 pt-4 pb-8 lg:px-8">
      <div className="animate-pulse space-y-4 py-8">
        <div className="h-7 w-56 rounded bg-gray-200 dark:bg-gray-800" />
        <div className="h-4 w-80 rounded bg-gray-100 dark:bg-gray-800/60" />
        <div className="h-40 w-full rounded-lg bg-gray-100 dark:bg-gray-800/60" />
      </div>
    </div>
  );
}
```

**Note:** a pathless route with `hydrateFallbackElement` and no `element` renders its children through
an implicit `<Outlet />`. If `tsc` rejects `hydrateFallbackElement` on a `RouteObject` without an
`element`, add `element: <Outlet />` to that route and import `Outlet` from `react-router`. Do this
only if the compiler requires it.

**Accept.** `npm run gate` → exit 0. Plus
`grep -c "manualChunks" vite.config.ts` → `1`, and
`grep -c "hydrateFallbackElement" src/lib/router/createAppRouter.tsx` → `2`.

**Verify.** `npm run gate`

### Step 8.5 — Document the deployment requirements

**Touch.** `docs/router-maximization/00-index.md` (edit)

**Do.** Phase 8 is the last code phase, and the server-side half of R35 (caching headers) has no host
config in this repo to edit. In `docs/router-maximization/00-index.md`, under the
`## Deployment requirements (R35)` heading, **delete everything between that heading and the next
`##` heading** — today that is the "Phase 8 appends the concrete header list here" sentence and the
four bullets below it — and replace it with the section below, so whoever configures the host has the
finished list. The section must read:

```markdown
There is no deploy config in this repo (no netlify/vercel/Dockerfile/nginx/caddy — checked
2026-10-27). These are the headers the deployment must set; they are the server half of R35 and the
reason a repeat visit loads only `index.html` and API data:

| Path | Header | Why |
| --- | --- | --- |
| `/assets/*` (Vite's hashed output) | `Cache-Control: public, max-age=31536000, immutable` | A hashed filename can never change, so it can be cached forever (R35) |
| `/index.html` | `Cache-Control: no-cache` | It is the one file that must always be revalidated, or a deploy is invisible to open tabs |
| `/locales/*.json` | `Cache-Control: public, max-age=3600` | Reference data that changes with a deploy; an hour is short enough to be safe |
| everything else | `Cache-Control: public, max-age=300` | Conservative default |

Also required: brotli or gzip compression on text assets, and HTTP/2 or better. Without compression
the bundle budget above is measured on bytes the user never downloads, so the numbers stop matching
reality.

If a service worker is ever added to precache route chunks, it **must not** serve a cached
`index.html` — that is the one file whose staleness breaks a deploy (R35).
```

**Accept.** `grep -c "locales/\*.json" docs/router-maximization/00-index.md` → `1` (a row the index did
not have before this step), and
`grep -c "Phase 8 appends the concrete header list" docs/router-maximization/00-index.md` → `0` (the old
bullet list is gone, not appended to).

**Verify.** `npm run gate`
