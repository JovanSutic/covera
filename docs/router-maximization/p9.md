# Phase 9 — regression guards

**Prerequisite:** phase 8 (the tree and the factory are final).
**Gate:** `npm run gate` — must be green before step 9.1.

**Why this phase is ninth:** playbook stage 8 (R34). Guards must describe the **final** tree, so they
land after every change that shapes it. This is also the phase that makes the previous eight phases
stay true.

**Observable gain.** None for the user, and that is the point: the gains of phases 1–8 stop being able
to silently disappear. A pull request that adds a heavy import to the shell, or a `lazy` route, or a
role literal outside the access layer, fails `npm run gate`.

**Touch.** `src/lib/router/__checks__/tree.test.ts` (create)

**Do.**

```ts
import { describe, expect, it } from "vitest";

import { defineRoutes } from "../defineRoutes";
import type { GuardMeta, RouteNode } from "../defineRoutes";
import { ACCESS_RULES } from "../access";
import { appPaths } from "../paths";
import { adminRoutes, appRoutes, hostRoutes, outsideRoutes } from "../routes";

const TREE: readonly RouteNode[] = [
  ...appRoutes,
  adminRoutes,
  hostRoutes,
];

/** A stub access layer: every rule passes, so the tree builds for inspection (H13). */
const deps = { isAllowed: () => true, errorElement: null };

/** One built RouteObject, narrowed to the parts the builder is contracted to write. */
interface Built {
  id?: string;
  path?: string;
  index?: boolean;
  handle?: { guard?: GuardMeta };
  children?: Built[];
}

/** `handle.guard` is where the builder puts the facts (see p6's preloader) — not `route.guard`. */
function flatten(routes: unknown): Built[] {
  const out: Built[] = [];

  for (const route of routes as Built[]) {
    out.push(route);
    if (route.children) out.push(...flatten(route.children));
  }

  return out;
}

/**
 * Both trees, because `appPaths` spans both: `login`/`updatePassword` live only in
 * `outsideRoutes`, and everything else only in the app tree (p5 split them). The
 * builder is called twice rather than once with both lists, so this test also
 * exercises the duplicate-id check the factory relies on.
 */
const APP_BUILT = flatten(defineRoutes(TREE, deps));
const OUTSIDE_BUILT = flatten(defineRoutes(outsideRoutes, deps));
const BUILT = [...APP_BUILT, ...OUTSIDE_BUILT];

/**
 * H13's unique value: `appPaths` is hand-written and the route is hand-written, so
 * nothing except this check notices when they disagree. TypeScript cannot — both
 * sides are individually well-typed. A typo'd rule *name* is a compile error
 * (`requires?: RuleName`), a duplicate id and an untyped `:param` both throw inside
 * the builder, so those are deliberately not re-checked here.
 */
function mismatches(): string[] {
  const found: string[] = [];
  const guardByPattern = new Map<string, GuardMeta>();

  for (const route of BUILT) {
    if (route.handle?.guard) {
      guardByPattern.set(route.handle.guard.pattern, route.handle.guard);
    }
  }

  for (const [name, definition] of Object.entries(appPaths)) {
    const guard = guardByPattern.get(definition.pattern);

    if (!guard) {
      found.push(`appPaths.${name} (${definition.pattern}) has no route`);
      continue;
    }

    if (JSON.stringify(guard.rules) !== JSON.stringify(definition.requires)) {
      found.push(
        `appPaths.${name} requires ${JSON.stringify(definition.requires)} but the ` +
          `route inherits ${JSON.stringify(guard.rules)}`,
      );
    }

    const declared = Object.keys(definition.params).sort();
    const actual = Object.keys(guard.params).sort();

    if (JSON.stringify(declared) !== JSON.stringify(actual)) {
      found.push(
        `appPaths.${name} declares params ${JSON.stringify(declared)} but the route ` +
          `has ${JSON.stringify(actual)}`,
      );
    }
  }

  const ids = BUILT.map((route) => route.id).filter(Boolean) as string[];
  if (new Set(ids).size !== ids.length) {
    found.push(`duplicate built route id among ${ids.length} routes`);
  }

  return found;
}

describe("the static route tree (H13)", () => {
  it("builds for a stub access layer", () => {
    expect(() => defineRoutes(TREE, deps)).not.toThrow();
  });

  it("has no path definition that disagrees with the tree", () => {
    expect(mismatches()).toEqual([]);
  });

  it("answers every rule name the tree uses with a real rule", () => {
    for (const route of BUILT) {
      for (const rule of route.handle?.guard?.rules ?? []) {
        expect(Object.keys(ACCESS_RULES)).toContain(rule);
      }
    }
  });

  it("keeps the outside tree outside the shell", () => {
    const outsideIds = OUTSIDE_BUILT.map((route) => route.id);

    // /login and /update-password render outside the shell, so they are built
    // separately — and must therefore not appear in the app tree.
    expect(outsideIds).toContain("/login#page");
    expect(outsideIds).toContain("/update-password#page");
    expect(APP_BUILT.some((route) => route.id === "/login#page")).toBe(false);
    expect(APP_BUILT.some((route) => route.id === "/update-password#page")).toBe(false);
  });

  it("has a * route inside the app tree, so 404s keep the shell", () => {
    expect(APP_BUILT.some((route) => route.path === "*")).toBe(true);
  });
});
```

Four shape facts this test depends on, all verified against the plan and the installed react-router
rather than assumed:

- The guard facts live on `route.handle.guard` (p3's `Handle`), which is also where p6's preloader
  reads them from (`match.route.handle.guard`). `route.guard` does not exist.
- `appPaths.hostApartment.requires` is `["public", "canOpenHost"]` and the `host` section route
  contributes `canOpenHost`, so the inherited chain matches — the check passes on the tree as
  specified. If it fails, **the tree is wrong, not the test**: fix the route or the definition, and
  record which.
- `appPaths` spans both trees. `login` and `updatePassword` are the only definitions whose route lives
  in `outsideRoutes`; the other six live in the app tree. That is why the test builds both and
  searches their union, and why the "outside" case asserts against `APP_BUILT` specifically.
- The `*` route is a real `RouteBase` node, so its built object is `{ id: "/*#page", path: "*" }` —
  the `guard` is on `handle`, so this case checks `path`, not the pattern.

**Accept.** `npm run gate` → exit 0 and the test count rises by 5.

### Step 9.2 — Router behaviour on a memory router

```ts
import { describe, expect, it, vi } from "vitest";
import type { DataRouter } from "react-router";

import { createAppRouter } from "../createAppRouter";
import { createAccess } from "../access";
import { createSessionStore } from "../session";
import { adminRoutes, appRoutes, hostRoutes, outsideRoutes } from "../routes";
import type { AuthenticatedUser, UserRole } from "@/lib/auth";
import type { SessionState } from "../session";

function sessionState(role: UserRole | null): SessionState {
  const user: AuthenticatedUser | null = role
    ? {
        id: `user-${role}`,
        email: `${role}@covera.test`,
        role,
        // AuthenticatedUser requires both (src/lib/auth.ts) — `strict` rejects the
        // object without them.
        firstName: role,
        lastName: "User",
      }
    : null;

  return { status: "ready", user, role };
}

async function buildRouter(role: UserRole | null, initialEntry: string) {
  const state = sessionState(role);
  const session = createSessionStore({ readUser: async () => state.user });
  await session.bootstrap();
  const access = createAccess(() => state);

  const created = createAppRouter({
    session,
    access,
    routes: [...appRoutes, adminRoutes, hostRoutes],
    outsideRoutes,
    // p5 renamed this option: the root route's error element, outside the shell.
    backstopElement: null,
    errorElement: null,
    initialEntries: [initialEntry],
  });

  // createMemoryRouter() calls .initialize(), which STARTS the first navigation
  // without returning its promise — so the state is not settled when the factory
  // returns. Await the flag before reading location or errors (verified against
  // react-router 7.14.0's createMemoryRouter/initialize).
  await settle(created.router);

  return created;
}

async function settle(router: DataRouter): Promise<void> {
  await vi.waitFor(() => expect(router.state.initialized).toBe(true));
}

describe("routing behaviour on the real tree", () => {
  it("404s a malformed uuid", async () => {
    const { router } = await buildRouter(null, "/inspection/not-a-uuid");

    const error = Object.values(router.state.errors ?? {})[0] as {
      status?: number;
    };

    expect(error?.status).toBe(404);
    // The URL is unchanged: a rejected param is an error at that URL, not a redirect.
    expect(router.state.initialized).toBe(true);
  });

  it("403s a host at /admin/dashboard", async () => {
    const { router } = await buildRouter("host", "/admin/dashboard");

    const error = Object.values(router.state.errors ?? {})[0] as {
      status?: number;
    };

    expect(error?.status).toBe(403);
    expect(router.state.location.pathname).toBe("/admin/dashboard");
  });

  it("lands /host on /host/dashboard", async () => {
    const { router } = await buildRouter("host", "/host");

    expect(router.state.location.pathname).toBe("/host/dashboard");
    expect(router.state.errors).toBeNull();
  });

  it("lets an admin into /admin/dashboard", async () => {
    const { router } = await buildRouter("admin", "/admin/dashboard");

    expect(router.state.errors).toBeNull();
    expect(router.state.location.pathname).toBe("/admin/dashboard");
  });

  it("keeps /login reachable when signed out", async () => {
    const { router } = await buildRouter(null, "/login");

    expect(router.state.errors).toBeNull();
    expect(router.state.location.pathname).toBe("/login");
  });

  it("matches an unknown URL in the tree, so the 404 is a page not a router error", async () => {
    const { router } = await buildRouter("host", "/nope");

    // The `*` route matches, so there is no router error — NotFoundPage renders.
    expect(router.state.errors).toBeNull();
    expect(router.state.matches.at(-1)?.route.path).toBe("*");
  });
});
```

The spy on the page module is deliberately **not** used: `loadModule` is a closure created inside
`makeLoader`, so no test can observe it from outside. The observable form of "the page was never
imported" is that the router settled with a 404 rather than rendering a component, paired with the
loader's own ordering (p3's `makeLoader` runs the rule and param checks before `await loadModule()`),
which p3's `defineRoutes.test.ts` already asserts directly. Do not add `vi.mock` of the page module
here — it would not observe the same thing and would make the test lie.

Two more shape notes, both verified against react-router 7.14.0 rather than assumed:

- `errors` is keyed by the nearest **error boundary**, not by the route that threw
  (`findNearestBoundary`). With `errorElement`/`backstopElement` passed as `null` this test's tree has
  no boundary at all, so the key falls back to the root match — which is why no case here asserts on
  the key. In the real app (p5) it is the nearest `#boundary`, and `RouteError` reads `status` off the
  error regardless of which route it is keyed to.
- `router.state.initialized` is what `settle()` waits on. It is set in `completeNavigation`, so it
  becomes true even when a loader rejected — which is exactly the settle point these cases need.

**Accept.** `npm run gate` → exit 0 and the test count rises by 6.

**Verify.** `npm run gate`

### Step 9.4 — Prove the guards actually fail

**Touch.** none (verification only), then revert

**Do.** Each case below is a deliberate violation. Make it, run the check, confirm **failure**, then
revert it with `git checkout -- <file>`. Do not commit any of them. This is the step that proves the
guards are load-bearing rather than decorative (S8.1, S8.2).

1. **A `lazy` route fails lint.** Add `lazy: async () => ({})` to `hostRoutes.children[0]` in
   `src/lib/router/routes/host.ts`, run `npm run lint` → fails with the "Routes are data (R1)" message.
   Revert.
2. **A role comparison outside the access layer fails lint.** Add
   `const isHost = someRole === "host";` (declare `const someRole: string = "host";` above it so the
   file still typechecks) to `src/components/Header.tsx`, run `npm run lint` → fails with the R26
   message. Revert.
3. **A hand-written `createBrowserRouter` fails lint.** Add `const r = createBrowserRouter([]);` plus
   the import to `src/components/Header.tsx`, run `npm run lint` → fails with the principle-6 message.
   Revert.
4. **A `react-router-dom` import fails lint.** Add `import { Link } from "react-router-dom";` to
   `src/components/Header.tsx`, run `npm run lint` → fails with `no-restricted-imports`. Revert.
5. **A path definition that disagrees with the tree fails.** Change
   `appPaths.hostApartments.requires` to `["public"]` (still a legal `RuleName`, so it compiles), run
   `npx vitest run src/lib/router/__checks__/tree.test.ts` → fails with
   `appPaths.hostApartments requires ["public"] but the route inherits ["public","canOpenHost"]`.
   Revert.
6. **A section rule that no longer reaches its children fails.** In
   `src/lib/router/routes/host.ts`, move `requires: "canOpenHost"` from the `host` section onto the
   `dashboard` child only, run `npx vitest run src/lib/router/__checks__/tree.test.ts` → fails with the
   same "requires … but the route inherits …" message for `hostApartments`/`hostApartment`. Use
   `npx vitest run`, not `npm run gate`: this edit is also a `tsc` error for the section's type, and
   `vitest` transforms without typechecking, so it is the command that isolates the assertion. Revert.
   (An *untyped* `:param` is a third, different guard: `assertParamsDeclared` throws inside the builder
   itself, so it fails `npm run gate` at build — p3's `defineRoutes.test.ts` already pins that.)
7. **A bundle regression fails the budget.** Temporarily add a heavy import (e.g.
   `import * as _ from "lucide-react";`… use any large module already in `node_modules`) to
   `src/App.tsx`, run `npx vite build && npm run perf:bundle` → fails with the budget message. Revert.

**Accept.** All seven cases observed to **fail**, each reverted, and `git status --porcelain` shows no
leftover modification from this step once reverted.
