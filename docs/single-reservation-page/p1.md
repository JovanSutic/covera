asserts ownership instead (step 1.2), which is what `createReservationRoute` already does.

### Step 1.2 — Add the handler

**Touch.** `src/modules/reservations/reservations.route.ts` (edit)

**Do.** Part (a): add `getReservationByIdRoute` to the existing import from `./reservations.contract`,


Part (b): add `assertApartmentOwnership` and `reservationErrors` usage. `assertApartmentOwnership` is
already imported in this file; `reservationErrors` is already imported too. **No import change is
needed for either** — verify with the Accept below before assuming otherwise.

Part (c): add the handler immediately after the `getReservationsByApartmentRoute` block and before
`createReservationRoute`:

```ts
app.openapi(getReservationByIdRoute, async (c) => {
  const db = c.get("db");
  const { id } = c.req.valid("param");
  const user = c.get("user");

  if (!user) {
    throw reservationErrors.unauthenticated();
  }

  const reservation = await reservationsService.getById(db, id);

  if (!reservation) {
    throw reservationErrors.notFound({ id });
  }

  // D5: ownership is asserted here rather than by apartmentGuard(true), because that
  // guard resolves an unknown id through the apartments table first and would report
  // APARTMENT_NOT_FOUND for a reservation that simply does not exist.
  await assertApartmentOwnership(db, reservation.apartmentId, {
    userId: user.id,
    role: user.role,
    allowAdmin: true,
  });

  const withInspection = await reservationsService.getByIdWithInspection(db, id);

  return c.json(withInspection, 200);
});
```

### Step 1.3 — Add the service read that loads the inspection

**Touch.** `src/modules/reservations/reservations.service.ts` (edit), `src/modules/reservations/reservations.route.ts` (edit — register the route), `src/modules/reservations/reservations.schema.ts` (edit — export the type in part (c))

**Do.** Part (a): in `reservations.service.ts`, add a method directly after the existing `getById`
(which stays untouched — `apartmentGuard` calls it and returns a bare `Reservation`). The new method
is the one that loads the relation, using the same `with: { inspection: true }` shape
`getByApartmentId` already uses for its list:

```ts
  /**
   * One reservation with its inspection attached — the shape the reservation page
   * reads (D4). `getById` above deliberately stays relation-free: `apartmentGuard`
   * calls it for ownership resolution and needs only the row.
   */
  async getByIdWithInspection(
    db: Variables["db"],
    id: string,
  ): Promise<ReservationWithInspection | null> {
    const reservation = await db.query.reservations.findFirst({
      where: eq(reservations.id, id),
      with: {
        inspection: true,
      },
    });

    return reservation || null;
  },
```

### Step 1.4 — Test the new route

**Touch.** `src/modules/reservations/reservations.test.ts` (edit)

**Do.** Add a `getByIdWithInspection` mock to the existing `vi.hoisted` block and to the
`vi.mock("./reservations.service")` factory, so the new method joins the module's mock surface.
In the `vi.hoisted` destructure and return, add `mockGetByIdWithInspection: vi.fn(),` next to
`mockGetById`, and in the service mock add `getByIdWithInspection: mockGetByIdWithInspection,`.

Then append a new `describe` block at the end of the file, before the closing of the top-level
`describe("Reservations routes", ...)`:

```ts
  describe("GET /reservations/:id", () => {
    it("should return the reservation with its inspection for the owner", async () => {
      mockGetById.mockResolvedValue({
        id: VALID_RESERVATION_ID,
        apartmentId: VALID_APARTMENT_ID,
      });

      const mockReservation = {
        id: VALID_RESERVATION_ID,
        apartmentId: VALID_APARTMENT_ID,
        guestName: "John Doe",
        guestEmail: "john@example.com",
        checkInDatetime: "2026-09-01T14:00:00.000Z",
        checkOutDatetime: "2026-09-05T10:00:00.000Z",
        status: "PENDING_PROOF",
        inspection: null,
        createdAt: "2026-08-01T00:00:00.000Z",
        updatedAt: "2026-08-01T00:00:00.000Z",
      };

      mockGetByIdWithInspection.mockResolvedValue(mockReservation);

      const res = await testApp.request(
        `/reservations/${VALID_RESERVATION_ID}`,
        { headers: { Authorization: MOCK_JWT } },
      );

      expect(res.status).toBe(200);
      const body: any = await res.json();
      expect(body.guestName).toBe("John Doe");
      expect(body.inspection).toBeNull();

      expect(mockGetByIdWithInspection).toHaveBeenCalledWith(
        expect.any(Object),
        VALID_RESERVATION_ID,
      );
    });

    it("should 404 for a reservation that does not exist", async () => {
      mockGetById.mockResolvedValue(null);

      const res = await testApp.request(
        `/reservations/${VALID_RESERVATION_ID}`,
        { headers: { Authorization: MOCK_JWT } },
      );

      expect(res.status).toBe(404);

      const body: any = await res.json();
      expect(body.success).toBe(false);
      expect(body.error.code).toBe("RESERVATION_NOT_FOUND");

      // The lookup must short-circuit: no ownership check and no second read.
      expect(mockAssertApartmentOwnership).not.toHaveBeenCalled();
      expect(mockGetByIdWithInspection).not.toHaveBeenCalled();
    });

    it("should 403 when the reservation belongs to another host", async () => {
      mockGetById.mockResolvedValue({
        id: VALID_RESERVATION_ID,
        apartmentId: VALID_APARTMENT_ID,
      });
      mockAssertApartmentOwnership.mockRejectedValueOnce(
        new ForbiddenException({
          code: "FORBIDDEN_APARTMENT_ACCESS",
          message: "You do not have access to this apartment.",
          meta: { origin: "DOMAIN", apartmentId: VALID_APARTMENT_ID },
        }),
      );

      const res = await testApp.request(
        `/reservations/${VALID_RESERVATION_ID}`,
        { headers: { Authorization: MOCK_JWT } },
      );

      expect(res.status).toBe(403);

      const body: any = await res.json();
      expect(body.success).toBe(false);
      expect(body.error.code).toBe("FORBIDDEN_APARTMENT_ACCESS");

      expect(mockGetByIdWithInspection).not.toHaveBeenCalled();
    });
  });
```

The third case constructs the rejection with the **`ForbiddenException` class directly**, not through
`apartmentErrors`, because no `forbidden` thrower exists on that object (verified —
`src/modules/apartments/apartments.errors.ts` defines only `notFound`, `userNotFound`,
`locationNotFound`, `maxPhotos`). `ForbiddenException` takes `{ code, message, meta? }`
(`src/core/errors/error.exceptions.ts`), and `meta: { origin: "DOMAIN" }` matches what
`assertApartmentOwnership` passes for a real ownership failure.

**So the import must be added.** In the existing import block at the top of the test file, extend:

```ts
import { ForbiddenException } from "@/core/errors/error.exceptions";
```

Placed directly after the `import { apartmentErrors } from "../apartments/apartments.errors";` line.

passing. Plus `grep -c "GET /reservations/:id" src/modules/reservations/reservations.test.ts` → `1`
