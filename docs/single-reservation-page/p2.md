### Step 2.2 — Add the reservation query module

**Touch.** `src/lib/api/queries/reservation.ts` (create)

**Do.**

```ts
import { getReservationsById } from "@/api/generated/requests/sdk.gen";
import { withAuth } from "@/lib/api/api";
import { QUERY_ACTIONS } from "@/lib/api/queryKeys";
import { useQuery } from "@tanstack/react-query";
import { PREFETCH_STALE_TIME_MS } from "./shared";
import type { ResourceDefinition } from "./shared";

export interface ReservationParams {
  id: string;
}

export function reservationQueryKey(id: string) {
  return [...QUERY_ACTIONS.RESERVATIONS_GET_ID, id] as const;
}

export async function fetchReservation(id: string, signal?: AbortSignal) {
  const config = await withAuth(signal ? { signal } : {});
  const response = await getReservationsById({ ...config, path: { id } });
  return response.data;
}

/**
 * `enabled` lets the caller hold the request. The reservation page does not need it,
 * but keeping the parameter here means a future surface can gate the read without a
 * second hook.
 */
export function useReservation(id: string | undefined, enabled = true) {
  return useQuery({
    queryKey: reservationQueryKey(id ?? ""),
    queryFn: ({ signal }) => {
      if (!id) throw new Error("reservationIdRequired");
      return fetchReservation(id, signal);
    },
    enabled: Boolean(id) && enabled,
    staleTime: PREFETCH_STALE_TIME_MS,
  });
}

export const reservationResource: ResourceDefinition = {
  action: QUERY_ACTIONS.RESERVATIONS_GET_ID,
  key: ({ id }: ReservationParams) => reservationQueryKey(id),
  fetch: ({ id }: ReservationParams, { signal }) => fetchReservation(id, signal),
};
```

**Accept.** `grep -c "^export" src/lib/api/queries/reservation.ts` → `5` — the four exports above plus
`export interface ReservationParams`. (`grep -c "export function\|export const"` returns `4`; the
interface is an `export interface`, so it is a separate count. Use the `^export` count.)

**Verify.** The Accept command above. The module cannot compile in isolation — step 2.3 registers it.

### Step 2.3 — Register the resource

**Touch.** `src/lib/api/queries/registry.ts` (edit)

**Do.** Part (a): add a **new import line** for the new module, placed directly after the existing
`import { reservationsResource } from "./reservations";` line (line 5 of the current file):

```ts
import { reservationResource } from "./reservation";
```

`reservation.ts` is a new file and `reservations.ts` keeps exporting `reservationsResource`
unchanged — the two names differ by one letter, so this is the step most likely to be mis-typed as a
merge into the existing line. It is not a merge; it is a second import.

Part (b): add the entry to `QUERY_RESOURCES`, directly after `reservations`:

```ts
  reservations: reservationsResource,
  reservation: reservationResource,
```

**Do not reorder existing entries.** `manifest.ts`'s `resourceOwners()` resolves ownership by object
identity (`new Map(Object.entries(QUERY_RESOURCES)…)`), not by insertion order, so ordering here is
cosmetic — but a reorder inflates the diff and hides the one added line.

**Accept.** `grep -n "reservationResource" src/lib/api/queries/registry.ts` → exactly two matches: the
import line and the `reservation: reservationResource,` entry. Plus
`grep -c "Resource,$" src/lib/api/queries/registry.ts` → `10` (it is `9` before this step: the nine
entries in `QUERY_RESOURCES`). Plus `grep -n "reservationsResource" src/lib/api/queries/registry.ts`
→ still exactly two matches, unchanged — the existing resource was not renamed or absorbed.

**Verify.** The Accept command above.

### Step 2.4 — Register the hook in the manifest

**Touch.** `src/lib/api/queries/manifest.ts` (edit)

**Do.** Part (a): add the module namespace import alphabetically — `reservation` sorts before
`reservations`:

```ts
import * as reservation from "./reservation";
import * as reservations from "./reservations";
```

Part (b): add it to the `MODULES` object in the same order:

```ts
const MODULES = { admin, apartment, assets, inspection, reservation, reservations, shots } as const;
```

**Why both halves are mandatory (D7).** `collectHooks()` walks `MODULES`, and for every `useX` export
it looks up the resource name derived from the hook (`useReservation` → `reservation`) in the
ownership map built from `QUERY_RESOURCES`, then **throws at module load** if that resource is not
owned by the same module. Registering the resource without the module leaves the hook invisible, so
`prefetchCoverage.test.ts` would not see the page's read at all — a vacuous pass, which is exactly
what that check exists to prevent.

**Accept.** `grep -n "reservation" src/lib/api/queries/manifest.ts` → the import line and the
`MODULES` entry, and `npm run gate` → exit 0 (this is the first step at which the module compiles and
the manifest's load-time invariant is exercised)

**Verify.** `npm run gate`

### Step 2.5 — Declare the path and the route

**Touch.** `src/lib/router/paths.ts` (edit), `src/lib/router/routes/host.ts` (edit)

**Do.** Part (a) — `paths.ts`. Add the path definition to `appPaths`, directly after `hostApartment`
(D1):

```ts
  hostReservation: {
    pattern: "/host/apartments/:id/reservations/:reservationId",
    requires: ["canOpenHost"],
    params: { id: "uuid", reservationId: "uuid" },
  },
```

Part (b) — `routes/host.ts`. Add the route as a **sibling of `apartments/:id`** inside the `host`
section's `children`, directly after that entry:

```ts
    {
      // A SIBLING of apartments/:id, not a child of it — and this is load-bearing.
      // A child route renders into its parent's <Outlet />, and
      // IndividualApartment.tsx has no <Outlet /> (grep -rn "Outlet" src/ finds one
      // occurrence, in Shell.tsx). Nested as a child, this route's loader would run,
      // the URL would match, and the page would never mount — a blank screen that
      // still passes every gate check. The URL still NESTS because the pattern is
      // written out in full.
      path: "apartments/:id/reservations/:reservationId",
      params: { id: "uuid", reservationId: "uuid" },
      page: () => import("@/pages/host/ReservationPage"),
      // The inspection read is declared but resolves to null (D10): the photos are
      // loaded only when the host opens the control, and a declaration that returns
      // null is how this registry says "not on this navigation" (registry.ts).
      data: [
        { resource: "reservation", params: (params) => ({ id: String(params.reservationId) }) },
        { resource: "inspection", params: () => null },
      ],
      handle: { crumb: "reservationPage.title" },
    },
```

**Three things that will bite if done carelessly.**

1. **Both params are declared on this node.** A sibling inherits nothing from `apartments/:id`, so
   the declaration is `{ id: "uuid", reservationId: "uuid" }` — not the child's `{ reservationId }`.
   `assertParamsDeclared` throws at build time for a `:param` with no declared type, and
   `routes.test.ts` walks the tree asserting every pattern segment has one.
2. **The path definition's `params` must list exactly the same two keys.** `tree.test.ts` compares
   `Object.keys(definition.params)` against `Object.keys(guard.params)` for the matched pattern, and
   `definePaths`'s `ParamKeysMatch` type rejects either an undeclared `:param` or an extra key.
3. `tree.test.ts` also asserts the **rule sets match**. `requires: ["canOpenHost"]` is correct
   because the sibling inherits the `host` section's rule and declares no additional one; writing
   `["canOpenHost"]` in the path definition is the full inherited chain, matching `hostApartment`'s
   existing entry.

`ReservationPage` does not exist yet — it arrives in phase 5. The route's `page` is a lazy import
string, so this compiles now; the missing module would only be a build-time resolution error, and
`coverage.ts`'s `resolveAlias` **throws** if the specifier does not resolve to a file under `src/`.
**So step 2.5 also creates a placeholder page**, which phase 5 replaces:

```tsx
import { useTranslation } from "react-i18next";
import PageLayout from "@/components/layout/PageLayout";
import PageTitle from "@/components/PageTitle";

export default function ReservationPage() {
  const { t } = useTranslation("host");

  return (
    <PageLayout size="lg">
      <PageTitle title={t("reservationPage.title")} />
    </PageLayout>
  );
}
```

Write it to `src/pages/host/ReservationPage.tsx`. It reads no query hook, so it satisfies
`prefetchCoverage.test.ts` (which measures a page's reads against its route's declarations — zero
reads is trivially covered). Phase 5 step 5.6 replaces this file wholesale.

**Accept.** `npm run gate` → exit 0. Plus:
- `grep -n "hostReservation" src/lib/router/paths.ts` → 1 match
- `grep -n "reservations/:reservationId" src/lib/router/routes/host.ts` → 1 match
- `test -f src/pages/host/ReservationPage.tsx && echo present` → `present`

**Verify.** `npm run gate`

### Step 2.6 — Test the key and the shared cache entry

**Touch.** `src/lib/api/queries/reservation.test.ts` (create)

**Do.** Write the test in the shape `apartment.test.ts` already uses — mock the generated request and
`withAuth`, then assert the key's provenance and that a prefetch is reused by a read.

```ts
import { describe, expect, it, vi, beforeEach } from "vitest";
import { QueryClient } from "@tanstack/react-query";
import { reservationQueryKey, fetchReservation } from "./reservation";
import { QUERY_ACTIONS } from "@/lib/api/queryKeys";
import { appPaths } from "@/lib/router/paths";

vi.mock("@/api/generated/requests/sdk.gen", () => ({
  getReservationsById: vi.fn(async ({ path }: { path: { id: string } }) => ({
    data: { id: path.id, guestName: "Test Guest", inspection: null },
  })),
}));

vi.mock("@/lib/api/api", () => ({
  withAuth: vi.fn(async (extra: Record<string, unknown>) => ({
    baseUrl: "http://localhost/api",
    ...extra,
  })),
}));

const VALID_UUID = "3f2504e0-4f89-41d3-9a0c-0305e82c3301";

describe("reservationQueryKey", () => {
  it("is composed from the QUERY_ACTIONS registry entry, not a literal", () => {
    expect(reservationQueryKey(VALID_UUID)).toEqual([
      ...QUERY_ACTIONS.RESERVATIONS_GET_ID,
      VALID_UUID,
    ]);
  });

  it("differs per id, so two reservations are two cache entries", () => {
    expect(reservationQueryKey("a")).not.toEqual(reservationQueryKey("b"));
  });
});

describe("the prefetch and the page share one cache entry", () => {
  let client: QueryClient;

  beforeEach(() => {
    client = new QueryClient({
      defaultOptions: { queries: { retry: false } },
    });
    vi.clearAllMocks();
  });

  it("a prefetch is reused by a read of the same query, with one request", async () => {
    await client.prefetchQuery({
      queryKey: reservationQueryKey(VALID_UUID),
      queryFn: ({ signal }) => fetchReservation(VALID_UUID, signal),
      staleTime: 30_000,
    });

    const cached = client.getQueryData(reservationQueryKey(VALID_UUID));

    expect(cached).toEqual({
      id: VALID_UUID,
      guestName: "Test Guest",
      inspection: null,
    });

    const again = await client.fetchQuery({
      queryKey: reservationQueryKey(VALID_UUID),
      queryFn: ({ signal }) => fetchReservation(VALID_UUID, signal),
      staleTime: 30_000,
    });

    expect(again).toEqual(cached);

    const { getReservationsById } = await import(
      "@/api/generated/requests/sdk.gen"
    );
    expect(getReservationsById).toHaveBeenCalledTimes(1);
  });
});

describe("the path definition matches the route", () => {
  it("declares the full inherited rule chain", () => {
    expect(appPaths.hostReservation.requires).toEqual(["canOpenHost"]);
  });

  it("types both ids as uuids", () => {
    expect(appPaths.hostReservation.params).toEqual({
      id: "uuid",
      reservationId: "uuid",
    });
  });
});
```

**Accept.** `npm run gate` → exit 0, with `Test Files` up by one and the five new tests passing.

**Verify.** `npm run gate`

## Phase 2 invariants

- [ ] `src/api/generated/` is **not** hand-edited — `getReservationsById` came from `api:generate`
- [ ] The regenerated diff is part of **this** phase's changes, not phase 1's commit
- [ ] `RESERVATIONS_GET_ID` is used through `reservationQueryKey`, never as a literal
- [ ] `reservation.ts` is a **new** module; `reservations.ts` is unmodified and still exports `reservationsResource`
- [ ] The resource is registered in **both** `QUERY_RESOURCES` and the manifest's `MODULES` (D7)
- [ ] The `inspection` declaration resolves to `null`, so it starts no request (D10)
- [ ] `host.test.ts`'s "declares exactly four queries" for `apartments/:id` still passes — the new
      route is a **sibling**, so the parent's `data` array is unchanged
- [ ] The route is a sibling of `apartments/:id` in the `host` section's `children`, **not** a child
      of it (see the note in step 2.5: `IndividualApartment` has no `<Outlet />`, so a nested child
      would never render)
- [ ] Both `id` and `reservationId` are declared on the route node **and** in `appPaths.hostReservation`
- [ ] `tree.test.ts` and `paths.test.ts` pass; the path definition and the route landed together
- [ ] No new i18n key is introduced, except `reservationPage.title`, which the placeholder page uses
      and phase 4 adds to the locale files
- [ ] Network calls go through `withAuth()`

## Note for phase 4

`reservationPage.title` is referenced by the placeholder page in this phase but written to the locale
files in **phase 4** (step 4.7). Until then the placeholder renders the raw key. That is the same
two-phase copy pattern `docs/asset-type-change/00-index.md` recorded for its phases 1–2, and it is
harmless because the placeholder is not user-facing work — phase 5 replaces it. Do not add the key
here; keep the locale edits in the phase that owns `host.json`.
