# Phase 6 — the inspection guide page

**Prerequisite:** phase 5 (the guide path, its route and the placeholder page all landed in step 5.5).
**Gate:** `npm run gate`.

This phase replaces the guide placeholder with the real page and removes the modal it replaces. It
touches **no router file** — step 5.5 already landed `appPaths.inspectionGuide` and its route, for the
same reason phase 2 landed the reservation route with its path: `tree.test.ts` fails a path with no
route, and `coverage.ts` throws for a route whose page module does not resolve.

**Grouping.** 6.1 before 6.2 — 6.2's edit removes the dialog that 6.1's page takes over. 6.3 is the
copy plus the translation run, last.

---

### Step 6.1 — The guide page

**Touch.** `src/pages/InspectionGuidePage.tsx` (**replace** — the file exists as phase 5's placeholder)

**Do.** Replace the file's whole content with:

```tsx
import { useMemo } from "react";
import { useNavigate } from "react-router";
import { useTranslation } from "react-i18next";
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { toast } from "sonner";

import PageLayout from "@/components/layout/PageLayout";
import PageTitle from "@/components/PageTitle";
import { ApartmentShotGuide } from "@/components/host/ShotsGuide";
import { useReservation } from "@/lib/api/queries/reservation";
import { useShots } from "@/lib/api/queries/shots";
import { QUERY_ACTIONS } from "@/lib/api/queryKeys";
import { getProofWindowState } from "@/lib/helpers/proofWindow";
import { addClientId } from "@/lib/helpers/uuid";
import {
  submitInspectionPhotos,
  type CapturedApartmentShot,
} from "@/lib/api/submitPhotoProofs";
import { appPaths, buildPath, useRouteParams } from "@/lib/router";

/**
 * D2/D8: the capture flow as a page rather than a dialog.
 *
 * It is NOT under the `host` section and it is NOT public. Both reads it makes
 * come from URL params alone — `reservationId` for the reservation, `apartmentId`
 * for the shots — which is the whole reason D2 keeps `apartmentId` in the pattern:
 * declared that way, both requests start alongside the chunk instead of the shots
 * waiting on the reservation to resolve.
 */
export default function InspectionGuidePage() {
  const { t } = useTranslation("host");
  const navigate = useNavigate();
  const queryClient = useQueryClient();

  const { apartmentId, reservationId } = useRouteParams(
    appPaths.inspectionGuide,
  ) as { apartmentId: string; reservationId: string };

  const {
    data: reservation,
    isLoading: reservationLoading,
    isError: reservationError,
  } = useReservation(reservationId);

  const { data: shots = [], isLoading: shotsLoading } = useShots(apartmentId);

  const preparedShots = useMemo(() => addClientId(shots), [shots]);

  const reservationPath = buildPath(appPaths.hostReservation, {
    id: apartmentId,
    reservationId,
  });

  const submitMutation = useMutation({
    mutationFn: (completedShots: CapturedApartmentShot[]) =>
      submitInspectionPhotos({
        apartmentId,
        reservationId,
        shots: completedShots,
      }),
    onSuccess: () => {
      // The same pair the reservation page's own actions invalidate: the detail
      // entry (which now reads COVERED) and the list that shows its status chip.
      queryClient.invalidateQueries({
        queryKey: [...QUERY_ACTIONS.RESERVATIONS_GET_ID, reservationId],
      });
      queryClient.invalidateQueries({
        queryKey: [...QUERY_ACTIONS.RESERVATIONS_GET_BY_APARTMENT, apartmentId],
      });
      toast.success(t("inspectionGuidePage.toast.submitSuccess"));
      // D17's destination: the reservation the proofs belong to, which now renders
      // the "already submitted" state and the photo control.
      navigate(reservationPath);
    },
    // eslint-disable-next-line @typescript-eslint/no-explicit-any
    onError: (error: any) => {
      toast.error(
        error?.message || t("inspectionGuidePage.toast.submitError"),
      );
    },
  });

  const backToReservation = (
    <button
      type="button"
      onClick={() => navigate(reservationPath)}
      className="text-sm text-gray-500 hover:text-gray-700 dark:text-gray-400 dark:hover:text-gray-200 cursor-pointer transition-colors"
    >
      {t("inspectionGuidePage.backToReservation")}
    </button>
  );

  if (reservationLoading || shotsLoading) {
    return (
      <PageLayout size="lg">
        <PageTitle title={t("inspectionGuidePage.title")} />
        <div className="flex items-center gap-2 text-sm text-gray-500 dark:text-gray-400">
          <div className="h-5 w-5 animate-spin rounded-full border-2 border-gray-900 dark:border-gray-100 border-t-transparent" />
          {t("inspectionGuidePage.loading")}
        </div>
      </PageLayout>
    );
  }

  if (reservationError || !reservation) {
    return (
      <PageLayout size="lg">
        <PageTitle
          title={t("inspectionGuidePage.notFound.title")}
          subtitle={t("inspectionGuidePage.notFound.subtitle")}
        />
        {backToReservation}
      </PageLayout>
    );
  }

  // The refusal is explicit, not a silent redirect (the decisions file's "States"
  // section asks for exactly this). Invariant 9: the answer is the helper's, so the
  // page that refuses and the button that offered can never disagree.
  const window = getProofWindowState(reservation, Date.now());

  if (!window.canTakeShots) {
    return (
      <PageLayout size="lg">
        <PageTitle
          title={t("inspectionGuidePage.unavailable.title")}
          subtitle={t(
            window.state === "ALREADY_SUBMITTED"
              ? "inspectionGuidePage.unavailable.alreadySubmitted"
              : window.state === "EXPIRED"
                ? "inspectionGuidePage.unavailable.expired"
                : window.state === "NOT_STARTED"
                  ? "inspectionGuidePage.unavailable.notStarted"
                  : "inspectionGuidePage.unavailable.tooEarly",
          )}
        />
        {backToReservation}
      </PageLayout>
    );
  }

  return (
    <PageLayout size="lg">
      <PageTitle
        title={t("inspectionGuidePage.title")}
        subtitle={t("inspectionGuidePage.subtitle", {
          guestName: reservation.guestName,
        })}
      />

      <div className="mb-6">{backToReservation}</div>

      {/* Unchanged from the dialog it replaces: same component, same props. The
          flow needed no rewrite, only a URL. */}
      <ApartmentShotGuide
        initialShots={preparedShots}
        isSubmitting={submitMutation.isPending}
        onSubmit={(completedShots) => submitMutation.mutate(completedShots)}
      />
    </PageLayout>
  );
}
```

**`PageLayout size="lg"`** matches the reservation page this flow is reached from and returns to
(step 5.6), so navigating between them does not shift the content width. The dialog it replaces used
`size="xl"` (`IndividualApartment.tsx`, the `<Modal … size="xl">` block step 6.2 removes); the page is
deliberately narrower, because as a full page it no longer has to out-measure the content behind it.

**Both reads are covered by the route's `data` declaration** from step 5.5 — `reservation` from
`reservationId` and `shots` from `apartmentId` — so `prefetchCoverage.test.ts` passes and the page
performs no request of its own on a cold load. `ApartmentShotGuide` reads no query hook
(`ShotsGuide.tsx` takes only `initialShots` / `isSubmitting` / `onSubmit`), so it adds no coverage
obligation.

**`addClientId` is carried over verbatim** from the dialog's handler: `ShotsGuide` keys its internal
list by `_clientId`, and the flow predates this phase. `useMemo` on `shots` keeps the array stable so
the guide's internal `useState` initialiser is not re-run on every render.

**Refusal, not redirect.** The prep and the decisions file both ask for the page to say why it cannot
be used. A redirect would hide a genuine window state — a host who follows a stale link is better
served by "the proof window has closed" than by being bounced to a page that also does not explain it.

**Accept.** `npm run gate` → exit 0. Plus:
- `grep -c "useReservation\|useShots" src/pages/InspectionGuidePage.tsx` → `4` (two imports, two calls)
- `grep -c "getProofWindowState" src/pages/InspectionGuidePage.tsx` → `2` (the import and the call)
- `grep -c "useInspection" src/pages/InspectionGuidePage.tsx` → `0` — the guide captures, it does not
  read the detailed inspection
- `grep -c "ApartmentShotGuide" src/pages/InspectionGuidePage.tsx` → `2` (the import and the element)

**Verify.** `npm run gate`

## Halt conditions specific to this phase

- **`submitInspectionPhotos` fails with a 401 from the guide route.** It calls three write endpoints
  that all require a bearer token, which is why R3 rejected making this route `public`. A 401 here means
  the route's rule is wrong, not that the flow needs a token — check that step 5.5's
  `requires: "canOpenHost"` is present and that the route is inside `appRoutes` (which renders under the
  session) rather than `outsideRoutes`.
- **Removing the modal leaves a binding that is still referenced.** Stop and report: every symbol in the
  removed block was checked against the rest of the file, so a surviving reference means the file
  differs from the version this step was written against.
- **`prefetchCoverage.test.ts` reports a gap for the guide page.** The fix is a `data:` declaration on
  the route, **not** an `INTERACTION_GATED_HOOKS` entry (D10, R5) — and if the gap names a hook the page
  genuinely does not read, the import list is wrong instead.

## Noticed, untouched — expected entries for this phase

- `general.json`'s `apartmentPage.modal.inspectionTitle` and `.reservationFor` become dead copy once
  step 6.2 deletes their only consumer. Removing them is a locale edit in a namespace this feature does
  not otherwise touch, and an unused key is harmless — unlike an unused binding, which fails the gate.
- `IndividualApartment.tsx` still reads `useReservations` for the unmatched-assets banner and `useShots`
  for the studio. Both stay; the route declares both, so coverage is unaffected.
- The reservation page's Proof section and the table's kebab both navigate to the guide, and the guide
  refuses when the window has closed. That refusal is reachable by URL for a reservation that is not the
  host's only if the route's rule is ever loosened — which is the future guard's problem (D8), not this
  phase's.
