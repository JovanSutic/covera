# Phase 1 — Tooltip primitives

Prerequisite: none.
Gate: `npm run gate`

Closes prep §3 (tooltip clipped by the scrolling wrapper) and the mechanism for §4 (tooltips
absent on the copy button, wrong placement). The bar and the copy button themselves are phase 2.

Touches only the two shared primitives, so both consumers (the bar in p2, the proof section in
p3) inherit the fix without either phase fighting over the same JSX.

**No test step (D15).** This is presentational CSS: a jsdom render of an absolutely-positioned
box proves nothing about whether it is clipped, and the assertion would rot. The behaviour it
unlocks is tested by p2's menu test.

### Step 1.1 — Open the panel above the trigger

**Touch:** `src/components/shared/InfoTooltip.tsx`

**Do:** replace the panel `<span>` and its arrow `<span>`. The panel moves from `top-full mt-1.5`
to `bottom-full mb-1.5`; the arrow from the panel's top edge (`-top-1 … border-l border-t`) to
its bottom edge (`-bottom-1 … border-b border-r`), which is the corner a 45°-rotated square
presents downward.

```tsx
      <span className="pointer-events-none absolute bottom-full left-0 z-30 mb-1.5 hidden w-64 max-w-xs animate-in fade-in zoom-in-95 duration-150 group-hover/tooltip:block group-focus-within/tooltip:block">
        <span className="relative block rounded-xl border border-gray-800 bg-gray-900 p-3 text-xs font-normal text-gray-100 shadow-xl dark:border-gray-700 dark:bg-gray-950">
          <span className="absolute -bottom-1 left-2.5 h-2 w-2 rotate-45 border-b border-r border-gray-800 bg-gray-900 dark:border-gray-700 dark:bg-gray-950" />
```

Leave the rest of the component — the trigger `<button>`, the `group/tooltip` wrapper, the
`content` body — exactly as it is.

**Accept:** `grep -n "bottom-full mb-1.5" src/components/shared/InfoTooltip.tsx` → one match on
the panel span; `grep -c "top-full" src/components/shared/InfoTooltip.tsx` → `0`.

**Verify:** `npm run gate`

### Step 1.2 — Make the tooltip always-on and tighten the button↔tooltip gap

**Touch:** `src/components/shared/ActionButton.tsx`

**Do:** replace the component's `return` block. Two changes, both of them the point:

1. The `hidden sm:contents` width gate is deleted (invariant 11) — the tooltip renders at every
   width.
2. Button and tooltip become one flex item with a `gap-1`, so the gap to a button's *own*
   tooltip is visibly smaller than the row's gap to the *next* button (a `gap-3` the callers
   pass). Under `contents` the row's gap applied to both and they read as equal — which is
   exactly what prep §4 asks to fix.

```tsx
  return (
    <span className="inline-flex shrink-0 items-center gap-1">
      <button
        type={type}
        disabled={disabled || loading}
        className={cn(actionButtonVariants({ variant, size }), className)}
        {...props}
      >
        {icon}
        <span>{label}</span>
        {loading && <Loader2 className="h-4 w-4 shrink-0 animate-spin" />}
      </button>

      {tooltip && (
        // Invariant 11: no width gate. The panel is absolutely positioned, so the
        // surfaces that host it must not clip it — that is the host's job, not this
        // component's (see `ReservationActionsBar`).
        <InfoTooltip content={tooltip} label={tooltipLabel ?? label} />
      )}
    </span>
  );
```

Then update the component's doc comment: the paragraph beginning "The rendered shape is a
fragment so this stays ONE flex item's worth of layout." is now false. Replace that line with:

```
 * The rendered shape is one flex item — button and its own tooltip, `gap-1` apart — so a
 * button's tooltip reads as belonging to it rather than to its neighbour.
```

**Accept:** `grep -c "hidden sm:contents" src/components/shared/ActionButton.tsx` → `0`;
`grep -c "inline-flex shrink-0 items-center gap-1" src/components/shared/ActionButton.tsx` → `1`.

**Verify:** `npm run gate`
