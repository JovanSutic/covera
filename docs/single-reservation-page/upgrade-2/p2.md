# Phase 2 — Delete from the table, and one rule table for both surfaces

Prerequisite: Phase 1 (p1) complete and committed.
Gate: `npm run gate`

Closes prep §1, §6, §7 — and carries §2 (delete loses its tooltip).

Read `../upgrade-2.md` §"Corrections" first. Prep §1's stated cause is wrong: the menu **already**
uses `ConfirmButton`. The real cause was verified by experiment during planning (step 2.2
reproduces it):

`PopoverContent` renders through `createPortal` into `document.body`. React propagates synthetic
events through the **React** tree, not the DOM tree, so a click on a menu row reaches the
`DataTable` row's `onClick` — while `event.target.closest("[data-row-click-stop]")` searches the
real DOM and finds nothing, because the clicked node is a child of `<body>` rather than of the
cell that carries the attribute. `AssetItemCard`'s confirm step does not portal and so never had
this problem, which is why the pattern worked there and not here.

Prep §6 is also incomplete: the backend requires `COVERED` **and** `hasPhotoProof`
(`covera-hono/src/core/utils/db-validator.ts` → `assertCanCreateInspection`). D2 matches it.

### Step 2.1 — The portal carries the row-click opt-out

**Touch:** `src/components/Popover.tsx`

**Do:** in `PopoverContent`'s `createPortal` call, add `data-row-click-stop` to the portalled
`<div>`, between `style` and `className`:

```tsx
    <div
      ref={popoverRef}
      style={{
        position: "absolute",
        top: `${coords.top}px`,
        left: `${coords.left}px`,
      }}
      // Invariant 12, and the fix for prep §1. A popover inside a clickable row must not
      // navigate that row. `DataTable` checks `event.target.closest(...)`, which walks the
      // real DOM — so the opt-out has to be on the PORTAL, not on the component that
      // renders the trigger. React bubbles this click through the React tree from
      // `document.body` up to the `DataTable` row, and without this attribute that
      // `closest()` call finds nothing and the row navigates.
      //
      // It is safe to put it here rather than at each call site: the attribute is inert
      // everywhere except inside `DataTable`'s row handler, and a caller that wants the
      // row to navigate can override it through `{...props}` below.
      data-row-click-stop
      className={`z-9999 rounded-xl bg-white dark:bg-gray-900 border border-gray-200 dark:border-gray-800 shadow-2xl p-4 ${className}`}
      {...props}
    >
```

### Step 2.3 — The rule table

**Touch:** `src/lib/helpers/reservationActions.ts` (new)

**Do:** create the file with exactly this content. It is pure: no React, and no clock of its own —
`now` is a parameter and the window comes from `getProofWindowState` (invariant 10).

```ts
import { getProofWindowState } from "@/lib/helpers/proofWindow";
import type { ProofWindowSubject } from "@/lib/helpers/proofWindow";

/**
 * D10: the ONE rule table for the three reservation actions, shared by the page's
 * `ReservationActionsBar` and the table's `ReservationActionsMenu`. Before this the two
 * surfaces each spelled the rules out inline, which is how the table's menu ended up
 * hiding rows the bar disabled, and how the create-inspection button ended up offering
 * an action the backend refuses.
 *
 * The tooltips are i18n KEYS, resolved by the caller's `t()` — the same convention
 * `reservationDates.ts` uses.
 *
 * Every key is returned even when the action is enabled: the tooltip is also the
 * explanation of what the button does. Only `delete` has none (prep §2: deleting is
 * self-explanatory, and a tooltip that only ever says "delete" is noise).
 */
export interface ActionAvailability {
  enabled: boolean;
  /** One of the `reservationPage.actions.tooltip.*` keys. Absent for `delete`. */
  tooltipKey?: string;
}

export interface ReservationActionAvailability {
  createInspection: ActionAvailability;
  copyMessage: ActionAvailability;
  delete: ActionAvailability;
}

export interface ReservationActionParams {
  reservation: ProofWindowSubject;
  /** The guest-inspection id, when one exists. */
  inspectionId?: string | null;
  /** Captured once by the caller at render (invariant 10). */
  now: number;
}

const TOOLTIP = {
  createInspection: "reservationPage.actions.tooltip.createInspection",
  hasInspection: "reservationPage.actions.tooltip.hasInspection",
  notCovered: "reservationPage.actions.tooltip.notCovered",
  noPhotoProof: "reservationPage.actions.tooltip.noPhotoProof",
  copyGuestMessage: "reservationPage.actions.tooltip.copyGuestMessage",
  noInspection: "reservationPage.actions.tooltip.noInspection",
  copyNotCovered: "reservationPage.actions.tooltip.copyNotCovered",
  past: "reservationPage.actions.tooltip.actionPast",
} as const;

export function getReservationActionAvailability({
  reservation,
  inspectionId,
  now,
}: ReservationActionParams): ReservationActionAvailability {
  const window = getProofWindowState(reservation, now);

  const hasInspection = Boolean(inspectionId);
  const isCovered = reservation.status === "COVERED";
  const hasPhotoProof = Boolean(reservation.hasPhotoProof);

  // D8 / prep §7: every action dies at the EFFECTIVE check-in. `getProofWindowState` has
  // already resolved the alternative-over-plain precedence, so this is not a second
  // derivation and cannot disagree with the proof window's own answer.
  const isPast = window.checkInTime === null || window.checkInTime <= now;

  // D2: exactly the backend's guard for POST /inspections
  // (`covera-hono/src/core/utils/db-validator.ts` `assertCanCreateInspection`), so an
  // enabled button cannot produce a 400.
  const canCreateInspection = !isPast && !hasInspection && isCovered && hasPhotoProof;

  // D7 / prep §7: present but disabled without a link, and without COVERED.
  const canCopyMessage = !isPast && hasInspection && isCovered;

  // Unchanged rule: deleting is allowed strictly before the effective check-in.
  const canDelete = !isPast;

  return {
    createInspection: {
      enabled: canCreateInspection,
      tooltipKey: isPast
        ? TOOLTIP.past
        : hasInspection
          ? TOOLTIP.hasInspection
          : !isCovered
            ? TOOLTIP.notCovered
            : !hasPhotoProof
              ? TOOLTIP.noPhotoProof
              : TOOLTIP.createInspection,
    },
    copyMessage: {
      enabled: canCopyMessage,
      tooltipKey: isPast
        ? TOOLTIP.past
        : !hasInspection
          ? TOOLTIP.noInspection
          : !isCovered
            ? TOOLTIP.copyNotCovered
            : TOOLTIP.copyGuestMessage,
    },
    // No `tooltipKey` — prep §2.
    delete: { enabled: canDelete },
  };
}
```

call).

### Step 2.4 — Test the rule table

**Touch:** `src/lib/helpers/reservationActions.test.ts` (new)

**Do:** create the file with exactly this content. Follows `proofWindow.test.ts`'s style: a fixed
`NOW`, a builder for the subject, and assertions on the returned keys — this helper returns keys

```ts
import { describe, expect, it } from "vitest";

import { getReservationActionAvailability } from "./reservationActions";

const NOW = new Date("2026-06-01T10:00:00.000Z").getTime();
const HOUR = 60 * 60 * 1000;

/** A covered, photo-backed reservation checking in a day from `NOW`. */
function subject(overrides: Record<string, unknown> = {}) {
  return {
    checkInDatetime: new Date(NOW + 24 * HOUR).toISOString(),
    checkOutDatetime: new Date(NOW + 96 * HOUR).toISOString(),
    alternativeCheckInDatetime: null,
    alternativeCheckOutDatetime: null,
    status: "COVERED",
    hasPhotoProof: true,
    ...overrides,
  };
}

const rule = (overrides = {}, inspectionId: string | null = null) =>
  getReservationActionAvailability({
    reservation: subject(overrides),
    inspectionId,
    now: NOW,
  });

describe("create inspection link", () => {
  it("enables for a covered, photo-backed reservation with no link yet", () => {
    const result = rule();
    expect(result.createInspection.enabled).toBe(true);
    expect(result.createInspection.tooltipKey).toBe(
      "reservationPage.actions.tooltip.createInspection",
    );
  });

  it("disables once a link exists, and says so", () => {
    const result = rule({}, "inspection-1");
    expect(result.createInspection.enabled).toBe(false);
    expect(result.createInspection.tooltipKey).toBe(
      "reservationPage.actions.tooltip.hasInspection",
    );
  });

  it("disables while the reservation is not COVERED", () => {
    const result = rule({ status: "PENDING_PROOF" });
    expect(result.createInspection.enabled).toBe(false);
    expect(result.createInspection.tooltipKey).toBe(
      "reservationPage.actions.tooltip.notCovered",
    );
  });

  it("disables without a satisfied photo proof, which the backend also refuses", () => {
    const result = rule({ hasPhotoProof: false });
    expect(result.createInspection.enabled).toBe(false);
    expect(result.createInspection.tooltipKey).toBe(
      "reservationPage.actions.tooltip.noPhotoProof",
    );
  });

  it("reports the past reason ahead of every other reason", () => {
    const result = rule(
      {
        checkInDatetime: new Date(NOW - HOUR).toISOString(),
        status: "PENDING_PROOF",
        hasPhotoProof: false,
      },
      "inspection-1",
    );
    expect(result.createInspection.enabled).toBe(false);
    expect(result.createInspection.tooltipKey).toBe(
      "reservationPage.actions.tooltip.actionPast",
    );
  });
});

describe("copy guest message", () => {
  it("enables only with a link, COVERED, and before check-in", () => {
    expect(rule({}, "inspection-1").copyMessage.enabled).toBe(true);
  });

  it("disables without a link, and explains why", () => {
    const result = rule();
    expect(result.copyMessage.enabled).toBe(false);
    expect(result.copyMessage.tooltipKey).toBe(
      "reservationPage.actions.tooltip.noInspection",
    );
  });

  it("disables when the reservation is not COVERED", () => {
    const result = rule({ status: "PENDING_PROOF" }, "inspection-1");
    expect(result.copyMessage.enabled).toBe(false);
    expect(result.copyMessage.tooltipKey).toBe(
      "reservationPage.actions.tooltip.copyNotCovered",
    );
  });
});

describe("the effective check-in is the deadline, not the plain one", () => {
  it("keeps the actions alive when a LATER alternative check-in is still ahead", () => {
    // The plain check-in has passed; the alternative pushes it into the future, which is
    // the whole reason prep §7 says the alternative wins.
    const result = rule({
      checkInDatetime: new Date(NOW - HOUR).toISOString(),
      alternativeCheckInDatetime: new Date(NOW + 2 * HOUR).toISOString(),
    });

    expect(result.delete.enabled).toBe(true);
    expect(result.createInspection.enabled).toBe(true);
  });

  it("kills them once the alternative itself has passed", () => {
    const result = rule({
      checkInDatetime: new Date(NOW + 5 * HOUR).toISOString(),
      alternativeCheckInDatetime: new Date(NOW - HOUR).toISOString(),
    });

    expect(result.delete.enabled).toBe(false);
    expect(result.createInspection.enabled).toBe(false);
    expect(result.copyMessage.enabled).toBe(false);
  });

  it("disables everything when there is no usable check-in at all", () => {
    const result = rule({ checkInDatetime: null });
    expect(result.delete.enabled).toBe(false);
    expect(result.copyMessage.enabled).toBe(false);
    expect(result.createInspection.enabled).toBe(false);
  });
});

describe("delete", () => {
  it("carries no tooltip — deleting is self-explanatory (prep §2)", () => {
    expect(rule().delete.tooltipKey).toBeUndefined();
  });

  it("is enabled before the effective check-in regardless of status", () => {
    expect(rule({ status: "PENDING_PROOF" }).delete.enabled).toBe(true);
    expect(rule({ status: "RESOLVED" }).delete.enabled).toBe(true);
  });
});
```

```tsx
interface ReservationActionsMenuProps {
  reservation: ReservationRow;
  apartmentId: string;

/**

 * enabled row shows the pointer, and a disabled one shows `cursor-not-allowed` and no
 * hover background.

 * deleting — was NOT the confirmation step, which `ConfirmButton` already provided. It

 * the shared rule table, which is what stops this menu and the page's bar disagreeing.

const ITEM_CLASSES =
  "w-full flex items-center gap-2.5 px-3 py-2 text-sm text-left text-gray-700 dark:text-gray-300 hover:bg-gray-50 dark:hover:bg-gray-800 disabled:opacity-40 disabled:cursor-not-allowed disabled:hover:bg-transparent cursor-pointer transition-colors";

                popover around it. */}

              <Popover>
                <PopoverTrigger>

                    type="button"
                    title={t(rules.copyMessage.tooltipKey ?? "")}

                type="button"
                disabled
                title={t(rules.copyMessage.tooltipKey ?? "")}
                className={ITEM_CLASSES}
              >
                <LinkIcon className="w-4 h-4 shrink-0" />
                {t("reservationActionsMenu.copyGuestMessage")}
              </button>
            )}

            {/* Delete is the one row that keeps its confirmation step, the shared
                primitive (D3). `ConfirmButton` renders the row itself as the trigger and

              confirmLabel={t("reservationActionsCell.confirm.deleteLabel")}
              cancelLabel={t("reservationPage.actions.confirmCancel")}

                type="button"
                disabled={!rules.delete.enabled}
                className={ITEM_CLASSES}

              </button>

      </Popover>
    </div>
  );
}
```

```tsx
import { ActionButton } from "@/components/shared/ActionButton";
import { ConfirmButton } from "@/components/shared/ConfirmButton";
import { Popover, PopoverContent, PopoverTrigger } from "@/components/Popover";
import { GuestInspectionMessage } from "./GuestInspectionMessage";
import { useReservationActions } from "@/hooks/useReservationActions";
import type { UseReservationActionsParams } from "@/hooks/useReservationActions";

interface ReservationActionsBarProps {
  reservation: UseReservationActionsParams["reservation"];
  apartmentId: string;
  inspectionId: string | null;
  onDeleted: () => void;
}

/**
 * The reservation page's general actions (prep §3, D17): three actions, one shape each,
 * all rendered through `ActionButton`, with delete going through `ConfirmButton`.
 *
 * The row WRAPS rather than scrolls. `overflow-x-auto` was doing two bad things:
 * introducing the scrollbar prep §3 reports, and clipping the absolutely-positioned
 * tooltip panels back to the strip's box — exactly the "confined with the wrapper"
 * complaint. Wrapping removes the clip and the scrollbar together.
 *
 * Every enable rule and every tooltip reason comes from
 * `getReservationActionAvailability` (D10) — the same table the table's menu reads.
 *
 * Delete carries no tooltip (prep §2): it is self-explanatory, and the info dot beside it
 * was noise. Every OTHER button's tooltip is the reason it is unavailable, or what it
 * does when it is.
 */
export function ReservationActionsBar({
  reservation,
  apartmentId,
  inspectionId,
  onDeleted,
}: ReservationActionsBarProps) {
  const { t } = useTranslation("host");

  const { rules, guestInspectionUrl, deleteMutation, createInspectionMutation } =
    useReservationActions({
      reservation,
      apartmentId,
      inspectionId,
      onDeleted,
    });

  const createLabel = t("reservationPage.actions.createInspection");
  const copyLabel = t("reservationPage.actions.copyGuestMessage");
  const deleteLabel = t("reservationPage.actions.delete");

  return (
    <div className="flex flex-wrap items-center gap-3">
      {/* D18: the confirmation step is retained from the previous plan; only the
          trigger's appearance changes — and `variant="success"` is why this confirm step
          is emerald rather than the delete pattern's rose (D32). */}
      <ConfirmButton
        className="shrink-0"
        variant="success"
        confirmLabel={t("reservationActionsCell.confirm.createLabel")}
        cancelLabel={t("reservationPage.actions.confirmCancel")}
        icon={<ClipboardPlus className="h-3 w-3" />}
        isLoading={createInspectionMutation.isPending}
        disabled={!rules.createInspection.enabled}
        onConfirm={() => createInspectionMutation.mutateAsync()}
      >
        <ActionButton
          variant="neutral"
          size="md"
          className="shrink-0"
          icon={<ClipboardPlus className="w-4 h-4 shrink-0" />}
          label={createLabel}
          disabled={!rules.createInspection.enabled}
          tooltip={t(rules.createInspection.tooltipKey ?? "")}
          tooltipLabel={createLabel}
        />
      </ConfirmButton>

      {/* The copy button is ALWAYS rendered (prep §7). A disabled button inside
          `PopoverTrigger` would still open the popover — the trigger div is the click
          target — so an unavailable copy action renders the same button outside one. */}
      {rules.copyMessage.enabled ? (
        <Popover>
          <PopoverTrigger>
            <ActionButton
              variant="neutral"
              size="md"
              className="shrink-0"
              icon={<LinkIcon className="w-4 h-4 shrink-0" />}
              label={copyLabel}
              tooltip={t(rules.copyMessage.tooltipKey ?? "")}
              tooltipLabel={copyLabel}
            />
          </PopoverTrigger>
          <PopoverContent align="left">
            <GuestInspectionMessage
              guestName={reservation.guestName}
              guestInspectionUrl={guestInspectionUrl}
            />
          </PopoverContent>
        </Popover>
      ) : (
        <ActionButton
          variant="neutral"
          size="md"
          className="shrink-0"
          icon={<LinkIcon className="w-4 h-4 shrink-0" />}
          label={copyLabel}
          disabled
          tooltip={t(rules.copyMessage.tooltipKey ?? "")}
          tooltipLabel={copyLabel}
        />
      )}

      {/* D4: styled exactly like the others — safety comes from the confirmation step,
          not from colour. NO tooltip (prep §2). `variant` defaults to `danger` on
          `ConfirmButton`, so the step itself is rose. */}
      <ConfirmButton
        className="shrink-0"
        confirmLabel={t("reservationActionsCell.confirm.deleteLabel")}
        cancelLabel={t("reservationPage.actions.confirmCancel")}
        icon={<Trash2 className="h-3 w-3" />}
        isLoading={deleteMutation.isPending}
        disabled={!rules.delete.enabled}
        onConfirm={() => deleteMutation.mutateAsync()}
      >
        <ActionButton
          variant="neutral"
          size="md"
          className="shrink-0"
          icon={<Trash2 className="w-4 h-4 shrink-0" />}
          label={deleteLabel}
          disabled={!rules.delete.enabled}
        />
      </ConfirmButton>
    </div>
  );
}
```

**Accept:** `grep -n "overflow-x-auto" src/components/host/ReservationActionsBar.tsx` → **one**
match, and it is line 22, the doc comment explaining why wrapping replaced it — there is no
`overflow-x-auto` in any `className` (baseline: one, in the root `className`);
`grep -c "tooltip={t(rules" src/components/host/ReservationActionsBar.tsx` → `3`, which is the
create button plus the copy button's **two** renderings (enabled and disabled) — delete
contributes none, which is the change worth checking.
