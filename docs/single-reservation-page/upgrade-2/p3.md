# Phase 3 — The photo-proofs control is enabled whenever photos exist

Prerequisite: Phase 1 (p1) complete and committed — this phase renders `ActionButton`, whose
shape p1 changes.
Gate: `npm run gate`

Closes prep §5.

The prep's ask has two halves. The first — "always enabled if there are photos" — is already what
`photoCount > 0` does. The second — "or let's say if this reservation is covered" — is the gap:
`COVERED` means proof was satisfied (`src/lib/api/submitPhotoProofs.ts` sets `hasPhotoProof` and
`status: "COVERED"` together), so a covered reservation must enable this control **even while the
inspection read is still in flight**. That is D9.

Nothing else in the section changes: the controls stay always-present (prep §4), one control per
action, and the explanation stays in the body line rather than on a tooltip.

---

### Step 3.1 — Widen the enable rule

**Touch:** `src/components/host/ReservationProofSection.tsx`

**Do:** replace this line:

```ts
  const canViewPhotos = photoCount > 0;
```

with:

```ts
  // D9 / prep §5: photos exist, OR the reservation is COVERED — which means the backend
  // already recorded a satisfied photo proof, so the photos are there to look at even
  // while the inspection read is still in flight. `status` is already a prop, so this
  // adds no request and no second clock.
  const canViewPhotos = photoCount > 0 || reservation.status === "COVERED";
```

Then update the component's doc comment: after the paragraph ending "which is the layout shift
the prep asks to remove.", add:

```
 * The photo control is enabled when photos exist OR the reservation is COVERED (D9) —
 * the second half of prep §5, and the reason a host returning from the inspection guide
 * sees an enabled control immediately rather than a disabled one waiting on a refetch.
```

**Accept:** `grep -n "photoCount > 0 || reservation.status" src/components/host/ReservationProofSection.tsx`
→ one match.

**Verify:** `npm run gate`

### Step 3.2 — The test for the covered-without-photos case

**Touch:** `src/pages/host/ReservationPage.test.tsx`

**Do:** the file's existing `reservation()` builder already accepts `overrides`, so no fixture
change is needed. Add this test inside the existing `describe("ReservationPage", ...)` block,
after the `"enables the photo control once there are active photos, and reports the count"` case:

```tsx
  it("enables the photo control for a COVERED reservation before the photos resolve", () => {
    // Prep §5's second half. The inspection read is deliberately left with no data:
    // COVERED is the backend's own statement that the proof was satisfied, so the
    // control must not sit disabled waiting for a refetch to agree.
    useReservation.mockReturnValue({
      data: reservation({ status: "COVERED", hasPhotoProof: true }),
      isLoading: false,
      isError: false,
    });
    useInspection.mockReturnValue({ data: undefined, isLoading: false, isError: false });

    render(<ReservationPage />, { wrapper: Wrapper });

    expect(
      screen.getByRole("button", { name: "reservationPage.proof.viewProofs" }),
    ).not.toBeDisabled();
  });
```

**Accept:** `npx vitest run src/pages/host/ReservationPage.test.tsx` → all tests pass, including
the new case.

**Verify:** `npx vitest run src/pages/host/ReservationPage.test.tsx`
