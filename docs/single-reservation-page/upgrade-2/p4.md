# Phase 4 — Alternative check-in/out capped at booked + 8h

Prerequisite: none. Independent of p1–p3 and may run first.
Gate: `npm run gate`

Closes prep §8: "People can be late but not more than 8h … it shouldn't be able to add new date
time that is more than 8h more than the regular check in or check out. and the values in the
date input should also permit this as well."

Two enforcements, both required by that last sentence: the zod schema (which produces the error
message) and the input's `max` attribute (which stops the picker offering the date at all).

D13 replaces the exported schema **const** with a factory, because the cap needs the booked times
as input. The alternative was a second parallel schema for this one rule — the drift the schema
was extracted to prevent. The factory keeps exactly one definition.

Scope is the reservation page's editor only (operator decision); `CreateReservationForm` has its
own inline copy of these rules and is not touched.

### Step 4.1 — Cap support in the validations module

**Touch:** `src/lib/validations/reservationDates.ts`

**Do:** three edits.

**1.** Add the message keys. In `ALTERNATIVE_DATE_MESSAGE_KEYS`, after
`altCheckInFuture`/`altCheckOutFuture`:

```ts
  altCheckInTooLate: "reservationPage.validation.altCheckInTooLate",

```

**2.** Add the cap constant and predicate, above `alternativeDatesSchema`:

```ts
/** D14: how far past the booked time an alternative may move a stay. */
export const ALTERNATIVE_MAX_LATENESS_HOURS = 8;

/**
 * D14: the cap, as an epoch-ms instant. Returns `null` when the booked value is missing or
 * unparseable — an unknown baseline cannot produce a bound, and inventing one would either
 * block every alternative or permit every one.
 */
export function latestAlternativeTime(
  bookedDatetime: string | null | undefined,
): number | null {
  if (!bookedDatetime) return null;

  const booked = new Date(bookedDatetime).getTime();
  if (!Number.isFinite(booked)) return null;

  return booked + ALTERNATIVE_MAX_LATENESS_HOURS * 60 * 60 * 1000;
}

/**
 * The same bound as a `datetime-local` value for the input's `max` attribute (prep §8:
 * "the values in the date input should also permit this as well"). `null` when there is no
 * baseline, which the caller renders as "no `max`".
 */
export function latestAlternativeLocalValue(
  bookedDatetime: string | null | undefined,
): string | null {
  const latest = latestAlternativeTime(bookedDatetime);
  if (latest === null) return null;

  return toDatetimeLocalValue(new Date(latest).toISOString());
}
```

**3.** Replace the `alternativeDatesSchema` const with the factory. Delete the whole
`export const alternativeDatesSchema = z.object({...}).refine({...});` block, and put this in its
place:

```ts
/**
 * D13: the schema is built per-reservation, because the 8h cap (D14) is measured from the
 * BOOKED times and those only exist once the reservation is loaded. A module-level const
 * could not see them.
 *
 * The cap is applied per field, before the pairing refine, so a too-late check-out is
 * reported against the field the host typed in rather than against the pair.
 */
export function createAlternativeDatesSchema({
  checkInDatetime,
  checkOutDatetime,
}: {
  checkInDatetime: string | null | undefined;
  checkOutDatetime: string | null | undefined;
}) {
  const optionalBoundedDatetime = (
    booked: string | null | undefined,
    futureKey: string,
    tooLateKey: string,
  ) =>
    z
      .string()
      .optional()
      .refine((value) => !value || isFutureDatetime(value), futureKey)
      .refine((value) => {
        if (!value) return true;

        const latest = latestAlternativeTime(booked);
        // No usable baseline: the future rule above is the only bound available.
        if (latest === null) return true;

        const parsed = new Date(value).getTime();
        // An unparseable date is the future rule's failure, not this one's.
        if (!Number.isFinite(parsed)) return true;

        return parsed <= latest;
      }, tooLateKey);

  return z
    .object({
      alternativeCheckInDatetime: optionalBoundedDatetime(
        checkInDatetime,
        ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckInFuture,
        ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckInTooLate,
      ),
      alternativeCheckOutDatetime: optionalBoundedDatetime(
        checkOutDatetime,
        ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckOutFuture,
        ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckOutTooLate,
      ),
    })
    .refine(
      (data) => {
        // Only a COMPLETE pair can be ordered. One field alone is legal: a host may
        // record a new check-in now and the check-out later.
        if (
          !data.alternativeCheckInDatetime ||
          !data.alternativeCheckOutDatetime
        ) {
          return true;
        }

        return isAfterDatetime(
          data.alternativeCheckOutDatetime,
          data.alternativeCheckInDatetime,
        );
      },
      {
        message: ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckOutAfterAltCheckIn,
        path: ["alternativeCheckOutDatetime"],
      },
    );
}

export type AlternativeDatesSchema = ReturnType<
  typeof createAlternativeDatesSchema
>;

/** Unchanged name and shape: the form is still typed off the schema's inferred output. */
export type AlternativeDatesValues = z.infer<AlternativeDatesSchema>;
```

Delete the now-unused `optionalFutureDatetime` helper (the factory's `optionalBoundedDatetime`
replaces it). Keep `isFutureDatetime`, `isAfterDatetime`, `toDatetimeLocalValue`,
`fromDatetimeLocalValue` and `checkInFuture` unchanged.

The old `export type AlternativeDatesValues = z.infer<typeof alternativeDatesSchema>;` line is
replaced by the redefined type in the block above — that is deliberately the only change to it,
so `ReservationTimeSection`'s five uses of the name keep compiling untouched (verified: `z.infer`
accepts a function's return type in zod 4).

Note: `toDatetimeLocalValue` is defined *below* where `latestAlternativeLocalValue` now sits.
Function declarations hoist, so this is fine — but if eslint reports `no-use-before-define`, move
`latestAlternativeLocalValue` to the bottom of the file instead of changing the helper.

**Accept:** `npx tsc -b` exits 0.
`grep -c "export const alternativeDatesSchema" src/lib/validations/reservationDates.ts` → `0`.
`grep -c "createAlternativeDatesSchema" src/lib/validations/reservationDates.ts` → `1`.

**Verify:** `npx tsc -b`

### Step 4.2 — Migrate the existing tests and cover the cap

**Touch:** `src/lib/validations/reservationDates.test.ts`

**Do:** the schema is no longer a const, so every construction changes. Two edits.

**1.** Replace the constants and add a builder, just below the imports:

```ts
const FUTURE = "2099-01-01T10:00";
const FUTURE_LATER = "2099-01-05T10:00";
const PAST = "2020-01-01T10:00";

/** Booked times chosen so the pre-existing fixtures stay legal: FUTURE is 6h after
 *  BOOKED_IN, inside the 8h cap D14 adds. */
const BOOKED_IN = "2099-01-01T04:00";
const BOOKED_OUT = "2099-01-05T04:00";

const schema = () =>
  createAlternativeDatesSchema({
    checkInDatetime: BOOKED_IN,
    checkOutDatetime: BOOKED_OUT,
  });
```

**2.** Replace every use of `alternativeDatesSchema` with `schema()`, and the type annotation
`ReturnType<typeof alternativeDatesSchema.safeParse>` in `firstMessage` with
`ReturnType<ReturnType<typeof createAlternativeDatesSchema>["safeParse"]>`. Update the import to
bring in `createAlternativeDatesSchema` and drop `alternativeDatesSchema`.

**3.** Add this `describe` block at the end of the file:

```ts
describe("the 8h lateness cap (prep §8)", () => {
  it("accepts an alternative exactly 8h after the booked time", () => {
    const result = schema().safeParse({
      alternativeCheckInDatetime: "2099-01-01T12:00",
      alternativeCheckOutDatetime: "2099-01-05T12:00",
    });

    expect(result.success).toBe(true);
  });

  it("rejects a check-in more than 8h late, pinned to the check-in field", () => {
    const result = schema().safeParse({
      alternativeCheckInDatetime: "2099-01-01T12:01",
      alternativeCheckOutDatetime: "",
    });

    expect(result.success).toBe(false);
    expect(result.success ? [] : result.error.issues.map((i) => i.path.join("."))).toEqual([
      "alternativeCheckInDatetime",
    ]);
    expect(firstMessage(result)).toBe(
      ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckInTooLate,
    );
  });

  it("rejects a check-out more than 8h late, pinned to the check-out field", () => {
    const result = schema().safeParse({
      alternativeCheckInDatetime: "",
      alternativeCheckOutDatetime: "2099-01-05T12:01",
    });

    expect(result.success).toBe(false);
    expect(firstMessage(result)).toBe(
      ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckOutTooLate,
    );
  });

  it("bounds each field against its OWN booked time, not the other's", () => {
    // 2099-01-03T12:00 is far past the check-in's cap and well inside the check-out's.
    expect(
      schema().safeParse({
        alternativeCheckInDatetime: "",
        alternativeCheckOutDatetime: "2099-01-03T12:00",
      }).success,
    ).toBe(true);
  });

  it("imposes no cap when the booked time is missing or corrupt", () => {
    const unbounded = createAlternativeDatesSchema({
      checkInDatetime: null,
      checkOutDatetime: "not-a-date",
    });

    expect(
      unbounded.safeParse({
        alternativeCheckInDatetime: "2099-06-01T10:00",
        alternativeCheckOutDatetime: "",
      }).success,
    ).toBe(true);
  });

  it("reports the future rule, not the cap, for a date that is merely in the past", () => {
    expect(firstMessage(schema().safeParse({
      alternativeCheckInDatetime: PAST,
      alternativeCheckOutDatetime: "",
    }))).toBe(ALTERNATIVE_DATE_MESSAGE_KEYS.altCheckInFuture);
  });
});

describe("latestAlternativeLocalValue", () => {
  it("returns the bound as a datetime-local value", () => {
    const bound = latestAlternativeLocalValue(BOOKED_IN);

    expect(bound).toHaveLength(16);
    expect(bound).not.toContain("Z");
    // 04:00 + 8h, expressed in local time the same way the input is.
    expect(bound).toBe("2099-01-01T12:00");
  });

  it("returns null rather than a fabricated bound when there is no baseline", () => {
    expect(latestAlternativeLocalValue(null)).toBeNull();
    expect(latestAlternativeLocalValue(undefined)).toBeNull();
    expect(latestAlternativeLocalValue("nonsense")).toBeNull();
  });
});
```

Add `createAlternativeDatesSchema` and `latestAlternativeLocalValue` to the import list.
`latestAlternativeTime` is exercised through the schema; import it only if a direct assertion is
added.

**Verify:** `npx vitest run src/lib/validations/reservationDates.test.ts`

### Step 4.3 — The time section builds the schema and bounds the inputs

**Touch:** `src/components/host/ReservationTimeSection.tsx`

**Do:** four edits.

**1.** Change the import to bring in the factory and the input bound, dropping the removed const:

```ts
import {
  createAlternativeDatesSchema,
  fromDatetimeLocalValue,
  latestAlternativeLocalValue,
  toDatetimeLocalValue,
} from "@/lib/validations/reservationDates";
```

**2.** The schema must be stable across renders or react-hook-form re-validates on every one.
Memoise it on the booked times as a **statement of its own, above the `useForm` call** — not
inside `useForm`'s argument object, which is where it is easy to put it by mistake and where it
does not compile:

```ts
  // D13: the schema is per-reservation because the 8h cap is measured from the booked
  // times. Memoised on those two values so the resolver identity is stable — a fresh
  // schema each render is a fresh resolver, and `mode: "onChange"` would re-run the whole
  // form validation on every keystroke of an unrelated field.
  const schema = useMemo(
    () => createAlternativeDatesSchema({ checkInDatetime, checkOutDatetime }),
    [checkInDatetime, checkOutDatetime],
  );
```

Insert it immediately before `const { register, handleSubmit, reset, formState: { errors } } =
useForm<AlternativeDatesValues>({`, and change that call's resolver line to:

```ts
    resolver: zodResolver(schema),
```

Add `useMemo` to the React import.

**3.** Compute the two bounds beside the form:

```ts
  // Prep §8: "the values in the date input should also permit this as well" — `max` stops
  // the picker offering a date the schema would reject.
  const maxAlternativeCheckIn = latestAlternativeLocalValue(checkInDatetime);
  const maxAlternativeCheckOut = latestAlternativeLocalValue(checkOutDatetime);
```

**4.** Add the `max` attribute to each `Input`:

```tsx
              {...register("alternativeCheckInDatetime")}
              max={maxAlternativeCheckIn ?? undefined}
```

```tsx
              {...register("alternativeCheckOutDatetime")}
              max={maxAlternativeCheckOut ?? undefined}
```

`Input` spreads `...props` onto the underlying `<input>`, so `max` passes through — and it must
come *after* the `{...register(...)}` spread so it is not overwritten by a registered prop of the
same name.

`grep -c "zodResolver(schema)" src/components/host/ReservationTimeSection.tsx` → `1`;
`grep -c "alternativeDatesSchema" src/components/host/ReservationTimeSection.tsx` → `0`.
